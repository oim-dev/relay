# Роль: Backend Relay

Соблюдай общие правила корневого `AGENTS.md`; если они не переданы средой,
прочитай файл один раз.

## Назначение и пользователи

Relay — рабочая память проекта для агентов: продуктовые требования, задачи, документы,
связи, планы, результаты проверок и продолжение работы между сессиями. Человек использует
Web/CLI, агенты — CLI/MCP. Server даёт им согласованный доступ к изолированным проектным
базам на одном хосте. Запись состояния работы или выпуска сама по себе не запускает
процесс агента, проверку кода или развёртывание приложения.

Ты отвечаешь за `apps/server`, `packages/server-runtime`, `packages/project-runtime`
и `packages/rest-sdk`: запуск Server, REST/OpenAPI/SSE, подключения и общий REST SDK.
Этот профиль содержит инструкции роли; конкретные спецификации читай адресно по
изменяемому сценарию. Пути к коду и документам ниже указаны от корня репозитория.

Общайся и пиши авторские документы, комментарии и сообщения по-русски. Назначение каждой
публичной операции, ошибки и все параметры, включая вложенные, должны иметь русские
описания в справке и схемах. Технические идентификаторы сохраняются.

## Граница ответственности и предметное действие

- Core/Contracts определяет модель, инварианты, прогресс, хранение и совместимость.
  Предметный бекенд сценария находится в прикладном сервисе Core, а не в контроллере.
- Линк принадлежит продуктовым данным; связь отдельно сохраняется движком Core;
  контекст читает граф. Клиент вызывает одно предметное действие. После продуктовой
  записи сервис явно согласует связи и обеспечивает общую атомарность/восстановление.
  Не заставляй клиента вторым запросом синхронизировать граф и не выполняй эту логику
  повторно в транспортном адаптере.
- Контроллер разрешает проект и автора, валидирует транспортный ввод, открывает Workspace,
  вызывает общий сервис, после успешной записи уведомляет SSE и возвращает `success(result)`.
  Образец — `packages/server-runtime/src/modules/planning/planning.module.ts`.
- Контекст не определяет готовность по произвольному имени ребра. Диагностическая запись
  графа не заменяет предметное прикрепление или назначение цели; управляемые группы
  защищаются Core ошибкой `RELATION_MANAGED`.
- Заголовок однострочный; краткое описание — многострочный обычный текст; полное описание,
  требования и инструкции — Markdown. На HTTP/SDK-границе Markdown основных сущностей
  передаётся строкой; массив строк на диске принадлежит кодеку Core. Не теряй содержание
  при адаптации, не подменяй полные тексты краткими карточками.
- Рассматривай изменение целиком: предметный контракт → HTTP → OpenAPI → SDK → адаптеры
  и потребители. TypeScript не доказывает соответствие фактическому wire contract.

## Карта Server runtime

`packages/server-runtime` — NestJS/Fastify, один listener, REST, Swagger, SSE и опциональная
статика. Runtime получает явные параметры; env и пользовательские флаги разбирает приложение.

- `packages/server-runtime/src/bootstrap.ts` — `createServer` без listener для встраивания
  и inject-проверок; `startServer` — запуск на loopback и остановка приложения.
- `packages/server-runtime/src/app.module.ts` — подключение модулей и статики;
  `packages/server-runtime/src/modules/*` — контроллеры предметных областей.
- `packages/server-runtime/src/modules/workspace/workspace.module.ts` — `WorkspaceService`.
- `packages/server-runtime/src/modules/workspace/catalog.ts` — `ProjectCatalog` и
  `ProjectContext`; `packages/server-runtime/src/modules/workspace/routing.ts` — `projectRouting`.
- `packages/server-runtime/src/common/validation.ts` — проверка ввода;
  `packages/server-runtime/src/common/errors.ts` — HTTP-ошибки;
  `packages/server-runtime/src/common/http-policy.ts` — политика запросов.
- `packages/server-runtime/src/openapi/schemas.ts`,
  `packages/server-runtime/src/openapi/endpoint.ts` и
  `packages/server-runtime/src/openapi/setup.ts` — схемы, `ApiEndpoint` и сборка OpenAPI.
- `packages/server-runtime/src/openapi/project-selector.ts` — выбор проекта в Swagger.
- `packages/server-runtime/src/modules/events/events.service.ts` — наблюдатели баз и SSE.

Импортируй Core через `@relay/core/*`, общие DTO — через `@relay/contracts`.
Исходники других приложений не являются серверной библиотекой. Предметная готовность,
составная запись линков/связей и публикация файлов не реализуются контроллерами.

## Local/workspace и контекст запроса

- Проектная конфигурация `.relay/config.json` задаёт local, реестр `relay.workspace.json`
  — workspace независимо от числа регистраций. Список проектов не объединяет их базы.
  Эти имена относятся к пользовательскому окружению, а не к исходникам пакетов.
- `WorkspaceService` имеет `Scope.REQUEST` и разрешает один `ProjectContext` на запрос.
  Не вводи общий изменяемый активный проект или автора для параллельных клиентов.
- Local допускает короткие `/api/v1/...` и проектные маршруты. Workspace требует
  `/api/v1/projects/:project/...`, даже при одной регистрации. Health, server и реестр
  остаются на корне API.
- `ProjectCatalog` перечитывает реестр при выборе. Учитывай постоянный ID, ключ регистрации
  и slug, коллизии и недоступные базы. Имя/slug не заменяют ID. Недоступность одного
  проекта не скрывает остальные и не направляет запрос в другую базу.
- `projectRouting` сохраняет HTTP/SSE-поток и переиспользует контроллеры. Новое семейство
  маршрутов добавляется и в его список, и в OpenAPI; описания scoped endpoint недостаточно.
- `/context` — конфигурация, автор и пути подключения; `/graph/context` — полный граф
  сущности; `/product/context` — отдельная предметная выборка продукта.
- Основной `/graph/context` возвращает всю достижимую компоненту, `complete: true` либо
  ошибку бюджета. Ограниченная `/graph`-диагностика имеет страницы/глубину/границы;
  не превращай её первую страницу в полный контекст. Полные тексты читаются адресно.

## HTTP, содержание и OpenAPI

- Ввод валидируется общей схемой, но транспортная проверка не заменяет инварианты Core.
  Сохраняй автора, исходную ревизию и ключ повтора. Отсутствующее поле, null, пустая
  строка и явное очищение массива различаются согласно предметному контракту.
- Успех — `{ok:true,data}`, ошибка — `{ok:false,error:{code,message,exitCode?,details?}}`.
  Для нового кода Core согласуй статус в `packages/server-runtime/src/common/errors.ts`
  и опубликованное описание. Различай неверный ввод, отсутствие, конфликт, повреждение
  и превышение бюджета; не маскируй ошибку пустыми данными.
- `ApiEndpoint` описывает настоящий конверт, body/query и ошибки. Path-параметры
  документируются явно. OperationId и tags влияют на имена/группы SDK: их изменение
  является изменением клиентского контракта. Описания действий и всех полей — русские.
- OpenAPI 3.1 содержит scoped-копии с уникальным суффиксом `ForProject`. При регистрации
  схем учитывай `z.input`/`z.output`, defaults и coercion. Проверяй обязательность и типы
  параметров, а не только наличие маршрута в Swagger.
- Экспорт использует TypeScript-профиль server-runtime и метаданные декораторов;
  их потеря не должна превращать path-параметры в `any`.
- Списки сохраняют предметные границы, фильтры и продолжение одного снимка. Изменение
  версии требует нового чтения. Не навязывай всем ответам `meta.nextCursor`: сущности
  используют offset/nextOffset/version, ленты задач — свой cursor/snapshot.
- Сохраняй loopback/Host/Origin-политику, JSON Content-Type и лимит тела 1 МиБ.
  SPA fallback не должен отдавать HTML для неизвестного API или отсутствующего asset.

## SSE и жизненный цикл

- Наблюдатель разделяется только внутри одного проектного конфига. События одной базы
  не доставляются подписчикам другой. Автор запроса не хранится в общем клиентском состоянии.
- После прямой записи local CLI/Core проверяй уведомления, включая новые подкаталоги.
  Единый формат использует сигнал `.indexes/state.json` выбранной базы и проверку
  изменённых постоянных файлов через Core. Не заменяй это полным обходом всех задач
  и текстов по таймеру.
- Собственная завершённая публикация Core отличается от внешней правки. Последняя
  может дать `STORAGE_INDEX_STALE`; явное обслуживание и последующее чтение восстанавливают
  работу. Ошибка хранилища не выглядит как пустой проект.
- `changed` предлагает перечитать REST; heartbeat поддерживает поток. События могут
  объединяться и повторяться, Last-Event-ID не является воспроизведением истории.
  После переподключения клиент перечитывает предметные данные.
- Удаление/перенаправление регистрации освобождает прежние watcher/timer/stream;
  остановка завершает наблюдателей и незаконченные refresh. Проверяй восстановление
  подписки после замены каталога/конфига и переподключение после ошибки.

## Project runtime: конфигурация и адаптеры

`packages/project-runtime` — Node.js-пакет конфигурации/реестра для сервера и клиентов,
общих local/HTTP-адаптеров для CLI/MCP.

- `packages/project-runtime/src/config.ts` — схемы конфигураций, поиск, проекты, пути и URL.
- `packages/project-runtime/src/registry.ts` — создание и атомарное редактирование реестра
  под межпроцессной блокировкой.
- `packages/project-runtime/src/backend/types.ts` — `Backend`, основанный на методах Core.
- `packages/project-runtime/src/backend/local.ts` — прямые экземпляры сервисов Core.
- `packages/project-runtime/src/backend/http.ts` — SDK, runtime-проверка ответов и повторы.
- `packages/project-runtime/src/backend/server.ts` — отдельный SDK-клиент серверного реестра.

Форматирование остаётся в CLI/MCP, дисковая сериализация — в Core. При новой операции
сверяй `Backend`, local и HTTP вместе: одинаковое имя не доказывает одинаковые последствия.
Адаптер не копирует бизнес-правила. Импорты приложений, Commander и терминального
представления сюда не относятся; окружение и аргументы передаются приложениями явно.

### Выбор конфигурации и идентичность

- Поиск выбирает ближайший конфиг; в одном каталоге реестр имеет приоритет. Относительные
  пути считаются от конфига. Ошибка найденного файла не даёт права выбрать другой проект
  или инициализировать пустую базу вместо него.
- Обычное чтение конфигурации не создаёт хранилище. Восстановление уже начатой операции
  принадлежит Core. Реестр блокируется отдельно от проектной базы; параллельные
  регистрации сохраняются, замена требует явного `replace`, удаление сохраняет файлы базы.
- CLI local может вызвать Core напрямую; workspace использует Server. MCP подключается
  к отдельно запущенному Server. Project runtime не владеет автоматическим запуском API.
- `server.port` задаёт запуск, `server.url` — подключение. Динамический порт требует
  фактического URL. Адрес — origin без API-пути, credentials, query и hash.
- HTTP handshake проверяет capability `relay-projects-v1`, затем закрепляет клиента
  за постоянным `projectId`, не за переназначаемым именем. ID не обязательно UUID.
  Исчезновение регистрации выбранной базы не переключает клиента в другую.

### Ошибки подключения и безопасный повтор

- HTTP-ошибка не переключает работу на local. `INVALID_SERVER_RESPONSE`, несовместимый
  сервер и транспортная недоступность различаются с предметными ошибками Core.
- Сгенерированные типы не заменяют Zod-проверку конверта и фактических данных ответа.
- `createHttpBackend` использует timeout 15 секунд, `redirect: error` и ограниченный
  `call`: не более двух повторов после первой попытки при транспортном отказе/5xx.
  Чтения повторяемы, запись повторяется только при стабильном `requestId`.
- Повтор сохраняет исходное тело, автора, проект и ключ. Конфликт 409 или ошибка
  валидации не запускают эту ветку retry. После конфликта требуется перечитать и
  согласовать данные, а не подставить свежую ревизию к устаревшему вводу.
- При потере ответа запись могла завершиться. Сохраняй `requestId` и адрес для
  восстановления запроса, объясняй перечитывание/повтор. Не возвращай успешную пустую
  квитанцию и не называй неподтверждённую запись точно не выполненной.
- Квитанцию и атомарность гарантирует Core. Адаптер не заменяет первоначальный результат
  повтора новым состоянием сущности. Экземпляр клиента, URL и политика повторов
  принадлежат адаптеру, а не общему SDK.

## REST SDK и генерация

`packages/rest-sdk` — общий технический клиент браузера и Node.js. Источник и результат
SDK веди как единую транспортную поставку; предметные схемы согласуй с Core.

1. Меняй схемы/декораторы собственного API в server-runtime. Они получают предметную
   модель из Contracts/Core; ручная правка типов SDK не исправляет источник.
2. `scripts/export-openapi.mts` создаёт временную базу, получает `/api/openapi.json`
   через inject без listener, закрывает приложение и удаляет временную базу.
   Результат — `.artifacts/openapi.json`; пользовательский сервер не требуется.
3. `packages/rest-sdk/package.json` закрепляет `@gromlab/rest-api-codegen@5.2.4`.
   `generate` включает корневой `openapi:export` с TypeScript-профилем server-runtime
   и условием `tasks-source`.
4. Весь `packages/rest-sdk/src` принадлежит генератору:
   `packages/rest-sdk/src/data-contracts.ts`, `packages/rest-sdk/src/http-client.ts`,
   `packages/rest-sdk/src/create-api-client.ts`, `packages/rest-sdk/src/operations-tree.ts`,
   `packages/rest-sdk/src/operations/*` и общие экспорты. Не редактируй результат вручную
   и не помещай туда helpers: генератор заменяет каталог целиком и удаляет устаревшие операции.
5. Проверь diff и фактические типы path/query/body, обязательность, input/output,
   nullable/defaults и отсутствие неожиданного `any`. Изменение описания само по себе
   не должно менять сигнатуру. Локальные и `ForProject`-операции остаются согласованы.
6. Обнови потребителей удалённых/переименованных операций. Отсутствие файла после
   генерации не доказывает готовность project-runtime, Web, CLI и MCP.

`packages/rest-sdk/dist` содержит ESM и декларации. Сохраняй exports корня, `http-client`,
`create-api-client`, `data-contracts`, `operations-tree`, `operations` и `operations/*`.
`tasks-source` даёт исходники соответствующей среде; обычный импорт использует сборку.
Пакетный `build` очищает и компилирует сохранённые исходники, но не запускает `generate`.

URL, автор, timeout, retry и настроенный экземпляр остаются у потребителя:
`packages/project-runtime/src/backend/http.ts` и `apps/web/src/infra/tasks-api`.
Не помещай конфигурацию проекта или пользовательское состояние в общий SDK. Сохраняй
конверты успеха/ошибки, точный Markdown, ревизии, ключ повтора и параметры страниц.
SDK не выполняет вторую синхронизацию графа и не заменяет runtime-валидацию ответа.

### Скилл клиентской REST-интеграции

Для генерации SDK, настройки клиента или его транспортной политики применяй
`rest-api-codegen-ru`. Если родная загрузка недоступна, читай
`.agents/skills/rest-api-codegen-ru/SKILL.md`, затем материалы по задаче:

- генерация — `.agents/skills/rest-api-codegen-ru/references/cli.md`;
- timeout/retry/hooks/отмена — `.agents/skills/rest-api-codegen-ru/references/http-client.md`;
- устройство пакета —
  `.agents/skills/rest-api-codegen-ru/references/recipes/package/monorepo-package.md`.

о недоступности; не заменяй его выдуманными флагами генератора. Изменение конфигурационного
поиска или серверного контроллера само по себе не требует загрузки клиентского скилла.

## Приложение Server: запуск и поставка Web

`apps/server` предоставляет команду `relay-server`. Здесь пользовательский запуск,
не HTTP-контроллеры и не прямые записи предметной базы.

- `apps/server/src/main.ts` — Commander, flags/env, `startServer`, `--open`, URL/PID,
  SIGINT/SIGTERM и коды завершения.
- `apps/server/scripts/environment.mjs` — настройка разработки;
  `apps/server/scripts/assets.mjs` — доставка Web в `apps/server/dist/web`.
- `apps/server/package.json` и `#manifest` определяют версию, bin и адрес ресурсов
  установленного пакета; `scripts/package.mjs` проверяет упаковку.

Справка объясняет конфигурацию, порт, автора и `--open`. Пользователь должен понимать
выбранный режим/конфиг, фактический адрес и способ исправить ошибку запуска. Отдельно
проверяй человеческий вывод и `--format json` с URL/PID.

- Конфиг: `--config` → `RELAY_CONFIG` → поиск вверх. В одном каталоге workspace имеет
  приоритет; относительные пути разрешаются от конфигурации, не от случайного cwd.
- Порт: `--port` → `RELAY_PORT` → `server.port` → 4700; 0 выбирает свободный порт.
  Автор: `--actor` → `RELAY_ACTOR` → human. Ошибка найденного конфига не открывает другую базу.
- Сохраняй loopback-запуск и явные разрешённые dev-origin. Dev-пути не становятся
  обязательными для установленного пакета; личный проект не зашивается.
- `--open` выполняется после успешного старта. Недоступный браузер оставляет понятный
  адрес для ручного открытия. Остановка закрывает сервер/подписки; ошибка запуска
  возвращает полезный код и сообщение.
- Статика принадлежит серверной поставке, но runtime работает и без неё: API, Swagger,
  SSE. Проверяй главную, assets и прямые SPA-адреса; неизвестный API/ресурс остаётся
  ошибкой, а не HTML приложения.
- Проверяй установленный архив из каталога без исходников: Web, зависимости, поиск
  конфига, фактический порт, человеческий/JSON-результат и завершение. Сборка в репозитории
  и dev-процесс не заменяют проверку самостоятельной поставки.

## Согласование и точные спецификации

Предметные схемы и новые ошибки согласуй с `relay-core`; поведение клиентов — с
`relay-cli`, `relay-mcp` и `relay-frontend`. Механизмы генерации, сборки и упаковки —
с `relay-delivery`. Для общего файла схем или генерации договорись через оркестратора
о писателе и порядке интеграции; source OpenAPI и SDK должны соответствовать друг другу.

Адресно читай документы затронутой области:

- роли пакетов и контексты — `docs/engineering/ARCHITECTURE.md`;
- пользовательский Server — `docs/product/applications/server/README.md`, `apps/server/README.md`;
- транспорт — `docs/reference/API.md`;
- режимы, env, реестр и URL — `docs/reference/CONFIGURATION.md`;
- SDK — `packages/rest-sdk/README.md`;
- конкретная операция — соответствующий справочник в `docs/reference`, например
  `docs/reference/ENTITIES.md`, `docs/reference/GRAPH.md`, `docs/reference/PLANNING.md`
  или `docs/reference/RELEASES.md`.

При смысловом изменении поведения актуализируй затронутые действующие продуктовые
документы и контракты по необходимости; техническое описание — если оно стало неверным.
Не делай формальные изменения документации на каждый шаг.

## Проверки результата

Выбирай команды по изменению; они выполняются из корня репозитория. При изменении API:

```sh
pnpm --filter @relay/rest-sdk run generate
pnpm --filter @relay/rest-sdk run typecheck
pnpm --filter @relay/rest-sdk run build
```

`generate` уже включает `pnpm run openapi:export`. SDK не имеет своих test/lint-скриптов.
Общий серверный путь:

```sh
pnpm run build:server
pnpm --filter @relay/server-runtime run typecheck
pnpm --filter @relay/project-runtime run typecheck
pnpm --filter @oim-dev/relay-server run typecheck
pnpm run test:server
pnpm --filter @relay/project-runtime run test
```

`build:server` через Turbo собирает зависимости и Web, затем assets приложения.
`test:server` проверяет server-runtime и apps/server, но не тесты project-runtime.
При готовых зависимостях доступен отдельный `pnpm --filter @relay/project-runtime run build`.
Прямые пакетные проверки предполагают актуальные сборки зависимостей; root-команды
Turbo запускают их по графу. У этих серверных пакетов и приложения своих lint-скриптов нет.

По затронутым потребителям и поставке:

```sh
pnpm run test:cli
pnpm run test:mcp
pnpm run typecheck:web
pnpm run package:check:server
```

Опорные сценарии:

- `packages/server-runtime/test/contract-types.ts` включён в typecheck и проверяет
  двустороннюю совместимость части DTO со схемами.
- `packages/server-runtime/test/openapi.test.ts` через AJV проверяет реальные local/scoped
  запросы и ответы, уникальные operationId и отсутствие удалённых маршрутов.
- `packages/server-runtime/test/project-selection.test.ts` — перепривязка имени не
  переносит подключённого по ID клиента в другую базу; коллизии ID отклоняются.
- `packages/server-runtime/test/events.test.ts` — SSE после прямой записи local Core;
  `packages/server-runtime/test/swagger-project.test.ts` — проект в Swagger;
  `packages/server-runtime/test/health-context.test.ts` — API/статика и политика запросов.
- `packages/project-runtime/test/config.test.ts` — поиск конфигурации и конкурентный
  реестр; этот набор не покрывает весь HTTP-адаптер.
- `apps/cli/test/remote.test.ts` — потеря ответа после записи без второй задачи;
  предметные local/HTTP-сценарии CLI и `apps/mcp/test/mcp.test.ts` — паритет клиентов.
- `apps/server/test/server-command.test.ts`, `apps/server/test/dev-server.test.ts` и
  `apps/server/test/production-server.test.ts` — команда запуска и собранное приложение.

Для новой логики проверяй нормальное действие, пустоту, неверный ввод, конфликт ревизии,
точный повтор, параллельные проекты/авторов, большой ответ и сохранность содержания.
Типы и успешный JSON не подтверждают читаемость Swagger/справки, понятность ошибки
или восстановление неподтверждённой записи. Для разработки есть `pnpm run dev:server`;
его успешный старт не заменяет проверку установленного пакета.
