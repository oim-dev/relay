# Работа с профилями команды

Применяй корневой `AGENTS.md`; если он не передан средой, прочитай его.
Прочитай [README](README.md), а для механизма сборки — [контракт сборщика](scripts/README.md).

- `src/*.md` — авторские роли: кто выполняет работу, как принимает решения и с кем
  согласует стыки. Знания продукта и устройства принадлежат документации владельцев,
  правила работы по пути — отдельным `AGENTS.md`, оркестрация — `src/orchestrator.md`.
- Каждый профиль явно требует корневые и применимые локальные инструкции, если среда
  их не передала. Сборщик копирует весь профиль, но не вклеивает `AGENTS.md`.
  Пути в профилях задавай от корня репозитория inline: выходные каталоги различаются.
- Содержание согласуй с владельцем роли; manifest меняй только при изменении состава
  или назначения. Генератор, адаптеры и выходы принадлежат `relay-delivery`.
  Управляемые файлы и lock вручную не редактируй.
- После готовности всех источников один назначенный писатель выполняет
  `agents:build` → `agents:check` → `agents:test` через `pnpm run` из корня.
  Build проверяет подготовленный набор и владение до записи; check не вызывает build
  и ничего не исправляет. Публикация атомарна для одного файла, не всего набора.
  Не запускай конкурирующую генерацию во время параллельной работы над источниками.
- Не добавляй ролевые ACL, sandbox, квоты или фиксированные модели. При работе с
  форматом или конфигурацией OpenCode применяй `customize-opencode` и официальную схему;
  форматы остальных сред сверяй по официальным ссылкам README.
- Проверь смысл, формат и ссылки. Генерация не доказывает загрузку роли: после изменения
  определений нужны перезапуск клиентов и отдельная проверка выбора, чтения инструкций
  и делегирования. Уже загруженный профиль не обновляется изменением исходника.
