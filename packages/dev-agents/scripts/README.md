# Сборщик проектных агентов

Из единого `packages/dev-agents/src/manifest.json` и полных профильных Markdown-файлов
сборщик получает настройки OpenCode, Claude Code и Codex. Продуктовые данные Relay,
линки и связи Core здесь не участвуют.

## Запуск

Прямые команды private ESM workspace-пакета из корня репозитория:

```bash
pnpm --filter @relay/dev-agents run build
pnpm --filter @relay/dev-agents run check
pnpm --filter @relay/dev-agents run test
```

Корневые алиасы — `pnpm run agents:build`, `pnpm run agents:check`, `pnpm run agents:test`.
Из `packages/dev-agents` используйте `pnpm run build`, `pnpm run check`, `pnpm run test`.
Прямой Node-запуск из корня: `node packages/dev-agents/scripts/check.mjs --format json`.

`--root <каталог>` выбирает другой корень. `--format json` включает машинный ответ;
по умолчанию команды выводят русский итог. `check` только читает файлы: код 0 означает
актуальную сборку, код 1 — расхождения или ошибку входа. JSON содержит `ok`, `mode`,
`agents`, `outputs`; при расхождениях — `issues`, при ошибке входа — `error`.
Ожидаемый набор вычисляется в памяти; `check` не вызывает `build`, не создаёт staging
и не изменяет выходы или lock.

Из `lib.mjs` доступны `prepareBundle(root)` (результаты в памяти),
`buildBundle({ root })` и `checkBundle({ root })`. `adapters.mjs` отвечает за форматы сред.

## Вход и владение

Manifest версии 1 содержит `orchestrator` и массив `agents`. У каждого агента обязательны
`name`, `kind` (`orchestrator` либо `worker`), `description`, `prompt`.
Нужен ровно один оркестратор с именем из `orchestrator`.
Имена уникальны, до 64 символов, состоят из строчных латинских букв, цифр и дефисов,
начинаются с буквы. `prompt` — относительный путь к `.md` внутри `packages/dev-agents/src`.
Неизвестные поля, пустые тексты, выход за корень и символьные ссылки отклоняются.

Тело каждого агента — весь его самодостаточный профиль, нормализованный Prettier с LF.
Это относится и к полной роли главного в `packages/dev-agents/src/orchestrator.md`.
`common.md` и корневые/локальные `AGENTS.md` не читаются и не вклеиваются сборщиком.
Корневой `AGENTS.md` содержит общие правила для всех: их загружает среда либо агент
читает файл один раз, если правила не переданы. `AGENTS.md` не бывает управляемым выходом.
Порядок элементов manifest не влияет на байты результата. Модель не фиксируется.
Для девяти профилей создаётся 29 выходных файлов и `agents-lock.json`.

Для совместимости с прежним входным контрактом принимается необязательный булевый
`readOnly`, но он не создаёт ограничений и не меняет полный prompt.

Lock версии 1 хранит `generator: "@relay/dev-agents"` и отсортированный массив
`outputs: [{ path, sha256 }]`, без времени сборки. Управляемый файл принадлежит сборщику
целиком; слияния произвольных пользовательских полей конфигурации нет.

Прежний `generator: "scripts/agent-bundle"` читается для безопасного перехода:
check сообщает drift, build проверяет прежние хеши до миграции и обновляет ID последним.
Неизвестный владелец и ручные правки прежних результатов останавливают миграцию.
При JSON-вызове root alias используйте `pnpm --silent run agents:check --format json`.
Относительный `--root` считается от каталога вызова пользователя: через pnpm учитывается
`INIT_CWD`, включая filter и пакетные команды; при прямом Node-запуске используется cwd.

- Первый запуск требует свободных выходных путей. Даже совпадающий файл без записи
  в lock считается чужим; автоматического присвоения нет.
- Перед первой записью проверяются все входы и коллизии. Файлы вне списка владения
  сохраняются, включая дополнительных агентов и локальные настройки.
- Изменённый вручную управляемый файл защищён от перезаписи и удаления. Перенесите
  нужные правки в исходники, затем восстановите прежний результат по Git или перенесите
  его с выходного пути. Следующая сборка восстановит результат.
- Переименование или удаление профиля удаляет только прежние неизменённые выходы из lock.
  Пустые каталоги не удаляются. Lock обновляется последним.
- `CLAUDE.md` не генерируется. Старую сгенерированную обёртку можно удалить только
  по совпадающей записи прежнего lock; чужой `CLAUDE.md` сохраняется.
- Публикация атомарна для одного файла, не для всего набора. Параллельные сборки
  не поддерживаются. После прерывания `check` показывает расхождения; новые файлы,
  не успевшие попасть в lock, требуют проверки происхождения и переноса перед повтором.

## Адаптеры и границы

- **OpenCode:** девять `.opencode/agents/*.md` с `description` и `mode`
  (`primary`/`subagent`); `opencode.json` со схемой и `default_agent`.
- **Claude Code:** девять `.claude/agents/*.md` с `name`, `description`, `model: inherit`;
  `.claude/settings.json` выбирает главного через `agent`.
- **Codex:** `.codex/config.toml` содержит полный профиль primary в `developer_instructions`
  и `[agents] enabled = true`;
  восемь самостоятельных `.codex/agents/*.toml` содержат `name`, `description`
  и `developer_instructions`.

Permissions, списки инструментов, sandbox, квоты и ограничения вложенного делегирования
не генерируются. Действующие возможности, системные ограничения и runtime overrides
определяются средой. Проектная конфигурация Codex применяется после доверия проекту;
проверка файла не подтверждает это доверие. Автоматическая загрузка инструкций самой
средой отдельно от явного чтения профиля не управляется сборщиком.

Claude 2.1.220 поддерживает `inherit`, но `CLAUDE_CODE_SUBAGENT_MODEL` в этой версии
может переопределять выбор модели. Сборщик не изменяет окружение или глобальные настройки.
После финальной сборки перезапустите OpenCode; новую первую директорию агентов Claude
также загружайте в новой сессии.

Источники форматов:

- [Схема OpenCode](https://opencode.ai/config.json).
- [Агенты Claude](https://code.claude.com/docs/en/sub-agents) и
  [настройки](https://code.claude.com/docs/en/settings).
- [Самостоятельные агенты Codex](https://developers.openai.com/codex/agent-configuration/subagents.md).

## Проверки совместимости

Unit-тесты не требуют CLI или сети. Fixtures создаются в системном `tmp/opencode`;
если он недоступен для записи, используется локальный `packages/dev-agents/scripts/.tmp-tests`.
Оба варианта автоматически очищаются. Реальные исходники ролей не используются;
fixtures не требуют `common.md`, корневого или локального `AGENTS.md`.

Дополнительные проверки установленных CLI включаются явно:

```bash
RELAY_AGENT_BUNDLE_CLI_CHECK=1 pnpm --filter @relay/dev-agents run test
```

Они создают изолированные домашние каталоги и временный Git-репозиторий, загружают
OpenCode через `debug agent`, Claude через SDK `initialize`, Codex через
`app-server --strict-config` и `debug prompt-input`. Запросов к модели нет.
Для Codex специально проверяется предупреждение о повреждённом файле агента:
успешного кода завершения недостаточно, чтобы доказать сканирование каталога.

Проверка рассчитана на OpenCode 1.18.32, Claude 2.1.220 и Codex 0.146.0;
фактические версии печатаются в диагностике. Реальное выполнение поручений моделью,
наличие каждого инструмента в конкретной сессии и пользовательские overrides
этими проверками не подтверждаются.
