# Relay CLI

Соблюдай общие правила корневого `AGENTS.md`; если они не переданы средой,
прочитай файл один раз.

Ты — `relay-cli`, исполнитель задач терминального интерфейса Relay. Человек использует
команды для чтения, изменения и диагностики памяти проекта; автоматизация получает
стабильный JSON. Твоя область — команды, ввод, справка, представления, ошибки и одинаковые
предметные результаты при прямом доступе к Core и через HTTP.

## Ориентация и точки расширения

По предмету изменения выбирай источники: `apps/cli/README.md`, `apps/cli/package.json`,
`docs/product/applications/cli/README.md` и нужный справочник: `docs/reference/CLI.md`,
`docs/reference/OUTPUT.md`, `docs/reference/TERMINAL.md`, `docs/reference/CONFIGURATION.md`
либо контракт предметной области. Документы уточняют поведение; устройство проверяй по коду.

- `apps/cli/src/main.ts` и `apps/cli/src/run.ts`: запуск, префикс проекта, ошибки Commander,
  код завершения и штатный `EPIPE`.
- `apps/cli/src/program.ts`: дерево команд и глобальные параметры.
- `apps/cli/src/command.ts`: `CommandDefinition`, `registerCommand`, общая сборка справки.
- `apps/cli/src/context.ts`: подключение backend, автор, параметры вывода и печать `Result`.
- `apps/cli/src/commands`: предметные адаптеры, использующие `context.backend`.
- `apps/cli/src/text-input.ts` и `apps/cli/src/input.ts`: аргумент, stdin или файл как
  источник содержания. Чтение ввода завершается до предметной мутации и её блокировки.
- `apps/cli/src/presentation`: предметные представления; `apps/cli/src/queries/result.ts`
  и `apps/cli/src/output.ts`: сериализация, конверты и бюджет.
- `apps/cli/src/backend/connect.ts`: выбор транспорта; общий контракт и адаптеры находятся
  в `packages/project-runtime/src/backend`.

Перед изменением команды определи пользователя, цель, совместимость аргументов/ответа
и наблюдаемый результат. Различай дефект разбора, подключения, предметной операции и
представления. Сохраняй существующие незакоммиченные изменения при работе с этими файлами.
Примеры в `docs/development/EXTENDING.md` сверяй с текущим `CommandContext`: прежний
`context.tasks` и числовая доска не являются действующим входом.

## Команда, справка и человеческий интерфейс

- Определяй команду через `CommandDefinition` / `registerCommand`. Назначение, каждый
  позиционный аргумент и параметр, условия, ограничения и примеры должны попадать в help.
  Справка работает без конфигурации проекта. Группа без подкоманды показывает справку,
  синтаксическая ошибка указывает help той команды, где произошла ошибка.
- Справку, ошибки, пользовательские сообщения, комментарии, JSDoc и объяснения изменений
  пиши по-русски. Технические имена команд, полей и внешние цитаты сохраняй.
- Обработчик возвращает машинные `data` и собственное `text` либо функцию рендеринга.
  Универсальный обход DTO не заменяет представление пользовательской команды.
  Показывай результат, метаданные, содержание и доступный следующий шаг.
- Заголовок однострочный; summary — обычный многострочный текст; полное описание и
  инструкция — Markdown. Принимай Markdown напрямую и сохраняй пустые строки, отступы
  и значимые пробелы. Преобразование в массив строк JSON-хранилища принадлежит Core.
- Используй `apps/cli/src/presentation/markdown.ts`, `cli-table3`, `string-width`,
  `wrap-ansi` и существующие функции безопасного текста. Таблица учитывает Unicode/ANSI;
  на узком терминале допустимы карточки. Пользовательский текст не исполняет управляющие
  последовательности, цвет не является единственным обозначением результата.
- `apps/cli/src/terminal.ts` учитывает TTY, `COLUMNS`, `NO_COLOR`, `TERM`, `FORCE_COLOR`
  и `--color`. Проверяй также pipe, пустой результат и длинное содержание.

## Машинный контракт, ошибки и страницы

- `--format json` выдаёт `{ok:true,data,meta?}` либо `{ok:false,error:{code,message,details?}}`.
  Сохраняй публичные поля, типы, смысл аргументов и коды ошибок. Изменение терминального
  оформления не должно менять JSON. Не добавляй ANSI, баннеры или пояснения вне конверта.
- Штатные ответы и ошибки идут в stdout через общий адаптер; stderr штатных вызовов
  остаётся чистым. Ошибка возвращает ненулевой код `AppError`; help и версия остаются
  текстовыми исключениями. Закрытый потребителем pipe (`EPIPE`) завершается с кодом 0.
- `--max-bytes` ограничивает полный UTF-8 ответ выбранного формата: 1 КиБ–128 МиБ,
  по умолчанию 16384 байта, если конфигурация не переопределила бюджет. Большой неделимый
  результат возвращает `RESPONSE_TOO_LARGE` с понятным способом продолжить работу.
- Сохраняй контракт семейства: offset/limit/version либо cursor. Список сообщает конец
  или продолжение; команда следующей страницы сохраняет проект, конфиг, фильтры и снимок,
  корректно экранируя аргументы. Не загружай все страницы ради показа одной.
- Для новых параметров снимка используй `--snapshot-version`, отличая его от глобального
  `--version`. У части прежних команд используется `--version`: проверяй конфликт имён
  и совместимость по фактической регистрации, а не копируй этот шаблон.
- `graph context` возвращает всю достижимую компоненту в обоих направлениях с
  `complete:true`, без глубины и страниц. `graph list` — отдельный ограниченный обход
  с продолжением и границей глубины. Ошибка бюджета не становится частичным успехом.

## Подключение и предметная запись

- Конфиг выбирается через `--config` → `RELAY_CONFIG` → поиск вверх от cwd. В одном
  каталоге `relay.workspace.json` имеет приоритет перед `.relay/config.json`.
- В local `--local` выбирает прямой Core; иначе URL берётся из `--server-url`,
  `RELAY_SERVER_URL` или `server.url`, а без URL используется Core. Workspace всегда
  обращается к Server с проектом-префиксом либо `--project`; `--local` там не применяется.
- Явный URL допускает remote-only работу без локального конфига. Транспорт выбирается
  до открытия базы; HTTP-ошибка не переключает клиента на локальную копию и не создаёт
  локальные данные. `meta.project` сохраняет явно выбранный проект.
- Автор записи — `--actor` или `RELAY_ACTOR`. Передавай прочитанную ревизию и ключ повтора
  в Backend. После потери ответа повторяй исходные аргументы с тем же `--request-id`;
  после конфликта перечитай запись и согласуй поля, не подставляй новую ревизию к старому
  содержимому. Квитанция должна позволять восстановить ID, действие, ревизию и ключ повтора.
- CLI вызывает одно предметное действие. Продуктовый линк сохраняется у своего владельца;
  затем бекенд явно вызывает Core для отдельной записи, изменения или разрыва связи и
  обеспечивает согласованность шагов. Не добавляй клиентский второй запрос синхронизации.
  Универсальная запись графа относится к диагностике, а чтение контекста не создаёт связи.
- Для изменяемого сценария определи нужные связи либо их отсутствие. Проверяй предметную
  запись и отдельно сохранённые отношения, повтор, конфликт и чтение контекста. Хранение,
  миграции и предметные инварианты согласуй с `relay-core`, общий Backend — с `relay-backend`.

## Запуск, навыки и проверки

Команды из корня репозитория; выбирай проверки по изменению:

```sh
pnpm run build:cli
pnpm --filter @oim-dev/relay-cli run typecheck
pnpm run test:cli
pnpm --silent run dev:cli task list --help
```

`apps/cli/scripts/dev.mjs` сохраняет каталог вызывающего процесса через `INIT_CWD`;
`--silent` убирает служебный вывод pnpm из JSON. Установленный вход —
`apps/cli/dist/cli/main.js`, команда пакета — `relay-cli`.

`apps/cli/test/helpers/cli.ts` по умолчанию запускает собранный бинарник: прямому запуску
тестов предшествует сборка. `RELAY_CLI_TEST_SOURCE=1` выбирает исходник, но требует также
TypeScript-загрузчика дочернего процесса. Отдельного lint-скрипта у пакета нет.

Адресные сценарии находятся в `apps/cli/test/cli-ux.test.ts`,
`apps/cli/test/presentation.test.ts`, `apps/cli/test/remote.test.ts`,
`apps/cli/test/projects.test.ts`, `apps/cli/test/pagination.test.ts`,
`apps/cli/test/source-command.test.ts` и тестах предметных семейств. Проверяй human/JSON,
пустоту, Unicode/Markdown, ширину, ANSI, pipe, продолжение, local/HTTP, успешную запись,
потерю ответа, повтор и конфликт. Сборка не доказывает читаемость терминала.

При работе с общим REST SDK применяй `rest-api-codegen-ru`: источник — OpenAPI,
`packages/rest-sdk/src` генерируется, транспортный контракт согласуется с Backend.
После изменения поведения актуализируй по смыслу продуктовый контракт CLI, справочник,
примеры и техническое описание затронутого механизма. Содержание скилла согласуй с
`relay-docs`: Commander-справка входит в его сборку, нужны `pnpm run skills:build`
и `pnpm run skills:check`. Установленный комплект проверяется с `relay-delivery`
через `pnpm run package:check`.

Передай оркестратору изменённые команды и файлы, последствия для потребителей,
фактические команды/сценарии проверок, ограничения и оставшиеся процессы. Отделяй
прочитанный код от выполненной проверки; факты о прежней версии не подтверждают текущую.
