# Единые исходники агентов Relay

Приватный ESM workspace-пакет `@relay/dev-agents` хранит реестр, полные профили главного
и воркеров и сборщик определений для OpenCode, Claude Code и Codex.
[orchestrator.md](src/orchestrator.md) — самодостаточная роль главной сессии,
[корневой AGENTS.md](../../AGENTS.md) — общие правила для всех агентов.
[Руководство команды](../../docs/development/AGENT-TEAM.md) поясняет выбор владельцев и передачу работы.

## Источники и загрузка

- [manifest.json](src/manifest.json) содержит `version`, имя `orchestrator` и список `agents`.
  У роли заданы `name`, `kind`, `description`, `prompt`; путь `prompt` считается от `src` пакета.
  Состав — один `kind: orchestrator` и восемь `kind: worker`.
- [AGENTS.md в корне](../../AGENTS.md) содержит общие правила, не назначает роль и не является
  управляемым выходом. Правила загружает среда; если они не переданы, агент читает файл один раз.
- [orchestrator.md](src/orchestrator.md) содержит полную роль и порядок работы главной сессии.
  Его тело целиком передаётся во все три среды, как и тела остальных профилей.
- Остальные указанные в манифесте `*.md` содержат знания соответствующего приложения,
  пакета или предметной области: архитектуру, контракты, способы работы и проверки.
  Воркер получает свой профиль целиком и конкретное поручение, без обязательного чтения
  других профилей, локальных `AGENTS.md` или общего пакета протоколов.
- `README.md` — инструкция сопровождения источников, не промпт агента. Сборщик
  `packages/dev-agents/scripts` не читает и не вклеивает корневые/локальные `AGENTS.md`
  или `common.md`; общие правила доступны отдельно от генерируемой роли.

Пути внутри промптов указываются от корня репозитория: один текст используется в нескольких
выходных каталогах. Спецификации и материалы читаются адресно по предмету поручения.
Локальные инструкции владельцев переносятся в их профили и удаляются. Журналы агентов
и протокол постоянной записи не используются. Исполнитель передаёт результат оркестратору
в ответе; долговременная документация меняется по смыслу, не после каждого действия.

## Выходы трёх сред

- **OpenCode:** `opencode.json` и `.opencode/agents/*.md`. Главный — `relay-orchestrator`,
  воркеры — субагенты; тела определений берутся из соответствующих профилей.
- **Claude Code:** `.claude/settings.json` и `.claude/agents/*.md`. Настройки выбирают
  оркестратора, определения содержат YAML-метаданные и исходный промпт роли.
- **Codex:** `.codex/config.toml` содержит полную роль оркестратора в `developer_instructions`;
  `.codex/agents/*.toml` определяют самодостаточных воркеров.

Корневой `agents-lock.json` версии 1 учитывает управляемые выходы с
`generator: "@relay/dev-agents"` без timestamp. Переход с прежнего `scripts/agent-bundle`
описан в [контракте владения](scripts/README.md#вход-и-владение): `check` сообщает расхождение,
а `build` проверяет прежние SHA-256 перед обновлением lock. Посторонние файлы не присваиваются.
Повторная сборка одинаковых источников должна давать одинаковый результат.
Роли наследуют действующие возможности среды; проект не добавляет ролевые permissions,
tool allowlists, sandbox или квоты. Модели не фиксируются; для Claude Code допустимо
`model: inherit`. Область поручения служит координации, а не настройке ограничений инструментов.

## Сопровождение и сборка

Содержание профиля согласуется с предметным владельцем. `relay-docs` сопровождает
документацию команды, `relay-delivery` — сборщик, адаптеры и генерируемые выходы.

1. Меняйте инструкцию роли в её профиле, включая [orchestrator.md](src/orchestrator.md).
   При изменении назначения согласуйте `description` в манифесте и
   [таблицу команды](src/orchestrator.md#ответственность-и-команда).
   Корневой `AGENTS.md` меняется только для общих правил, не для жизненного цикла воркеров.
2. Изменение форматов или алгоритма сборки передайте `relay-delivery` с критериями всех
   трёх сред. Назначьте одного писателя выходов и `agents-lock.json` после готовности источников.
3. Этот исполнитель запускает из корня:

   ```sh
   pnpm run agents:build
   pnpm run agents:check
   pnpm run agents:test
   ```

   Прямые команды из корня:

   ```sh
   pnpm --filter @relay/dev-agents run build
   pnpm --filter @relay/dev-agents run check
   pnpm --filter @relay/dev-agents run test
   ```

   Корневые алиасы вызывают эти пакетные задачи. Из `packages/dev-agents` доступны
   `pnpm run build`, `pnpm run check`, `pnpm run test`.
   [Технический контракт](scripts/README.md) описывает `--root`, JSON и миграцию lock.
   `check` вычисляет ожидаемый набор в памяти и только читает выходы: без предварительного
   `build`, staging и молчаливого исправления расхождений.

4. Проверьте diff, смысл профилей и навигацию. Для документов используйте
   `pnpm exec prettier --check <изменённые пути>`, `git diff --check` и `pnpm run docs:check`.
   При параллельном переносе общая проверка ссылок выполняется после готовности связанных файлов.
5. Завершите текущие сессии затронутых сред и запустите их заново из проекта.
   OpenCode читает конфигурацию при запуске. Проверьте в каждой заявленной среде выбор
   главного, загрузку полных профилей главного и воркеров, доступность общих правил
   (от среды или однократного чтения) и реальное делегирование.
   В ответе передайте версию среды и наблюдаемые результаты отдельно от статических проверок.

Успешная сборка не означает пройденную runtime-приёмку. Временное использование универсального
субагента с полным текстом нужного профиля описано в
[инструкции команды](../../docs/development/AGENT-TEAM.md#сборка-и-загрузка-ролей).

Пакет работает из исходников без сборки приложений и не входит в runtime-поставку CLI/Server/MCP.
Его Turbo-задачи `build`, `check`, `test` имеют `dependsOn: []` и `cache: false`;
`lint`/`typecheck` также не запускают `build`. Корневой `check` включает `agents:check`
и `skills:check`, а тесты обоих tooling-пакетов выполняет один раз через Turbo.
CI проверяет отслеживаемые выходы до сборки, чтобы генерация не скрывала расхождения.

## Доступность скиллов

Скиллы выбираются по задаче и профилю владельца. `react-reference` и `unit-architecture`
перечислены в [skills-lock.json](../../skills-lock.json). `.agents/skills` исключён из Git;
после чистого клонирования выполните `pnpm run skills:install`. Дополнительные локальные
скиллы не гарантируются lock-файлом.

Если инструмент загрузки скилла недоступен, прочитайте доступный
`.agents/skills/<имя>/SKILL.md` и нужные материалы. Отсутствие обязательного для конкретной
задачи скилла обозначьте явно. Открытое ограничение: локальный `template-generation`
отсутствует в `skills-lock.json` — 4 записи в lock при 5 установленных скиллах.

## Официальные форматы

При изменении адаптера сверяйте поля с документацией используемой версии:

- OpenCode: [агенты](https://opencode.ai/docs/agents/) и
  [JSON Schema](https://opencode.ai/config.json); применимый скилл — `customize-opencode`.
- Claude Code: [определения агентов](https://code.claude.com/docs/en/sub-agents).
- Codex: [субагенты и TOML-конфигурация](https://developers.openai.com/codex/multi-agent).

Примеры ограничений и выбора моделей во внешней документации не входят в контракт
команды Relay. Её адаптеры сохраняют исходные промпты и наследование возможностей среды.
