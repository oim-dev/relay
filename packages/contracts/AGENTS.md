# Работа в Contracts

Инструкция действует для любого исполнителя и QA в `packages/contracts`.
Общие правила — [корневой AGENTS.md](../../AGENTS.md). Пакет владеет переносимыми
схемами и типами; изменения Core, HTTP и потребителей согласуйте с оркестратором.

## Маршрут чтения

- Начните с [README](README.md) и [API](docs/API.md) до изменения схемы.
- Если продукт и границы неизвестны, прочитайте [PRODUCT](../../docs/PRODUCT.md)
  и [ARCHITECTURE](../../docs/ARCHITECTURE.md); затем только нужную
  [возможность](../../docs/CAPABILITIES.md) и [предметный контракт](../../docs/domain/README.md).
  Весь общий комплект читать не требуется.
- Для транспортного изменения сверьтесь с [REST API](../server-runtime/docs/API.md),
  для оболочек и повторов — с [STORAGE](../../docs/domain/STORAGE.md).
  Актуальные версии и гарантии не копируйте из прежних профилей.

## Правила схем

- Сохраняйте переносимость: без Core, Node.js, NestJS и React; схема формы данных
  не заменяет предметную проверку сервиса Core.
- Различайте `z.input` и `z.output`, defaults/coercion, optional/null и явную очистку.
  Не переносите defaults создания в patch без контракта владельца.
- Описывайте по-русски назначение и все публичные поля, включая вложенные объекты,
  варианты и элементы массивов; проверяйте понятность в OpenAPI/MCP, а не только коде.
- Внешний Markdown остаётся строкой; дисковое представление не является API DTO.
  Не обещайте дедупликацию по `requestId` или автоматический повтор мутации.
- Не заводите вторую таблицу REST и независимые копии API-схем. Изменения SDK идут
  через источник OpenAPI и генерацию; generated `packages/rest-sdk/src` вручную не правится.

## Проверка и документация

- Команды из корня: `pnpm --filter @relay/contracts run typecheck`,
  `pnpm run test:contracts`; их область описана в README. Это проверки типов,
  не runtime-тесты Zod; собственного lint нет.
- По изменению согласуйте runtime-проверки Core/Server и совместимость потребителей,
  не требуйте весь репозиторий для небольшой правки.
- Знание обновляйте по [DOCUMENTATION](../../docs/DOCUMENTATION.md), покрытие —
  в общей матрице, не по одному наличию типа. Markdown проверяйте адресно.
