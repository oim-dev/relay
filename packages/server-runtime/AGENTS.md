# Работа в server-runtime

Для любого исполнителя и QA в `packages/server-runtime` действуют
[общие правила](../../AGENTS.md). Здесь владелец HTTP/OpenAPI/SSE и runtime сервера,
не бизнес-логики и не команды запуска. Выход за пакет согласуйте с оркестратором.

## До изменения

- Прочитайте [README](README.md), нужный раздел [API](docs/API.md) и
  [DEVELOPMENT](docs/DEVELOPMENT.md). Контракт предшествует правке транспорта.
- При неизвестном контексте начните с [PRODUCT](../../docs/PRODUCT.md) и
  [ARCHITECTURE](../../docs/ARCHITECTURE.md), далее выберите конкретную
  [возможность](../../docs/CAPABILITIES.md) и [domain-контракт](../../docs/domain/README.md).
  Читать все общие документы не требуется.
- Выбор проекта сверяйте с [CONFIGURATION](../project-runtime/docs/CONFIGURATION.md),
  схемы — с [Contracts API](../contracts/docs/API.md), гарантии записи и текущего
  хранения — с [STORAGE](../../docs/domain/STORAGE.md), без локальной копии версий.

## Транспортная граница

- Выбирайте проект и автора на запрос, валидируйте ввод и вызывайте сервис Core.
  Согласуйте local/HTTP/Core; не копируйте предметные проверки в контроллеры.
- Предметные поля и отношения согласует Core общей записью. Не требуйте второго
  клиентского запроса графа и не подменяйте сохранённую связь проекцией.
- Меняйте реальный маршрут, scoped-маршрут, DTO и OpenAPI согласованно.
  Переиспользуйте переносимые схемы, различайте input/output и описывайте параметры.
- После изменения API согласуйте экспорт `pnpm run openapi:export` и
  [генерацию SDK](../rest-sdk/docs/DEVELOPMENT.md); generated `src` не правьте руками.
  При работе с API-клиентом/codegen загрузите `rest-api-codegen-ru` через skill tool.
- Пользовательский URL и env/flags принадлежат приложению/подключению, не SDK.
  Внешние инструменты применяйте по фактической задаче, не для формальной проверки.
- Не добавляйте автоматический retry мутаций. Ошибка базы не означает пустую базу;
  SSE не заменяет ответ записи. Закрывайте созданные watcher, timer и stream.

## Проверки

- Выбирайте проверки из DEVELOPMENT: `pnpm --filter @relay/server-runtime run typecheck`,
  адресные transport-тесты или `pnpm run test:server`; собственного lint нет.
- Проверяйте реальные ответы и local/scoped пути, изоляцию проектов/авторов,
  конфликты и потерю ответа без повтора. Сборка не доказывает wire contract.
- Документацию поддерживайте по [DOCUMENTATION](../../docs/DOCUMENTATION.md);
  небольшая Markdown-правка требует адресных форматирования и ссылок, не всей сборки.
