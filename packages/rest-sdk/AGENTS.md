# Работа в REST SDK

Инструкция для любого исполнителя и QA в `packages/rest-sdk`; общие правила —
[корневой AGENTS.md](../../AGENTS.md). Здесь технический генерируемый клиент.
Изменение API и потребителей вне пакета согласуйте с оркестратором.

## Источник и маршрут

- До изменения прочитайте [README](README.md), [DEVELOPMENT](docs/DEVELOPMENT.md)
  и затронутый контракт [REST API](../server-runtime/docs/API.md).
- Если назначение и границы неизвестны, начните с [PRODUCT](../../docs/PRODUCT.md)
  и [ARCHITECTURE](../../docs/ARCHITECTURE.md); далее выбирайте только нужную
  [возможность](../../docs/CAPABILITIES.md) и [domain-контракт](../../docs/domain/README.md),
  а не все общие документы.
- При API-клиенте/codegen-логике обязательно загрузите `rest-api-codegen-ru`
  через skill tool. Внешние инструменты нужны по применимости, не автоматически.

## Правила изменения

- Весь `src/` генерируется: запрещены ручные правки и helpers внутри него.
  Исправляйте источник OpenAPI server-runtime, затем согласованно регенерируйте SDK.
- Источник схем собственного API — не URL настроенного пользовательского Server.
  Origin, проект, автор, timeout и экземпляр клиента принадлежат потребителю;
  не добавляйте их в общий singleton SDK.
- Не реализуйте бизнес-правила, файловое хранение или синхронизацию связей клиентом.
  Типы генератора не заменяют runtime-валидацию ответа в адаптере.
- Не включайте автоматический retry мутаций. Действующие гарантии и версии —
  в [STORAGE](../../docs/domain/STORAGE.md), политика HTTP Backend —
  в [CONFIGURATION](../project-runtime/docs/CONFIGURATION.md), без второй копии правил.

## Проверка результата

- По изменению используйте `pnpm --filter @relay/rest-sdk run generate`,
  `pnpm --filter @relay/rest-sdk run typecheck` и `pnpm --filter @relay/rest-sdk run build`.
  Generate создаёт временную базу: при запрете такой работы не запускайте его.
- Проверьте diff генерации, local/scoped операции и затронутых потребителей.
  Собственных test/lint нет; фактический транспорт проверяется у Server/потребителя.
- Следуйте [DOCUMENTATION](../../docs/DOCUMENTATION.md). Для одной Markdown-правки
  достаточно адресных проверок, не генерации и запуска всей системы.
