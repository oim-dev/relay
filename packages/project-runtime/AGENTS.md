# Работа в project-runtime

Для любого исполнителя и QA здесь действуют [общие правила](../../AGENTS.md).
Пакет владеет конфигурацией, реестром и общим Backend CLI/MCP. Изменения других
владельцев согласуйте с оркестратором, не расширяйте адаптер до предметного сервиса.

## Перед работой

- Прочитайте [README](README.md) и [CONFIGURATION](docs/CONFIGURATION.md) до изменения.
- Если контекст неизвестен, начните с [PRODUCT](../../docs/PRODUCT.md) и
  [ARCHITECTURE](../../docs/ARCHITECTURE.md); затем читайте только затронутую
  [возможность](../../docs/CAPABILITIES.md) и её [контракт](../../docs/domain/README.md).
  Общую библиотеку целиком читать не нужно.
- Для Backend сверьте [REST API](../server-runtime/docs/API.md),
  [Contracts](../contracts/docs/API.md) и метод Core. Гарантии повторов и актуального
  хранения берите из [STORAGE](../../docs/domain/STORAGE.md), не старых профилей.

## Границы адаптации

- Согласуйте `Backend`, local и HTTP с Core; транспорт не копирует бизнес-правила.
  Отсутствующий метод не обходите прямой записью файлов или вторым запросом связей.
- Сохраняйте идентичность проекта, изоляцию автора, проверку конвертов и результатов.
  HTTP-ошибка не разрешает local fallback; чтение конфигурации не создаёт базу.
- Пакет принимает явные параметры. Env/flags и жизненный цикл остаются у приложений;
  пользовательский URL подключения отличается от listener и источника OpenAPI.
- При изменении API-клиента или codegen-логики обязательно загрузите
  `rest-api-codegen-ru` через skill tool и прочитайте [SDK DEVELOPMENT](../rest-sdk/docs/DEVELOPMENT.md).
  Generated SDK `src` не правьте; изменение источника и генерацию согласуйте с владельцем.
- Не повторяйте мутации автоматически, включая timeout/5xx. После неопределённого
  ответа нужно чтение состояния; конфликт не разрешает подставить новую ревизию
  к старому телу. Политику чтений сверяйте с CONFIGURATION, не с HTTP-глаголом одним.

## Проверки

- Из корня доступны `pnpm --filter @relay/project-runtime run typecheck` и
  `pnpm --filter @relay/project-runtime run test`; подготовка зависимостей — в README.
  Собственного lint нет. Выберите проверки по изменённому пути.
- Тест конфигурации не доказывает HTTP Backend: при его изменении проверьте
  local/HTTP и нужных потребителей CLI/MCP, не весь репозиторий автоматически.
- Знания обновляйте по [DOCUMENTATION](../../docs/DOCUMENTATION.md); для Markdown
  достаточно адресной проверки формата, ссылок и diff.
