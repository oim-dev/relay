# Продуктовый скилл Relay

Приватный ESM workspace-пакет `@relay/relay-skill` содержит авторские материалы в `src`
и сборщик в `scripts`. Содержание принадлежит `relay-docs`, механизм — `relay-delivery`.
Главный источник — `src/skill.md`, явный состав поставки — `src/bundle.json`.

## Сборка и проверки

Из корня репозитория:

```sh
pnpm run skills:build
pnpm run skills:check
pnpm run skills:test
```

Прямые команды — `pnpm --filter @relay/relay-skill run build/check/test` с одним выбранным
действием. Из каталога пакета используйте `pnpm run build`, `pnpm run check`, `pnpm run test`.
Build/check работают на Node.js без запуска CLI и предварительной сборки приложений.
Тесты рабочего цикла используют CLI из исходников через tsx и `tasks-source`, с конфигурацией
TypeScript Server Runtime; они проверяют local и HTTP workspace на независимых базах.

`build` готовит staging в `.artifacts`, проверяет ссылки, заменяет `skills/relay` и обновляет
`apps/playground/.agents/skills/relay`. Оба пути считаются от корня репозитория независимо
от cwd. Замена каталога удаляет прежние материалы этого скилла, включая вложенные справочники;
соседние скиллы и проектные данные не затрагиваются.

`check` вычисляет ожидаемый пакет в памяти и только читает результаты и ссылки. Он обнаруживает
устаревшее содержание, лишние файлы и drift установленной копии без записи и staging.
Распространяемый каталог обязателен; копия Playground может отсутствовать на чистом checkout,
но если существует — проверяется. Build и check не публикуют изменения в Git или npm.

Turbo-задачи build/check/test не кешируются и не запускают предварительную сборку.
В корневом [процессе проверки](../../scripts/README.md#сборка-и-проверки) `skills:check`
входит в preflight до build, чтобы перегенерация не скрывала drift; `skills:test` — в tooling.
Полный корневой `check` обязателен перед push по правилам репозитория.

## Состав поставки

Пакет содержит ровно девять файлов:

- `SKILL.md` — назначение Relay, CLI discovery, обзор проекта, пять этапов работы,
  обязательность истории и карта референсов в самом конце; бюджет — до 300 строк.
- `references/KNOWLEDGE.md` — сбор знаний, паспорт и библиотека документов.
- `references/FEATURES.md` — заполнение и изменение фич и сценариев.
- `references/APPLICATIONS.md` — приложения и состав реализаций FI/SI.
- `references/TASKS.md` — доски, постановка, критерии, зависимости и результат исполнителя.
- `references/PLANNING.md` — итерации, планы, этапы и общий итог работ.
- `references/RELEASES.md` — состав и фиксация выпуска.
- `references/HISTORY.md` — сессии, участия, checkpoints, продолжение и делегирование.
- `bundle-info.json` — версия схемы, имя скилла и хеши входов без timestamp.

Скилл начинает чтение настроенного проекта с `overview`; подробности читаются адресно.
Основной интерфейс агента — `npx @oim-dev/relay-cli` с читаемым выводом. Точный синтаксис
даёт установленный CLI через `--help`, поэтому каталог команд и полная документация
интерфейсов в комплект не копируются. Server нужен человеку для Web; MCP используется
по явному запросу при проверенном подключении.

Методики объясняют применение предметной модели и качество содержания, опираясь на
канонические документы `docs/domain` и пользовательскую документацию владельцев. Изменение
предметного правила требует сверки соответствующей методики; сборщик не проверяет семантику
текста по изменению хешей кода. Агент читает нужный референс по карте, а не всю библиотеку заранее.

## Устройство сборки

В `files` манифеста пути относительны `src`. Сборщик переписывает ссылки `skill.md` в
`SKILL.md`, сохраняет ссылки между референсами и проверяет их переносимость без checkout.
Канонические страницы и исходники компонентов не являются runtime-зависимостью комплекта.
Генерация второго справочника CLI отклоняется.

Входы `files` хешируются автоматически; `watch` добавляет метаданные пакета, инструменты,
lockfile и общий Markdown-helper. `documents`, `aliases` и `externalRoots` остаются
возможностями сборщика для адресного включения и переписывания ссылок, но текущая поставка
их не использует. `processBundle({ root, check })` позволяет проверять независимые fixtures,
включая пути с пробелами. CLI сборщика не принимает агентские `--root` и `--format`.

Проверки покрывают точный состав исходников и поставки, карту в конце, переносимость,
детерминизм, удаление устаревших файлов и read-only check. Рабочие сценарии отдельно проверяют
реальные CLI-операции знаний, задач, планов, релизов и принятия дочерней истории через local/HTTP.
Это не проверка публикации npm-пакетов или поведения автономного агента.
