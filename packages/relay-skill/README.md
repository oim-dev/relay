# Продуктовый скилл Relay

Приватный ESM workspace-пакет `@relay/relay-skill` объединяет авторские источники в `src`
и технический сборщик в `scripts`. Содержание принадлежит `relay-docs`, механизм —
`relay-delivery`. Главный источник — `src/skill.md`, состав — `src/bundle.json`.

Из корня доступны алиасы `pnpm run skills:build`, `pnpm run skills:check`,
`pnpm run skills:test` и прямые пакетные команды:

```sh
pnpm --filter @relay/relay-skill run build
pnpm --filter @relay/relay-skill run check
pnpm --filter @relay/relay-skill run test
```

Из `packages/relay-skill` используйте `pnpm run build`, `pnpm run check`, `pnpm run test`.
Команды работают через исходники CLI с `tasks-source` и tsx, без предварительной
сборки приложений. Тест примеров использует конфигурацию TypeScript Server Runtime.

`build` готовит staging в `.artifacts`, публикует `skills/relay` и всегда обновляет
`apps/playground/.agents/skills/relay`. Оба выходных пути считаются от корня репозитория
независимо от cwd. `check` вычисляет ожидаемый пакет в памяти и только читает результаты
и ссылки: без записи, staging или предварительного `build`. Распространяемый `skills/relay`
обязателен; установленная копия Playground может отсутствовать на чистом checkout,
а если существует — также проверяется.

Turbo-задачи `build`, `check`, `test` имеют `dependsOn: []` и `cache: false`;
`lint`/`typecheck` не запускают `build`. Корневой `check` включает `skills:check` и
`agents:check`, а тесты обоих tooling-пакетов выполняет один раз через Turbo.
CI проверяет отслеживаемые выходы до сборки, чтобы она не скрывала расхождения.
CLI скилла не принимает агентские флаги `--root` и `--format`; библиотечный
`processBundle({ root, check })` позволяет работать с независимыми fixtures, включая пути с пробелами.

В manifest `files` относительны к `src`, а `documents`, `aliases`, `watch` — к корню
репозитория. Часть ссылок авторских материалов разрешается только в собранном пакете.
Метаданные `bundle-info.json` сохраняют схему версии 1, имя `relay` и хеши входов
без timestamp. Приватный workspace-пакет не входит в npm-выпуск CLI/Server/MCP.

## Состав и чтение

Корневой `SKILL.md` самостоятельно объясняет назначение и возможности Relay, роли
инструментов и единый цикл: знания о продукте → задачи → план и выполнение → релиз.
Новый и существующий проект проходят одну последовательность; сохранённые знания,
задачи и планы сначала читаются и актуализируются. Основной интерфейс агента — `npx @oim-dev/relay-cli`;
MCP используется только по запросу пользователя при настроенном и проверенном окружении.
Server обязателен для наблюдения человека в Web UI, в том числе при прямом local-CLI;
агент запускает или проверяет подходящий процесс и передаёт фактическую ссылку пользователю.
Все команды в главной инструкции и авторских примерах даны в CLI-синтаксисе.
Агент читает обычный человекочитаемый вывод, доступный пользователю, без отладочного формата.
Диагностика выполняется перед первым обращением к проектным данным; для объяснения
возможностей запуск окружения не нужен. При неизвестной границе local/workspace
целевая база уточняется до инициализации.
`references/interfaces/AGENT_GUIDE.md`, `CLI.md` и `CLI-COMMANDS.md` читаются адресно
для ближайшего действия, без обязательного предварительного чтения целиком.
Перед первым заполнением агент читает `references/guides/CONTENT.md` для нужного вида.
Основной файл задаёт стандарт содержательных Markdown-описаний и проверку достаточности
знаний до перехода к задачам; примеры показывают различие между аннотацией и требованиями.
Основной файл содержит карту предметных справочников с условиями чтения и вход
в библиотеку. Бюджет — до 300 строк после форматирования. Сборщик требует ссылки
на библиотеку и матрицу возможностей и проверяет ссылки поставляемых материалов;
полная карта `references` в `SKILL.md` перечисляет все поставляемые справочные страницы.

Основной маршрут задают четыре этапа `SKILL.md`,
карта справочных знаний находится в разделе «Где уточнять подробности».
За ней следует «Полная карта справочных материалов» с назначением каждой страницы.
Предметные правила остаются в канонической документации.
Агент читает нужные для текущего шага справочники, а при ошибке — восстановление.

`documents` берётся из канонических `docs` и пользовательских справочников владельцев.
Агентские протоколы и исполняемые примеры находятся в `src/references`.
`scripts/*.mjs` копируются побайтно, не форматируются как Markdown; диагностический
`src/scripts/diagnose.mjs` запускается без зависимостей и без checkout.

Локальные ссылки и HTTPS-ссылки на включённые страницы `oim-dev/relay/blob/main`
становятся внутренними. `externalRoots` явно разрешает ссылки на необязательные
инженерные источники в GitHub; неизвестные обязательные страницы останавливают сборку.
Ссылки внутри кодовых примеров не переписываются. Отдельные domain/guides-индексы
сохраняют навигацию; внутренние профили и инструкции разработчиков не поставляются.

## Диагностика

```sh
node skills/relay/scripts/diagnose.mjs --root /путь/к/проекту --client opencode
```

JSON версии 1 содержит независимые `runtime`, `configuration`, `server`, `client`,
`next`. Exit 0 означает полученный отчёт, не готовность подключения. `found` подтверждает
структурное чтение конфига, не полную schema-валидацию. JSONC/TOML не интерпретируются
как обычный JSON; такие файлы требуют проверки клиентом. `unverified` идентичности не
даёт права на запись. Скрипт не открывает Core, не вызывает npm и не исправляет данные.
Поля диагностики MCP и клиентские рекомендации не являются условиями готовности local-CLI.
Для запрошенной MCP-ветки состояние текущей сессии проверяет агент после перезапуска.

Новые конфиги используют `--transport stdio`: установленный через npx MCP должен
поддерживать этот флаг. Сборка исходников не публикует новую npm-версию автоматически.
