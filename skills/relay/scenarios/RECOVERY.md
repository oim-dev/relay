# Неопределённое состояние, ошибка и восстановление

[Карта сценариев](../SKILL.md). Временный маршрут при сбое подключения, конфликте,
потере ответа, неполном чтении или проблеме данных. После установления состояния
вернись к прерванному шагу основного сценария.

## Определи исходную ситуацию

Зафиксируй в текущем контексте проект, интерфейс, действие, аргументы и наблюдаемую
ошибку. Различи отказ чтения, отказ записи и неизвестный результат записи. Не считай
недоступные данные пустыми и не повторяй создание после таймаута автоматически.

## Что предложить пользователю

Объясни, что известно и что требуется проверить: «Ответ записи потерян; сначала
проверю состояние в том же проекте, затем определю следующий шаг». Для восстановления
подключения предложи проверку адреса и процесса. Для обслуживания базы сначала объясни
основание, затронутые данные и условия выполнения.

## Выбери ветку

| Наблюдение                                                 | Действия агента                                                                                                                    |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Server недоступен                                          | Проверить адрес, процесс и базу, восстановить Web UI и дать ссылку; доступность local-CLI не заменяет этот шаг                     |
| Не та регистрация или `identity=mismatch`                  | Остановить запись, установить нужную область, заново прочитать исходную сущность                                                   |
| Пользователь запросил MCP, но он недоступен                | Проверить конфиг выбранного клиента и перезапуск; CLI остаётся основным доступом к той же базе, файл сам не доказывает подключения |
| Опубликованный CLI не поддерживает нужную команду или флаг | Проверить через `npx @oim-dev/relay-cli <команда> --help`, сообщить блокер совместимости                                           |
| Ответ изменения потерян                                    | Перечитать запись, статус и отношения; после создания искать по доступным признакам, не только заголовку                           |
| Ответ публикации комментария потерян                       | Прочитать ленту и полное содержание подходящих сообщений перед решением о повторе                                                  |
| Конфликт ревизии                                           | Перечитать полный текст, сравнить с исходным намерением и согласовать новое изменение                                              |
| Список неполон или версия страниц устарела                 | Проверить продолжение; при конфликте начать чтение заново, сохраняя проект и фильтры                                               |
| Полный контекст превышает бюджет                           | Использовать адресное чтение нужных знаний; если нужен именно полный граф — проверить допустимый бюджет по контракту               |
| Ошибка индексов, формата или целостности                   | Установить конкретную причину и перейти к явному обслуживанию только при соответствующем поручении                                 |
| Завершение задачи, плана или релиза отклонено              | Прочитать предметный прогресс и состав; невыполненное обязательство требует работы или согласованного пересмотра                   |

## Как продолжать

1. Выполни доступные CLI-чтения, достаточные для выбранной ветки. `--request-id` служит
   корреляции, не возвращает сохранённый результат и не обеспечивает дедупликацию.
2. Если результат уже достигнут, не повторяй запись. Если однозначно не достигнут,
   определи новое действие в рамках поручения. При неустранимой неоднозначности
   передай её пользователю с фактами и конкретным вопросом.
3. Для обслуживания следуй справочнику: подтверждённая local-база, остановка записей,
   резерв и проверка поддерживаемого формата. Перестроение индексов, миграция и согласование связей
   решают разные задачи. Ошибка HTTP не разрешает переключиться на другую local-базу.
4. После исправления проверь проект, исходную запись и затронутые отношения обычным
   интерфейсом. Успешная проверка целостности не заменяет проверку пользовательского результата.

## Когда этап закончен

Известно состояние прерванного действия и подтверждено корректное продолжение либо
явно назван блокер, недостающее основание и следующий шаг. Вернись к прежнему маршруту
со свежими чтениями; после паузы используй [продолжение](RESUME.md).
