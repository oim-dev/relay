# Новый проект: от идеи или ТЗ к первой работе

[Карта сценариев](../SKILL.md). Выбирай, когда создаётся новый продукт и требуется
сформировать его знания. Пустая база при существующем коде — [внедрение](ADOPT_EXISTING.md).

## Определи исходную ситуацию

Проверь поручение, файлы проекта и доступные записи Relay. Выясни, есть ли идея, ТЗ,
ограничения, уже выбранные технологии и конкретная ближайшая задача. Не проси повторить
сведения, которые пользователь уже передал. Несколько независимых продуктов требуют
сначала определить [границы workspace](WORKSPACE.md).

## Что предложить пользователю

Кратко назови исходные материалы и ближайший результат: «Предлагаю уточнить назначение
и первый пользовательский сценарий, сохранить требования в Relay, затем определить
работу для первого результата». Подстрой предложение под поручение:

| Что есть                                | Следующий шаг агента                                                                   |
| --------------------------------------- | -------------------------------------------------------------------------------------- |
| Только «используй Relay»                | Проверить подключение; спросить, какой продукт создаётся и чем заняться сначала        |
| Идея без ТЗ                             | Уточнить пользователя, его цель, основной путь и границы первого результата            |
| Подробное ТЗ                            | Прочитать материал, выделить требования, противоречия и вопросы, показать понимание    |
| Конкретная первая задача                | Собрать достаточные основания для неё; не требовать полного описания будущего продукта |
| Просьба только описать или спланировать | Подготовить знания или план; результатом этапа не является разработка                  |

Задавай вопросы небольшими группами по ближайшему решению. Предлагай варианты там,
где нужен выбор; помечай собственный вариант как предложение. Не добавляй неуказанные
роли, авторизацию, интеграции или масштабирование как принятые требования.

## Как действовать

1. Выполни недостающую подготовку CLI по главной инструкции. Запусти Server или проверь
   подходящий работающий процесс и дай пользователю ссылку на Web UI. Подтверди чтение
   конфигурации и досок через CLI; MCP не является условием начала работы.
2. Сохрани исходное ТЗ и существенные уточнения по мере анализа, различая требования,
   предложения и открытые вопросы. Найди уже созданные записи перед добавлением новых.
3. Заполни паспорт: назначение, пользователи, границы и ограничения. Выдели фичи и
   конкретные сценарии с ожидаемым результатом и существенными отклонениями.
4. Предложи необходимые приложения и их ответственность. Frontend/backend — возможные
   части продукта, а не обязательная схема. После выбора создай приложения и нужные FI/SI,
   опиши собственный вклад каждого; проверь slug и префиксы до создания.
5. Прикрепи документы-основания к соответствующим сущностям, перечитай сохранённые тексты.
   Объясни пользователю, что определено, какие решения ещё открыты и что можно делать дальше.
6. Для порученной работы перейди к постановке задач и планированию. Существенное неизвестное
   вынеси в исследование или вопрос, а независимую определённую часть можно готовить дальше.

## Когда этап закончен

Для ближайшего объёма понятны пользователь, поведение, границы, ответственность приложений
и признаки результата; источники и нерешённые вопросы сохранены. Это достаточность знаний
для выбранного шага, а не требование описать весь будущий продукт и не доказательство реализации.

Далее: [планирование](PLANNING.md), [отдельная задача](TASK.md) или
[исследование](RESEARCH.md) — по цели пользователя. При паузе укажи записи и ближайший вопрос.
