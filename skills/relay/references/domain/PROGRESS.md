# Предметный прогресс и готовность

Прогресс объясняет, что выполнено, что осталось и какое обязательство мешает завершению.
Читайте его для нужной сущности, затем переходите к причинам и полным исходным записям.
Прогресс вычисляется Core по текущим данным; вручную записать процент или формулу нельзя.

## Состояние не равно выполнению

Фактическое выполнение задачи требует одновременно колонки `done`, выполненных критериев
и фактического выполнения всех детей и обязательных зависимостей. Правило применяется
транзитивно. `canComplete` проверяет обязательства без собственной колонки `done`.
Поэтому задача в `review` может быть готова к закрытию, но ещё не выполнена.

Если зависимость вновь открыта, зависимая задача теряет фактическое выполнение,
даже оставаясь в `done`. Автоматического перемещения колонок нет. Такое изменение
влияет на все учитывающие задачу реализации, требования, планы и релизы.
`cancelled` не является успехом ни для самой задачи, ни для её потребителей.

## Чей состав считается

Есть восемь предметных обработчиков, а не единый процент для всех видов:

| Сущность   | Основа расчёта                                                                   |
| ---------- | -------------------------------------------------------------------------------- |
| Задача     | Колонка, критерии, дети и обязательные зависимости                               |
| Реализация | Собственные задачи; для FI также активные SI той же фичи и приложения            |
| Сценарий   | Активные реализации приложений и прямые продуктовые задачи                       |
| Фича       | Её проектные сценарии, активные FI и прямые продуктовые задачи                   |
| Приложение | Объявленный состав реализаций; продуктовая работа и все задачи доски различаются |
| Продукт    | Фичи и их готовность по полному предметному составу                              |
| План       | Фактическое выполнение явно включённых задач этапов                              |
| Релиз      | Выбранные планы со статусом `completed` и текущим фактическим выполнением        |

Документу, проекту или доске не назначается искусственная готовность лишь потому,
что это сущность. Этап раскрывается внутри плана, не как девятый самостоятельный вид прогресса.

Для продуктовой готовности `none` означает отсутствие готовности, `partial` —
промежуточное состояние, `done` — готовность всего обязательного состава.
SI без задач не готова. FI может завершиться по выбранным SI без отдельной прямой
задачи FI, но существующие незавершённые прямые задачи продолжают блокировать её.
Снятые реализации не входят в активный расчёт; их адресное чтение должно отличать
снятое участие от действующего обязательства.

Пустая обязательная часть не считается выполненной. Если Web выполнил три задачи,
а обязательная реализация API не имеет задач, счётчик может быть 3/3, но сценарий не готов.
Проектный сценарий без работы не исчезает из обязательств своей фичи.
Пустой этап плана не выполнен, но не блокирует завершение плана с непустым фактически
выполненным общим составом задач. Markdown `completionConditions` этапа не исполняется.

## Счётчики и границы

Одна задача учитывается один раз в конкретном уникальном счётчике, даже если достижима
по нескольким предметным включениям. Счётчики пересекающихся составов нельзя просто
складывать, а проценты — усреднять. Распределение по колонкам отличается от числа
фактически выполненных задач.

Дети и зависимости влияют на готовность, но не включаются автоматически в собственный
состав реализации или плана. Внешняя инфраструктурная зависимость может блокировать
состав, не появляясь среди его собственных задач.

При отсутствии работ нельзя показывать 100%. Полные итоги не зависят от фильтра,
числа загруженных строк или страницы. Ограниченный список составляющих или причин
нужно читать с продолжением; отсутствие строки на странице не означает отсутствия работы.

## Как разбирать неготовность

1. Различите сохранённое состояние и вычисляемую готовность.
2. Найдите невыполненную часть, пустое обязательство или адрес внешнего блокера.
3. Прочитайте её собственный прогресс и полные требования.
4. Выполните работу либо пересмотрите состав, если это разрешено: закрытый план неизменяем.
5. Перечитайте прогресс после сохранения результата.

Цикл обязательств, повреждённая ссылка и ошибка чтения должны давать диагностируемую
ошибку, а не готовность, пустой список или бесконечный обход.
Обычная правка описания не снимает готовность; изменение текста критерия снимает его отметку.

## Что прогресс не доказывает

Статусы закрытого [плана](PLANNING.md) и выпущенного [релиза](RELEASES.md) сохраняют
факт перехода, даже если текущая готовность утрачена. Расчёт не переписывает эти состояния.
`progress.completed` плана не означает статус `completed`, а готовность релиза — `released`.
Он также не доказывает внешнее тестирование, публикацию или поставку.

Прогресс использует предметные данные, а не обход произвольного [контекста](CONTEXT.md).
Прикрепление документа, `related` и диагностические рёбра не создают обязательств.
Чтение прогресса не меняет ревизии и не сохраняет историю вычислений.
