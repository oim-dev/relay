# Запуск Relay Server

Server открывает Web, REST и события изменений для одного проекта или workspace.
До запуска нужен существующий проект либо реестр: начните с
[подключения проекта](../guides/GETTING_STARTED.md).
Требуется Node.js 22+; отдельный запуск Web для установленного пакета не нужен.

## Обычный запуск

Из каталога проекта или workspace:

```bash
npx @oim-dev/relay-server --open
```

Команда ищет конфигурацию вверх от текущего каталога, выводит `Relay: <url>` и адрес
Swagger, затем открывает браузер. Используйте фактически напечатанный URL.
Если браузер не открылся, откройте этот адрес вручную; отсутствие программы открытия
браузера не означает отказ API.

Процесс остаётся в терминале. `Ctrl+C` (`SIGINT`) или `SIGTERM` закрывает приложение,
активные подписки и наблюдатели. Server сам не перезапускает процесс после остановки.

## Параметры команды

| Параметр            | Назначение                                                |
| ------------------- | --------------------------------------------------------- |
| `--config <path>`   | Явно выбрать проектный конфиг или workspace вместо поиска |
| `--port <number>`   | Переопределить порт HTTP; `0` выбирает свободный порт     |
| `--actor <id>`      | Задать автора по умолчанию для изменений через сервер     |
| `--open`            | Открыть браузер после успешного запуска                   |
| `--format <format>` | Формат сообщения запуска: text; json — для отладки        |
| `--help`            | Показать справку без запуска                              |
| `--version`         | Показать версию команды                                   |

Приоритеты конфигурации, порта и автора, env и правила относительных путей находятся
в [CONFIGURATION](CONFIGURATION.md).
Флаги нужны для явного выбора, а не для повторения значений по умолчанию. Например,
для другого реестра или временного свободного порта:

```bash
npx @oim-dev/relay-server --config ../team/relay.workspace.json --open
npx @oim-dev/relay-server --port 0
```

Сообщение с URL означает успешный запуск, не завершение процесса. Передайте пользователю
кликабельную ссылку на Web UI по фактическому адресу. Ошибки запуска выводятся
в stderr как `CODE: сообщение` с ненулевым кодом завершения, в том числе в отладочном
формате; универсальный JSON-конверт ошибки для команды не обещается.

## Local, workspace и Web

`.relay/config.json` выбирает local, `relay.workspace.json` — workspace, даже если
зарегистрирован один проект. В одном каталоге реестр имеет приоритет. Запуск не создаёт
отсутствующую базу и не переключается на другую при ошибке найденного конфига.

В local Web открывает один проект; в workspace позволяет выбрать зарегистрированную
независимую базу. Изменение регистрации не объединяет данные. Реестр перечитывается
при выборе проекта без перезапуска Server.

| Адрес относительно URL запуска      | Что открывает                                     |
| ----------------------------------- | ------------------------------------------------- |
| `/`                                 | Web из поставки сервера                           |
| `/api/docs`                         | Swagger с выбором проекта                         |
| `/api/openapi.json`                 | OpenAPI 3.1                                       |
| `/api/v1/health`                    | Проверку доступности API, не полную проверку базы |
| `/api/v1/server`                    | Режим и состояние регистраций                     |
| `/api/v1/projects/:project/context` | Контекст подключения выбранной базы               |

Проектные REST-операции в local доступны также по короткому `/api/v1/...`.
Workspace требует `/api/v1/projects/:project/...`. Все операции, ошибки и SSE описаны
в [API](API.md).

Установленная поставка содержит Web. Встраиваемый runtime может работать без статики:
доступность API и Swagger в таком случае не обещает страницу `/`.
Прямые SPA-адреса обслуживаются Web; неизвестный API и отсутствующий asset не должны
возвращать HTML приложения.

## Если запуск или подключение не удались

- Конфиг не найден: перейдите в каталог проекта, инициализируйте проект через CLI
  либо явно выберите существующий конфиг. Не создавайте пустую базу поверх повреждённой.
- Порт занят: остановите свой прежний процесс или явно выберите другой порт;
  при `--port 0` передайте клиентам фактический URL.
- Проект недоступен: проверьте путь регистрации и ошибку в `/api/v1/server`.
  Недоступная регистрация не означает пустую базу.
- Origin/Host отклонён: Server рассчитан на loopback, а не публичную сетевую публикацию.
  Используйте адрес запуска; произвольные Host и cross-origin запросы запрещены.
- База требует обслуживания: следуйте [восстановлению](../guides/RECOVERY.md).
  Server не выполняет скрытую миграцию вместо пользователя.

Запись плана или релиза не запускает агента, внешнюю проверку или развёртывание.
Для работы над самим сервером используйте отдельное [руководство разработчика](https://github.com/oim-dev/relay/blob/main/apps/server/docs/DEVELOPMENT.md).
