# Проектное подключение MCP к клиенту

MCP запускает и останавливает клиентское окружение через `npx`; Relay Server работает
отдельно. Конфигурация добавляется **только в проект**, не в домашние настройки.

## Перед настройкой

1. Определите клиент по текущей сессии. Наличие клиентских файлов не выбирает текущий
   клиент: при неопределённости спросите пользователя.
2. Прочитайте проектный конфиг. Дополните только Relay, сохранив остальные MCP и поля;
   не переписывайте JSONC/TOML как JSON и не создавайте конкурирующие файлы.
3. Предложите подготовку отсутствующего Relay и дождитесь согласия. Затем выполните
   [первый запуск](../guides/GETTING_STARTED.md).
4. В терминале проекта выполните `npx @oim-dev/relay-mcp --help`: подготовьте npm-кеш
   и ответьте на возможный запрос npm **до** подключения stdio. Проверьте `--transport`
   со значением `stdio`. Если опубликованная версия не поддерживает его, сообщите
   несовместимость поставки. Не записывайте неработающий конфиг и не переходите
   молча к ручному запуску HTTP MCP.

Примеры используют Server `http://127.0.0.1:4700`. Подставьте фактический origin.
Явный адрес убирает зависимость MCP от cwd, но не подтверждает идентичность базы.

## Claude Code

Файл **`.mcp.json` в корне проекта**:

```json
{
  "mcpServers": {
    "relay": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "@oim-dev/relay-mcp",
        "--transport",
        "stdio",
        "--server-url",
        "http://127.0.0.1:4700"
      ]
    }
  }
}
```

Только project scope хранится в `.mcp.json`. Claude Code «local scope» означает запись
в домашнем `~/.claude.json` и **не подходит**. Не вызывайте `claude mcp add` без project
scope. Предложите перезапуск в этом проекте и штатное подтверждение проектного сервера,
если клиент его запросит. Состояние видно в `/mcp`; готовность проверяется вызовом.

## Codex

Файл **`.codex/config.toml` внутри проекта**:

```toml
[mcp_servers.relay]
command = "npx"
args = ["@oim-dev/relay-mcp", "--transport", "stdio", "--server-url", "http://127.0.0.1:4700"]
```

Не добавляйте одноимённую таблицу повторно. Проектная конфигурация читается только
для доверенных проектов: доверие подтверждает пользователь средствами клиента.
Не меняйте глобальные файлы. Предложите перезапуск сессии/расширения, затем чтение Relay.

## OpenCode

Файл **`opencode.json` в корне проекта**; существующий проектный JSONC дополните
вместо создания второго файла:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "relay": {
      "type": "local",
      "command": [
        "npx",
        "@oim-dev/relay-mcp",
        "--transport",
        "stdio",
        "--server-url",
        "http://127.0.0.1:4700"
      ],
      "enabled": true
    }
  }
}
```

`local` здесь — процесс клиента, не режим базы. OpenCode загружает конфигурацию при
запуске: предложите выйти и открыть проект снова.

## Другое окружение и проверка

Выясните поддержку проектного конфига и команды
`npx @oim-dev/relay-mcp --transport stdio --server-url <origin>`.
Используйте документированный формат. Если проектная настройка не поддерживается,
сообщите ограничение; не переходите к глобальной или ручному запуску MCP.
На native Windows исполнение `npx.cmd` зависит от launcher клиента: проверьте его
документацию и запуск, не считайте POSIX-пример проверенным на Windows.

После настройки запустите Server, сообщите URL и необходимость перезапуска клиента.
Файл означает «подготовлено», не «подключено». После перезапуска:

1. Найдите инструменты Relay через discovery; клиент может добавлять префиксы имён.
2. Вызовите `projects_list({})`, проверьте режим, доступность и идентичность проекта.
3. В workspace выберите проект явно; прочитайте `project_config` и `boards_list`.
4. Для содержательных записей проверяйте полный Markdown в `structuredContent`.

Stdio не занимает порт 4710 и не запускает API. Без Server discovery доступен,
предметный вызов возвращает ошибку. После запуска API повторите **чтение**.
Потерянный ответ записи требует [проверки состояния](../guides/RECOVERY.md).
Отдельно управляемый HTTP-режим описан в [MCP](MCP.md).
