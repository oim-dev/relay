# Терминальное представление Relay CLI

Этот документ помогает читать человеческий вывод и настраивать его для терминала,
pipe и CI. Агент использует то же читаемое представление, которое видит пользователь; синтаксис команд,
конверты, ошибки и страницы определены в [справочнике CLI](CLI.md).

## Выбор формата

```bash
npx @oim-dev/relay-cli task get PRODUCT-1
npx @oim-dev/relay-cli task list --format text --color never
```

Если формат не передан, используется настройка конфигурации; исходное значение CLI —
`text`. Pipe сам по себе не переключает формат. Если конфигурация меняет его,
агент явно передаёт `--format text`, чтобы пользователь мог читать его действия и результаты.

В text предметные команды показывают карточки, таблицы, содержание и подсказки
следующего действия. Отладочный JSON возвращает неизменённые машинные поля. Включение
цвета или изменение ширины не меняет данные JSON. Help и версия всегда текстовые.
Технические команды реестра `projects` используют общее структурированное
представление, а не полноценные предметные карточки.

## Цвет и ширина

`--color auto` — обычный режим; `always` принудительно включает подсветку,
`never` выключает. В auto:

1. Непустой `NO_COLOR`, `TERM=dumb` или `FORCE_COLOR=0` выключает цвет.
2. Иначе наличие `FORCE_COLOR` включает цвет.
3. Иначе цвет включён только для TTY stdout.

Явный `--color always` имеет приоритет над автоматическими запретами. JSON всегда
выключает цвет, в том числе при `always`. Цвет — дополнительное обозначение:
результат и состояние остаются понятны по тексту и символам без подсветки.

Ширина берётся из `stdout.columns`, при его отсутствии — из `COLUMNS`.
Корректное положительное целое ограничивается диапазоном 24–160; иначе используется
100 колонок. `COLUMNS` не переопределяет фактическую ширину TTY, если она известна.

```bash
NO_COLOR=1 npx @oim-dev/relay-cli task list --format text
COLUMNS=40 npx @oim-dev/relay-cli product overview --format text --color never | less
npx @oim-dev/relay-cli task get PRODUCT-1 --format text --color always | less -R
```

На узкой ширине представление может переходить от таблиц к карточкам. Выравнивание
учитывает Unicode и ANSI: число байтов, длина JS-строки и экранная ширина не равны.
Длинные строки переносятся; не используйте пробельные позиции таблицы как API.

## Карточки, списки и Markdown

В списке сначала найдите ключ/ID и краткое описание, затем вызовите адресную команду
`get`. Карточка помогает прочитать состояние, ревизию, автора, содержание и связи;
список не обязан включать полный текст. Пустая выборка показывается как пустой
результат, а не как ошибка отсутствующей записи. Не путайте её с отказом чтения базы.

Заголовки — одна строка, summary — обычный многострочный текст. Полное содержание
рендерится как Markdown: заголовки, списки, цитаты, inline-код, ссылки и fenced code.
Для json/js/ts/bash/sh/http предусмотрена лёгкая лексическая подсветка блоков.
Это не HTML-браузер и не исполнение кода. Маркеры Markdown и адреса ссылок остаются
видимыми; абзацы, пустые строки и отступы не схлопываются в одну строку.

Отображение применяет безопасный текст: пользовательские управляющие
последовательности не должны исполняться терминалом. Не считайте text побайтовой
копией исходного поля: переносы, оформление и обезвреживание управляющих символов
принадлежат представлению. В обычной работе читайте полный текст карточки; побайтовую
проверку содержимого выполняют отдельно при отладке CLI.

## Страницы и бюджет

Человеческие списки показывают конец либо продолжение; команда продолжения помогает
сохранить фильтры и версию. При ручном копировании проверьте также проект и нестандартный
конфиг. Разные семейства используют `--snapshot-version`, локальный `--version`
или `--cursor`; не заменяйте одно другим. Подробная таблица —
[правила продолжения](CLI.md#правила-продолжения).

`--max-bytes` ограничивает **полный UTF-8 ответ выбранного формата**, а не число
экранных символов. Дополнительная разметка/ANSI и многобайтные символы тоже занимают
бюджет. По умолчанию 16384 байта, если конфиг не задаёт иное; диапазон 1 КиБ–128 МиБ.
При `RESPONSE_TOO_LARGE` уменьшите страницу, прочитайте отдельную запись или явно
увеличьте лимит. `graph context` не имеет страниц: он возвращает полный ответ
с `complete:true` либо ошибку, никогда успешное усечение.

```bash
npx @oim-dev/relay-cli graph context PRODUCT-1 --format text --max-bytes 1048576
npx @oim-dev/relay-cli entities list --kind document --limit 10 --format text
```

## Pipe и ошибки

Штатный результат и штатная ошибка идут в stdout; stderr штатного вызова чист.
Ошибка имеет код и понятное сообщение, в text — также визуальную отметку.
Проверяйте код завершения и сообщение результата, а не наличие слова «ошибка» в пользовательском тексте.
Закрытие pipe получателем (`EPIPE`) считается штатным и даёт код 0.

Help группы не требует открытия проекта. Ошибка синтаксиса указывает help команды,
в которой возникла проблема. Ошибка бюджета после выполнения записи не доказывает
отсутствие изменения: сначала перечитайте состояние, не повторяйте вслепую.

## Где сопровождается представление

Для разработчика: `src/terminal.ts` вычисляет среду, `src/presentation/` содержит
предметные рендереры, `src/presentation/markdown.ts` — Markdown,
`src/queries/result.ts` сериализует конверт, `src/output.ts` проверяет бюджет.
Подробности проверки и добавления команды — в [EXTENDING.md](https://github.com/oim-dev/relay/blob/main/apps/cli/docs/EXTENDING.md).
Пути исходников относятся к checkout, а не обещают наличие TypeScript в npm-архиве.
