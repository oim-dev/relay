## REST

Корень: `/api/v1/projects/:project/board-tasks`; local также `/api/v1/board-tasks`.
Обычный конверт `{ok:true,data:...}`. Записи возвращают первоначальную квитанцию
`{id,key,boardId,revision,action,requestId}`, чтение — актуальное состояние.
Создание с `includeTask: true` дополнительно возвращает `task` — первоначальное состояние
для мгновенного открытия редактора. По умолчанию квитанция компактная, без полного Markdown.

| Метод | Путь                 | Назначение                                                                          |
| ----- | -------------------- | ----------------------------------------------------------------------------------- |
| GET   | `/`                  | Карточки: `board`, `column`, `q`, `readiness`, `offset`, `limit`, `version`         |
| GET   | `/:reference`        | Полный Markdown и вычисляемые `blockers`, `blocked`, `ready`                        |
| GET   | `/:reference/links`  | Прямые и обратные связи: `offset`, `limit`, `version`                               |
| POST  | `/`                  | `board`, `title?`, `description?`, `column?`, `includeTask?`, `requestId`, `actor?` |
| POST  | `/:reference/update` | `title?`, `description?`, `ifRevision`, `requestId`, `actor?`                       |
| POST  | `/:reference/move`   | `column`, `board?`, `beforeId?`, `ifRevision`, `ifVersion?`, `requestId`, `actor?`  |
| POST  | `/:reference/links`  | `target`, `relation`, `remove?`, `ifRevision`, `requestId`, `actor?`                |

`reference` — ID из 8 символов или текущий/прежний ключ задачи. `board` принимает ключ,
slug, префикс или ID. `relation`: `depends-on`, `related`, `parent`; `remove` по умолчанию false.
`beforeId` — ключ или ID карточки; null/отсутствие означает конец полной колонки.
Новая задача по умолчанию в `inbox`, описание пустое. Markdown — строка до 256 КиБ UTF-8.
Заголовок — строка до 1024 байт, по умолчанию пустая. Прямых зависимостей/связей не более 200 каждого вида.

Страница содержит `items`, `total`, `nextOffset`, `version`. Размер 40, диапазон 1–100;
`completion=unfinished` исключает done/cancelled до вычисления total и страниц;
`completion=finished` выбирает только их. Без фильтра статусы не исключаются.
`searchIn=title` ограничивает q ключами (включая прежние), ID и заголовком;
`searchIn=all` или отсутствие сохраняет также поиск в Markdown. Эти фильтры относятся
к GET списка задач, а не к чтению существующих связей.
`parentId` принимает ID или текущий/прежний ключ родителя и выбирает только прямые
подзадачи до вычисления счётчика и пагинации. Без фильтра возвращается обычный список.
Готовые и отменённые дети остаются в выборке, если отдельно не задан `completion`.
полное описание не входит в список карточек. Версия относится к задачам всего проекта:
изменение соседней доски тоже может изменить блокеры. Данные связей показывают направление
и актуальную карточку соседа; транзитивный граф читается последовательно по ID.

`blockers` объединяет невыполненные прямые зависимости и прямых детей (`parentId`),
без повторов. Блокировку снимает фактическое выполнение: `done`, критерии и все обязательства
ниже по цепочке. [Адресный прогресс](PROGRESS.md) объясняет причины. `TASK_BLOCKED` запрещает перевод
родителя в `done`, создание либо привязку незавершённого ребёнка к готовому родителю.
Повторное открытие ребёнка пересчитывает блокеры без автоматического переноса родителя.
Новые рёбра проверяются на циклы общего порядка завершения, включая смешанные
цепочки детей и зависимостей. Старые смешанные циклы не блокируют чтение и удаление
связей; это позволяет исправить их без ручного изменения файлов.

Ошибки: 404 `NOT_FOUND`, 400 `VALIDATION_ERROR`, 409 `REVISION_CONFLICT`, `BOARD_CHANGED`,
`TASK_BLOCKED`, `DEPENDENCY_CYCLE`, `IDEMPOTENCY_CONFLICT`, `INVALID_REFERENCE`.
Повтор проверяется до ревизии и возвращает исходную квитанцию даже после следующего переноса.
Область requestId — автор и проект. Повтор с другим содержимым отклоняется.

## Хранение и восстановление

В едином формате текущая задача находится в `entities/tasks/{id}.json` независимо от доски.
Комментарии и квитанции находятся в файле задачи, общего аудита нет;
перенос не перемещает файл. Продуктовые линки
и группы связей Core изменяются одним общим WAL. [Формат и миграция](STORAGE.md).
Описание файла задач версии 5, вложенных путей и прежнего WAL ниже применяется к старым базам.

Обсуждения, их REST/хранение/совместимость описаны отдельно:
[контракт ленты задачи](TASK-ACTIVITY.md).

### Критерии приёмки

GET задачи и списка возвращает `acceptance: {total, completed}` и `canComplete`.
`blocked`, `blockers` и `ready` сохраняют смысл зависимостей/подзадач; критерии влияют
только на возможность завершить задачу. Полные тексты читаются отдельно:

| Метод | Путь                                | Назначение                                                                           |
| ----- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| GET   | `/:reference/criteria`              | Заголовки, summary и выполнение; offset/limit/version, по умолчанию 20, максимум 100 |
| GET   | `/:reference/criteria/:criterionId` | `{criterion, revision}` с полным Markdown                                            |
| POST  | `/:reference/criteria`              | Адресное действие с action, ifRevision, requestId, actor?                            |

Действия POST:

- `add`: title, summary?, description?; назначает ID и добавляет в конец.
- `update`: criterionId, title?, summary?, description?; хотя бы одно поле обязательно,
  пропущенные поля сохраняются. Изменение текста сбрасывает выполнение/автора/время.
- `complete`: criterionId, completed — явное boolean-состояние, не переключатель.
- `remove`: criterionId; удаление сохраняет порядок и ID остальных строк.

Квитанция дополнена criterionId, action — `criterion-add/update/complete/remove`.
Повтор возвращает первоначальную квитанцию до проверки ревизии. Список содержит
items/total/nextOffset/version/revision; его версия — ревизия задачи.
Несовпадение версии — `BOARD_CHANGED`, старой ревизии — `REVISION_CONFLICT`.
В готовой задаче изменения критериев возвращают 409 `TASK_ACCEPTANCE_LOCKED`.
Невыполненные критерии при создании/переводе в done — 409 `TASK_ACCEPTANCE_INCOMPLETE`.

Критерий: ID из 8 символов, обязательный однострочный title до 1024 байт,
summary — обычный многострочный текст до 4 КиБ, description — Markdown до 64 КиБ.
completedAt/completedBy заполнены только при completed=true. Максимум 100 критериев.
Создание задачи (включая движок сущностей) принимает `acceptanceCriteria?: Array<{title,summary?,description?}>`
и сохраняет задачу с невыполненными критериями атомарно. Размер HTTP-запроса дополнительно
ограничен общим лимитом сервера; это не отменяет лимит файла задачи.

### Файл задачи

Создание и обновление принимают `productLinks?: Array<{kind,id}>`: kind — `feature`,
`scenario` или `implementation`, id — постоянный ID цели (1–128 символов) этого проекта.
Набор заменяется целиком, `[]` очищает; максимум 100. Повторы целей запрещены.
Тип доски ограничивает набор: `product` принимает `feature`/`scenario`,
`application` — только `implementation` своего `applicationId`, `infrastructure` — только `[]`.
Новые имплементации должны быть активными; ранее связанная снятая имплементация сохраняется.
Несовместимость возвращает `INVALID_REFERENCE`; перенос между досками проверяет
весь набор до записи и требует предварительного явного снятия несовместимых связей.
Чтение старых записей, изменение содержания без `productLinks` и смена колонки
на той же доске не перепроверяют старые связи. Миграции формата нет.
Тип задачи отсутствует. Создание дополнительно принимает `parentId?` для атомарной
подзадачи. GET списка принимает `productTarget?` — ключ/ID фичи, сценария либо имплементации.
Выборка обходит тот же состав, что готовность: проектная фича включает свои сценарии
и активные реализации; проектный сценарий — активные SI; FI — выбранные активные SI
своего приложения и фичи. Прямые задачи каждого узла также входят в список.
Снятая имплементация остаётся адресуемой для собственных исторических задач,
но не расширяет состав родителя.
Задача с несколькими подходящими ссылками показывается один раз. Расширение цели
применяется до остальных фильтров, total и пагинации; произвольные рёбра графа не добавляют задачи.
Версия списка с productTarget учитывает также состав активных реализаций и предназначена
для продолжения этой выборки; для ifVersion переноса читается обычная версия канбана без productTarget.

Создание также принимает dependencies/related — до 100 ключей или ID задач каждого вида.
Для унифицированных полей targets, parent и действий по ключам доступен [движок сущностей](ENTITIES.md).

В формате 3 задача находится в `entities/tasks/<id>.json`: полные `comments`,
`commentSequence` и бессрочные `receipts` встроены в файл владельца. Общие `events`
не сохраняются; алиасы и предметные данные не удаляются вместе с аудитом.
[Точный контракт и переход](STORAGE.md).

Далее описан прежний формат, только как источник миграции:
`.relay/boards/<slug>/tasks/<id>.json`, запись `version: 5`. Критерии находятся
в массиве `acceptanceCriteria` этого же файла; вложенный Markdown кодируется массивом строк.
Публичные поля дополняются
`keys` (история ключей), `requests` (квитанции и полные хеши запросов), `events` (новые ревизии).
Markdown представлен массивом строк; пустые строки, отступы и завершающий перевод строки
сохраняются. Чтение не меняет содержание.
Markdown во вложенной первоначальной квитанции также кодируется массивом строк.
Версии 1/2/3 совместимо читаются с пустыми критериями, версия 1 получает пустые productLinks без изменения файла.
Версия 4 читается с сохранением критериев и прежних событий. Следующая
атомарная запись публикует версию 5; ID, ключи, текст и квитанции сохраняются,
ревизия меняется только вследствие самой пользовательской операции.
Промежуточное локальное поле kind, отменённое до выпуска, игнорируется кодеком
также во вложенной квитанции. Старые pending-намерения читаются и восстанавливаются.

Все операции защищены общей блокировкой Core. Перед составной записью публикуется
`.relay/kanban-pending.json`: список целевых документов и прежних путей переноса.
Он долговечный, не временный кеш. Перед следующей операцией Core публикует целевые
документы, удаляет прежний файл перемещённой задачи и затем намерение. Повтор шагов безопасен.
Промежуточный дубликат не наблюдается читателями под блокировкой.

Перемещение перенумеровывает порядок целевой колонки одной транзакцией; изменившиеся
карточки получают новые ревизии. Номера ключей выделяются по сохранённой истории всех
задач, поэтому после переноса номер не переиспользуется. Удаление задач пока отсутствует.
Файл задачи ограничен 16 МиБ, намерение — 32 МиБ. Ошибка размера возникает до публикации.

SSE сравнивает версию нового канбана и наблюдает каталоги задач всех досок, включая
прямую запись локального CLI. REST остаётся источником данных.

## Короткие ID

Общий генератор `packages/core/src/shared/ids.ts` выдаёт 8 символов из `A–Z`, `a–z`, `0–9`.
Случайный ID содержит хотя бы одну букву.
Генерируемые ID записей продукта, контрактов, задач и проектов используют короткую форму.
Проекты изолируют пространства ID;
повтор projectId в реестре отклоняется существующей проверкой.
При случайной генерации проверяется занятость ID в агрегате/каталоге; производные ID
досок и идемпотентных вложенных записей проверяются перед записью. Полные ключи запросов
сохраняются отдельно, чтобы сокращённый хеш не подменял проверку повтора.

Старые длинные ID не переименовываются: их схемы продолжают читаться, сохранённые связи
и квитанции остаются работоспособными. `passport` — семантический адрес паспорта продукта.
UUID запросов, хеши версий и имена временных файлов не сокращаются.
