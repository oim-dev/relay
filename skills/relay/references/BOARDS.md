# Доски: хранение и REST

Продуктовые правила: [доски проекта](BOARDS.md).
Владелец схем и операций — `packages/core`, транспорта — `packages/server-runtime`.

## Каталог хранения

В едином формате доска записана в `entities/boards/{id}.json`, её префикс — в
`keyspaces/{id}.json`, задачи — в общей коллекции `entities/tasks`. Slug используется
в интерфейсе, но не определяет путь. Приложение, доска и связи публикуются
общей операцией; квитанции и история операций не сохраняются.
Подробности и переход — [STORAGE.md](STORAGE.md).

### Совместимый прежний формат

Ниже описан источник переноса, не разрешение сохранять события и квитанции сейчас.
При переходе весь автоматический аудит удаляется, пользовательские комментарии сохраняются.

Корень `boards` находится рядом с конфигурацией проекта, независимо от прежнего
`storageDir`. Стандартное размещение:

```text
.relay/boards/
  product/board.json
  product/tasks/
  web/board.json
  web/tasks/
  infrastructure/board.json
  infrastructure/tasks/
```

`board.json` содержит `version: 1`, постоянный `id`, `slug`, `prefix`, `kind`, `applicationId`,
`revision`, `createdAt`, `createdBy`. `kind`: `product`, `application`, `infrastructure`.
У системных досок `applicationId: null`, префиксы — `PRODUCT` и `INFRA`.
Новые ID — 8 символов; ID прикладной доски устойчиво выводится из ID приложения.
Старые `board_product`, `board_infrastructure` и префиксные ID продолжают читаться.
Префикс принимает 2–16 заглавных латинских букв и цифр, первый символ — буква.
При изменении читаемого ключа движком запись переходит в version 2: key, aliases, requests
и events сохраняются атомарно с ревизией. Чтение version 1 остаётся совместимым;
начальный ключ — BOARD-<префикс>. [Общая адресация](ENTITIES.md).
При создании приложения задаётся `fields.prefix`; без него префикс получается из slug.
Смена префикса запрещена; совпадение с другой доской отклоняется.

Slug должен совпадать с именем папки. У доски приложения совпадают slug и ссылка на
приложение; название при чтении берётся из актуальной записи приложения. Дубли ID,
несоответствие пути и потерянные связи отклоняются. Новые задачи записываются в `tasks/`
с постоянным ID в имени файла. [Контракт канбана](KANBAN.md) описывает операции и восстановление.

## Создание и восстановление

Для нового формата используется общий `transactions/pending.json`; сведения о
`.pending-applications` ниже относятся к прежним базам.

Init создаёт системные доски до успешной публикации конфигурации. Повтор init существующего
проекта возвращает прежнюю ошибку `ALREADY_INITIALIZED`, не изменяя данные.

Создание приложения выполняется под общей блокировкой. До записи приложения и доски
сохраняется долговечное намерение в `boards/.pending-applications/<applicationId>.json`.
Оно содержит продуктовую запись в дисковом формате, включая Markdown-массивы и квитанцию.
Это служебный каталог, а не пользовательская доска.

Перед следующей операцией под блокировкой ядро восстанавливает недостающие части,
проверяет совпадение уже опубликованного приложения и удаляет завершённое намерение.
При несовместимых данных восстановление останавливается с ошибкой; существующие данные
не перезаписываются. Каталог намерений нельзя очищать как временный кеш.

Общий `storage migrate` переносит доски и задачи. Доска приложения удаляется его предметным
каскадом; отдельного пользовательского удаления системной доски или смены slug нет.

## Чтение REST

Префикс: `/api/v1/projects/:project/boards`; в local также `/api/v1/boards`.

| Метод | Путь     | Результат                                          |
| ----- | -------- | -------------------------------------------------- |
| GET   | `/`      | Каталог: `items`, `total`, `nextOffset`, `version` |
| GET   | `/:slug` | Метаданные одной доски и её отображаемое `name`    |

Конверт: `{ok:true,data:...}`. Каталог принимает `offset` (по умолчанию 0), `limit`
(по умолчанию 50, диапазон 1–100), необязательную `version` первой страницы.
`nextOffset: null` означает конец. Если переданная версия изменилась, ответ —
409 `BOARD_CHANGED`; чтение начинается заново. Порядок: продукт, приложения по дате
создания доски с ID как вторичным ключом, инфраструктура.

Неизвестная доска — 404 `NOT_FOUND`, некорректные аргументы — 400 `VALIDATION_ERROR`,
повреждённое хранилище — 500. При создании приложения занятый slug — 409 `ALREADY_EXISTS`,
смена существующего slug — 409 `IMMUTABLE_FIELD`. Создание выполняется существующей
операцией продукта с обязательным `fields.slug`; отдельного POST досок нет.

SDK генерируется из OpenAPI. SSE сообщает об изменениях каталога и приложений;
наблюдение за файлами дополняется периодической сверкой.
