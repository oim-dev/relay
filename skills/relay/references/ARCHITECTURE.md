# Архитектура Relay

Core — главный пакет всей предметной логики Relay. Приложения предоставляют
интерфейсы к этой логике, а не независимые варианты правил проекта.
Эта страница задаёт общие границы; внутреннее устройство и команды разработки
принадлежат README и документации соответствующих приложений и пакетов.

## Пути обращения к данным

```text
Человек → Web → REST SDK ───────────────────────────────┐
Агент → MCP → project-runtime / HTTP → REST SDK ────────┤
Агент → CLI → project-runtime / HTTP → REST SDK ────────┤
                                                      ↓
                                      Server / server-runtime → Core → хранение
Агент → CLI → project-runtime / local ──────────────────────────→ Core → хранение
```

CLI может работать напрямую с Core в локальном режиме либо через REST.
MCP обращается к отдельно запущенному Relay Server; Web также работает через сервер.
Разные пути доступа не означают разные предметные модели или отдельные копии данных.

## Владельцы ответственности

- [Core](https://github.com/oim-dev/relay/blob/main/packages/core/README.md) — предметные операции, правила сущностей
  и отношений, согласованность изменений, чтение контекста и работа с хранением.
- [Contracts](https://github.com/oim-dev/relay/blob/main/packages/contracts/README.md) — переносимые схемы, типы и общие
  определения данных без зависимости от Core, Node.js, NestJS или React.
  Схемы не заменяют предметные операции Core.
- [REST SDK](https://github.com/oim-dev/relay/blob/main/packages/rest-sdk/README.md) — технический клиент HTTP API,
  генерируемый из OpenAPI сервера. Не владеет предметными правилами.
- [Project runtime](https://github.com/oim-dev/relay/blob/main/packages/project-runtime/README.md) — общая конфигурация
  и подключение CLI/MCP, разрешение проекта, адаптеры локального Core и HTTP.
- [Server runtime](https://github.com/oim-dev/relay/blob/main/packages/server-runtime/README.md) — общая реализация REST,
  OpenAPI и SSE: транспорт, контекст запроса и проекта, доставка событий изменений,
  вызов Core.
- [Server](https://github.com/oim-dev/relay/blob/main/apps/server/README.md) — самостоятельная точка запуска сервера,
  параметры процесса и поставка Web.
- [Web](https://github.com/oim-dev/relay/blob/main/apps/web/README.md) — человеческий интерфейс: навигация, редакторы,
  представление данных и состояние взаимодействия.
- [CLI](https://github.com/oim-dev/relay/blob/main/apps/cli/README.md) — терминальный интерфейс: команды, аргументы,
  человеческое и машинное представление результата.
- [MCP](https://github.com/oim-dev/relay/blob/main/apps/mcp/README.md) — агентский протокол: обнаружение инструментов,
  аргументы и преобразование вызовов в операции серверного клиента.

Contracts задаёт общий язык данных, Core — их предметное поведение. Валидация
входного формата на границе приложения не переносит туда владение бизнес-правилом.
Наличие общей схемы также не означает, что каждый интерфейс уже предоставляет
все описанные ею действия: это отражает [матрица возможностей](CAPABILITIES.md).

## Хранение и изменения

Хранение обеспечивает сохранение проектных записей и отношений между запусками.
Core владеет предметной интерпретацией этих данных и правилами их изменения;
клиенты не должны обходить операции Core прямым редактированием файлов.
Физическая организация хранилища и внутренние механизмы записи описываются у Core,
а общий наблюдаемый контракт — в [предметной документации](domain/README.md).

Сервер выбирает контекст нужного проекта и передаёт действие в Core. События
изменений позволяют клиентам обновлять представление; доставка события не является
отдельной реализацией предметной операции и не подтверждает внешнюю проверку результата.

## Что остаётся вне Core

В приложениях остаётся специфичная для интерфейса логика: маршрутизация и черновики
Web, разбор команд и вывод CLI, MCP-протокол, запуск процессов и параметры окружения.
Runtime-пакеты разделяют технический код между приложениями без импорта исходников
одного приложения другим. Общие предметные правила при этом принадлежат Core.

Инструменты разработки, профили команды и сборка пользовательского скилла
не образуют дополнительный предметный слой Relay. Их устройство описывается
локально, отдельно от контрактов пользовательских данных.
