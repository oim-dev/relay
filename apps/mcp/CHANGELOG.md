# История изменений Relay MCP

## 0.9.2

- Сохранена компактная форма `product_overview` при расширении серверного обзора:
  инструмент явно возвращает только `productId`, `version`, `items` и `readiness`,
  без нового среза проекта. Показатели оператора и их детализация доступны в Web и CLI,
  но не добавлены в MCP.
- Имена инструментов, аргументы и транспорты MCP относительно `0.9.1` не изменены.
  Для работы с обновлённым HTTP-обзором нужен Relay Server той же версии;
  обновите и перезапустите сервер вместе с MCP.
- Совместный выпуск с `@oim-dev/relay-cli@0.9.2` и `@oim-dev/relay-server@0.9.2`.

## 0.9.1

- Совместный patch-выпуск с `@oim-dev/relay-cli@0.9.1` и `@oim-dev/relay-server@0.9.1`
  сопровождает обновление отдельного пользовательского скилла Relay.
- Инструменты, аргументы и транспорты MCP относительно 0.9.0 не изменены.

## 0.9.0

- Совместный выпуск с `@oim-dev/relay-cli@0.9.0` и `@oim-dev/relay-server@0.9.0`:
  версия MCP согласована с остальными пакетами комплекта.
- Инструменты, аргументы и транспорты MCP относительно 0.8.0 не изменены.
  Перестройка команд CLI не переименовывает MCP-инструменты; для предметных вызовов
  по-прежнему нужен отдельно запущенный Relay Server.
- Установочная проверка комплекта адаптирована к новому CLI и сохраняет сценарий
  доступа MCP к задачам workspace, проверки обязательного выбора проекта и ошибки
  после остановки Server. Новых возможностей MCP этот выпуск не добавляет.

Подключение и инструменты описаны в
[справочнике MCP](https://github.com/oim-dev/relay/blob/main/apps/mcp/docs/MCP.md).

## 0.8.0

- Добавлен транспорт `--transport stdio`: агентский клиент запускает MCP-процесс
  и обменивается сообщениями через stdin/stdout без отдельного слушающего порта.
- Stdio использует тот же набор инструментов и HTTP-доступ к Relay Server. Discovery
  доступен до запуска API; предметные вызовы требуют работающего Server. MCP не запускает
  API автоматически и не переключается на локальную базу при его недоступности.
- EOF stdin и сигналы завершения закрывают транспорт и ресурсы процесса;
  stdout stdio-процесса содержит только сообщения MCP.
- Подготовлены проектные конфигурации и инструкции подключения Claude Code, Codex
  и OpenCode с проверкой инструментов после настройки клиента.
- Запуск без `--transport` сохраняет совместимый HTTP-режим; его также можно выбрать
  явно через `--transport http`.
- Совместный выпуск с `@oim-dev/relay-cli@0.8.0` и `@oim-dev/relay-server@0.8.0`.

## 0.7.0

### Инструменты и действия агента

- Удалены инструменты общего аудита `entity_history`, `task_history_list`
  и `task_history_get`. Пользовательские обсуждения доступны через `task_comments_list`,
  `task_comment_get` и `task_comment_publish`; полный Markdown читается адресно.
- Инструкции сервера и описания инструментов записи уточняют: `requestId` — только
  корреляция, не дедупликация и не ключ сохранённого ответа. HTTP-мутации не повторяются
  автоматически после сбоя. При потере ответа агент должен перечитать текущее состояние
  и согласовать дальнейшее действие, а не повторять запись вслепую или подставлять
  свежую ревизию в прежнее тело запроса.
- Повторная публикация комментария, в том числе с тем же `requestId`, может создать
  дубликат: сначала прочитайте обсуждение. Результат планирования или релиза — текущее
  состояние, а не история операций.

### Совместимость с сервером

- Используйте MCP, Server и CLI согласованной версии `0.7.0`. База сервера переходит
  на формат 4 (оболочки записей версии 3): текущие данные и комментарии, без общего
  аудита, `events`/`planningEvents`, `receipts`/`requests` и сохранённых результатов команд.
- До явного переноса поддерживаемых legacy-баз и форматов 1/2/3 через локальный CLI
  `storage migrate` остановите старые процессы записи, сохраните резервную копию
  и обновите используемые клиенты. ID, алиасы, ревизии, связи и полные пользовательские
  комментарии сохраняются; история и квитанции удаляются необратимо.
- Откат требует старой базы из резервной копии и соответствующей версии пакетов;
  автоматического downgrade нет. После миграции проверьте базу через CLI `validate`
  и перечитайте данные через обновлённые инструменты.
- Проверки CI выполняются на Node.js 24; `engines` не изменён, заявленная
  runtime-поддержка Node.js 22 этим изменением не отменяется.

## 0.6.2

- Подготовка совместного выпуска `@oim-dev/relay-mcp@0.6.2`,
  `@oim-dev/relay-server@0.6.2` и `@oim-dev/relay-cli@0.6.2`:
  один GitHub Release `v0.6.2`, стабильная версия без prerelease-суффикса, npm-канал `latest`.
- Для выпуска предусмотрена автоматизированная поставка: событие GitHub Release
  `published` запускает проверки комплекта, затем проверенные npm-архивы передаются
  как артефакты для публикации через npm Trusted Publishing (OIDC).
  Push и PR запускают только проверки, без npm-публикации.
- Runtime MCP не менялся: выпуск согласует версию с CLI и Server и улучшает проверку
  поставки всего комплекта.

Это описание подготовки выпуска, а не подтверждение публикации `0.6.2` или успешного
OIDC-запуска. Совместная версия продолжает правило комплекта `0.6.1`; ручной способ
публикации в разделе `0.6.1` относится к тому историческому выпуску.

## 0.6.1

- Подготовка первого npm-выпуска `@oim-dev/relay-mcp@0.6.1` в согласованном комплекте
  с `@oim-dev/relay-server@0.6.1` и `@oim-dev/relay-cli@0.6.1`.
- Для этого выпуска предусмотрена ручная публикация проверенного самодостаточного

После публикации проверить доступную справку можно командой:

```bash
npx @oim-dev/relay-mcp@0.6.1 --help
```

  Для этого выпуска используйте `@gromlab/relay-server@0.6.0` и `@gromlab/relay-cli@0.6.0`.
