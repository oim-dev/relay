# Справочник Relay MCP

Relay MCP — агентский интерфейс к знаниям и работе проекта: продукту, документам,
задачам, планам, релизам и связям. Этот справочник описывает подключение и все
98 зарегистрированных инструментов, включая динамические семейства сущностей.
Он предназначен для использования без чтения исходников. Установленная версия
может отличаться: сверяйте её discovery перед вызовом.

## Подключение

### Первый запуск

Из корня пользовательского проекта установите скилл и выберите своего агента:

```bash
npx skills add oim-dev/relay
```

Затем выполните [инициализацию и запуск Relay Server](../../../docs/guides/GETTING_STARTED.md).
Основной агентский маршрут — CLI через npx. Только если пользователь запросил MCP,
подготовьте [проектный конфиг клиента](CLIENTS.md), запускающий процесс:

```bash
npx @oim-dev/relay-mcp --transport stdio --server-url http://127.0.0.1:4700
```

Команду запускает клиент, не агент вручную. В stdio stdout занят протоколом,
порт MCP не используется; discovery доступен до запуска API, вызовы требуют Server.
После перезапуска клиента проверьте чтение проекта. Нужны Node.js 22+ и npm.
Совместимый отдельный HTTP-режим (без `--transport` или с `--transport http`) доступен по адресу
`http://127.0.0.1:4710/mcp`, Relay Server — `http://127.0.0.1:4700`.
В MCP-клиенте задайте транспорт **Streamable HTTP** и URL MCP; синтаксис настройки
зависит от клиента. Это не stdio и не URL REST API. После подключения обновите
discovery и вызовите:

```text
projects_list({})
boards_list({})
```

В local второй вызов читает доски единственного проекта. В workspace сначала
выберите регистрацию из первого ответа, например:

```text
boards_list({ project: "alpha" })
board_task_get({ project: "alpha", reference: "PRODUCT-1" })
```

Используйте реально полученный ключ задачи. Проверьте не только наличие инструмента,
но и доступность полного Markdown из `structuredContent` в своём клиенте.
Краткая текстовая карточка может не содержать полных данных.

### Параметры процесса

`--transport http|stdio` выбирает транспорт; default — `http` для совместимости.
В stdio `--port` не используется, а выбор отладочного формата не добавляет сообщений в stdout:
канал принадлежит MCP. EOF stdin, SIGINT и SIGTERM закрывают процесс клиента.

| Параметр             | Назначение и приоритет                                                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--config <path>`    | Конфигурация: флаг → `RELAY_CONFIG` → поиск вверх от текущего каталога. В одном каталоге `relay.workspace.json` имеет приоритет перед `.relay/config.json`. |
| `--server-url <url>` | Адрес Server: флаг → `RELAY_SERVER_URL` → конфигурация. Явный URL позволяет remote-only запуск без локального конфига.                                      |
| `--port <number>`    | Порт MCP: флаг → `RELAY_MCP_PORT` → `mcp.port` → `4710`; диапазон 0–65535, `0` выбирает свободный порт.                                                     |
| `--format <format>`  | `text` по умолчанию: сообщение запуска в stderr. `json`: `{ok:true,data:{url,pid}}` в stdout. Это сообщение CLI, не ответ MCP-инструмента.                  |
| `-h`, `--help`       | Справка установленной команды.                                                                                                                              |
| `-V`, `--version`    | Версия установленного MCP.                                                                                                                                  |

При явном URL Server локальный конфиг не читается, поэтому его `mcp.port`
тоже не применяется: остаются явный порт, переменная окружения или 4710.
Для нестандартного подключения достаточно, например,
`npx @oim-dev/relay-mcp --server-url http://127.0.0.1:4800`.
Полный контракт — [конфигурация project-runtime](../../../packages/project-runtime/docs/CONFIGURATION.md).

MCP всегда работает через общий HTTP Backend и REST SDK. Режим `local` относится
к контексту Server, не означает прямой доступ MCP к Core. Реестр читается с Server
при вызовах и обновляется без перезапуска MCP. Недоступность Server — ошибка,
а не пустая база или переключение на локальную копию.

Сервис слушает только `127.0.0.1`. `/mcp` принимает POST для `initialize`,
`tools/list`, `tools/call`; GET и DELETE возвращают 405, другой путь — 404.
Host разрешён только для `127.0.0.1`/`localhost` с фактическим портом;
переданный Origin должен соответствовать одному из этих HTTP-адресов, иначе 403.
Транспорт stateless, отдельный для каждого запроса. Не требуется MCP session ID.
Остановка через `Ctrl+C`/SIGTERM завершает активные операции; чужие процессы
останавливать не нужно. Запущенный MCP не подключает себя к агентскому клиенту.

## Общие аргументы и результат

### Обозначения справочника

В таблицах `?` означает необязательный аргумент, `=значение` — значение при пропуске.
Без `?` аргумент обязателен. Объекты передаются JSON, не JSON-строками.
Неизвестные поля строгая схема отклоняет. Все параметры находятся на верхнем уровне,
кроме явно перечисленных объектов, массивов и совместимого `product_save.command`.

**Каждый проектный инструмент** принимает дополнительно:

| Аргумент    | Значение                                                                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `project?`  | Ключ регистрации или ID из `projects_list`. В workspace обязателен даже при одной регистрации; в local может опускаться. Выбор действует только на текущий вызов. |
| `maxBytes?` | Целое число байт от 1024 до 134217728 (1 КиБ–128 МиБ); без него используется `output.maxBytes` выбранного проекта (стандартное значение 16384 байта).             |

Исключения реестра: `projects_list` принимает `maxBytes`, но запрещает `project`;
`project_register` и `project_unregister` не принимают `maxBytes`.

**W** в таблицах записи означает обязательные `actor` и `requestId`:

- `actor` — своё непустое однострочное имя, до 128 символов и 512 байт UTF-8.
  Автор не наследуется от другого клиента; это атрибуция, не аутентификация.
- `requestId` — строка 1–128 символов, начинается с буквы/цифры, далее допустимы
  латинские буквы, цифры, `.`, `_`, `:`, `-`. Например `agent-docs-001`.
  Это **только корреляция**, не ключ дедупликации.
- **R** означает W плюс `ref` и `ifRevision`: адрес записи и ревизия из её чтения.
  Для `entity_*` ревизия целая ≥0; для задач досок, планов, релизов и прямого
  изменения реализации — целая ≥1. Дополнительные требования продукта описаны ниже.

`ref`/`reference` — строка ключа, алиаса, ID или уточнённого `kind:ID`, до 257 символов;
ссылки разрешаются только внутри выбранного проекта. Объект `{kind,id}` передаётся
лишь там, где он явно предусмотрен, например `relations[].target` или `scope[]`.
Новый `key` — до 128 символов формата `^[A-Z][A-Z0-9]*(?:-[A-Z0-9]+)*$`.

Заголовки — одна строка; `summary` — обычный многострочный текст;
полные `description`, `body`, цели, итоги и условия — Markdown строкой.
Не превращайте Markdown в массив строк: это ответственность хранения.

### Безопасная запись

1. Объясните намерение, выберите проект, прочитайте запись и её текущую ревизию.
2. Вызовите одно предметное действие со своим автором и необходимой ревизией/версией.
3. Проверьте результат и перечитайте содержание; для изменения отношений проверьте
   также сохранённые связи. Второй запрос «синхронизации графа» не нужен.

Ответ записи может содержать ID, ключ, действие, ревизию и `requestId`, но постоянной
квитанции нет. После потери ответа сначала перечитайте состояние; для публикации —
сообщения задачи. Не повторяйте создание вслепую и не подставляйте свежую ревизию
в старое тело. Повтор — новое исполнение; создание/публикация могут дать дубликат,
изменение со старой ревизией — конфликт. Записи имеют `idempotentHint:false`,
`readOnlyHint:false`, `destructiveHint:true`; чтения — обратные значения,
`openWorldHint:false` у всех. Аннотации не заменяют согласования действия.

Частичные `entity_*_update`, `board_task_update`, `plan_update`,
`plan_stage_update`, `task_criterion_update` сохраняют пропущенные поля.
`product_*_save` и `release_update` требуют полного содержания: не переносите
на них семантику patch. Пустой массив явно меняет состав; `null` допустим
только в указанных полях.

### Ответ, страницы и бюджет

Успех: `structuredContent = {ok:true,data,meta?}`. `content` содержит либо тот же JSON,
либо краткий текст результата. Ошибка: `{ok:false,error:{code,message,details?}}`
и `isError:true`; пустой список остаётся успехом, не ошибкой.
`meta` проектного ответа содержит выбранный `project` и серверный `configPath`.

Бюджет считается по **всему сериализованному MCP-ответу**, включая оба представления.
Превышение даёт `RESPONSE_TOO_LARGE` с `requiredBytes` и `maxBytes`, не обрезанный
успешный результат. Для списков уменьшайте `limit`, для адресного текста или
полного контекста увеличивайте `maxBytes`. Если слишком большим оказался ответ
записи, это не доказывает, что запись не выполнена: сначала перечитайте состояние.

Обозначение **P(n)**: `offset?=0` (целое ≥0), `limit?=n` (1–100),
`version?` — строка версии первой страницы. Для продолжения используйте
`offset: nextOffset` и возвращённую `version`, сохраняя проект и фильтры.
`nextOffset:null` завершает чтение; конфликт версии требует начать с первой страницы.
Итоги относятся ко всей выборке, не только к видимым строкам.

Исключения:

- `projects_list`: `limit?=20`, `cursor?` до 4096 символов;
  продолжение в `meta.nextCursor`, `meta.hasMore`, `meta.total`.
  Бюджет по умолчанию 16384 байта; страница может уменьшиться для размещения в нём.
- `task_comments_list`: курсорная лента, см. раздел комментариев.
- `product_list`, `product_entities`: `offset?=0`, `limit?=30` (1–100),
  ответ содержит `version`, но вход **не принимает version**. Между страницами
  нет гарантии единого снимка; перед записью перечитайте выбранную запись.
- `product_lint`: offset/limit без версии.
- `entity_context`: нет offset/limit/depth, только полный ответ либо ошибка бюджета.

## Проекты

| Инструмент           | Аргументы сверх общих                                             | Результат / действие                                                                                                                                                               |
| -------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `projects_list`      | `limit?=20`, `cursor?`; `project` запрещён                        | Актуальный режим local/workspace, регистрации, пути и подключения; область всего Server.                                                                                           |
| `project_register`   | `project`, `path?`, `config?`, `replace?=false`; без W и maxBytes | Подключить существующий проект в workspace. `path` относителен к реестру **на Server**, `config` — к path; это не инициализация базы. `replace:true` разрешает замену регистрации. |
| `project_unregister` | `project`; без W и maxBytes                                       | Удалить регистрацию workspace, сохранив данные проекта.                                                                                                                            |
| `project_config`     | Нет                                                               | Полные настройки и пути выбранного проекта, включая storagePath.                                                                                                                   |
| `project_validate`   | Нет                                                               | Проверить целостность продукта, досок, задач и связей; не исправляет данные и не подтверждает выполнение требований.                                                               |

`project` регистрации — имя длиной 1–64 символа: первая буква/цифра Unicode,
затем буквы, цифры, `_`, `-`; не имя продукта и не slug приложения.
Для регистрации нужен хотя бы один непустой `path` или `config`.
Бюджет ответа register/unregister фиксирован: 16384 байта. В реестровых действиях нет actor/requestId
во входе, несмотря на общее предупреждение discovery для записей. Настройки имени
проекта и разделов меняются через `entity_project_update`; slug проекта MCP не меняет.

## Общие операции сущностей

Каталог содержит 11 видов: `project`, `product`, `feature`, `scenario`, `application`,
`implementation`, `board`, `task`, `document`, `work-plan`, `release`.
Этап плана, критерий и комментарий — вложенные записи, не новые виды.

### Чтение и адресация

| Инструмент          | Аргументы сверх общих | Результат                                                                                                                 |
| ------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `entity_types`      | P(40)                 | Назначение видов, действия и поддерживаемые фильтры.                                                                      |
| `entity_type_get`   | `kind` из 11 видов    | Поля, схемы создания/изменения и правила ключей; null-схема не обещает generic-действия.                                  |
| `entities_list`     | P(40) и фильтры ниже  | Краткие карточки, для документов также свойства библиотеки и её счётчики.                                                 |
| `entity_get`        | `ref`, `kind?`        | Полные типизированные `data`, ревизия, ключ и прямые предметные ссылки. Текстовая карточка не заменяет structuredContent. |
| `entity_resolve`    | `ref`, `kind?`        | Постоянный адрес и текущий ключ по ID/ключу/алиасу.                                                                       |
| `entity_keys`       | `ref`, `kind?`, P(40) | Текущий ключ и прежние алиасы, не история содержания.                                                                     |
| `entity_key_spaces` | `kind`, P(40)         | Области нумерации, префиксы и доски выбранного вида.                                                                      |
| `entity_context`    | `ref`                 | Все узлы и сохранённые рёбра достижимой компоненты в обоих направлениях, включая циклы; успех всегда `complete:true`.     |

Все фильтры `entities_list` необязательны:

| Поле                                                              | Значение                                                                                                                |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `kind`                                                            | Один из 11 видов.                                                                                                       |
| `q`                                                               | Поиск, до 4096 символов; для библиотеки также поиск содержания.                                                         |
| `refs`                                                            | До 100 строк адресов для краткого адресного чтения.                                                                     |
| `board`, `application`, `feature`, `scenario`, `target`, `parent` | Ключи или ID соответствующих областей. `target` — явная цель; `parent` — родитель задачи. Применимость зависит от вида. |
| `status`                                                          | Предметное состояние, строка до 128 символов. Для документа: draft/active/archived.                                     |
| `active`                                                          | Строка `"true"` или `"false"`, активность реализации.                                                                   |
| `section`                                                         | ID раздела до 64 символов; `none` — без раздела.                                                                        |
| `documentKind`                                                    | Один из семи типов документа, перечисленных ниже.                                                                       |
| `pinned`, `archived`                                              | Строки `"true"`/`"false"`, не boolean; только закреплённые/незакреплённые, только архив/исключить архив.                |
| `sort`                                                            | `key` (по умолчанию), `title`, `updated`.                                                                               |

Полный `entity_context` не имеет `depth`, `offset`, `limit` и не выдаёт частичный
граф. При `RESPONSE_TOO_LARGE` увеличьте maxBytes. Содержание найденных записей
читайте через entity_get и предметные get; контекст не создаёт отношений.
`product_context` — отдельная предметная подборка, не обход этого графа.

### Создание

Каждый инструмент принимает W. Название вида уже в имени, поле `kind` передавать не нужно.

| Инструмент                     | Содержательные аргументы                                                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `entity_product_create`        | `name`, `summary`, `description` — заполнить паспорт единственного продукта.                                                                                 |
| `entity_feature_create`        | `name`, `summary`, `description`.                                                                                                                            |
| `entity_scenario_create`       | `featureId` (ключ/ID фичи), `name`, `description`; поля summary нет.                                                                                         |
| `entity_application_create`    | `name`, `summary`, `description`, `slug`, `type`, `prefix?`.                                                                                                 |
| `entity_implementation_create` | `application` (ключ/ID приложения), `target` (ключ/ID фичи или сценария), `title`, `description`, `status?=none`.                                            |
| `entity_task_create`           | `board` (ключ/ID), `title?=""`, `description?=""`, `targets?=[]`, `dependencies?=[]`, `related?=[]`, `parent?=null`, `column?=inbox`, `acceptanceCriteria?`. |
| `entity_document_create`       | `name`, `summary`, `body`, `documentKind`, `targets?=[]`, `sectionId?`, `documentStatus?`, `pinned?`, `relations?`.                                          |

Общие поля продукта и приложения: name/title до 1024 байт UTF-8, непустая строка;
summary до 4096 байт (может быть пустым); description/body — непустой Markdown
до 256 КиБ. `type`: `frontend`, `backend`, `internal`. `slug` приложения —
неизменяемый адрес до 64 символов, `prefix` — префикс задач; при пропуске выводится
из slug. Точный допустимый формат приведён в разделе продукта.
`status`: `none`, `partial`, `done` — совместимые метаданные, не ручная установка
вычисляемой готовности.

Для generic-задачи массивы targets/dependencies/related содержат до 100 строк
ключей/ID каждый. `targets` — фичи, сценарии или реализации по правилам доски;
`parent` — адрес родителя или null. Схема `acceptanceCriteria[]` и колонки описаны
в разделе задач. Операция сохраняет выбранные предметные связи вместе с записью.

## Документы и разделы

Поля ниже используются в entity_document_create/update и product_document_save.
Общие правила прикрепления — [документы](../../../docs/domain/DOCUMENTS.md).

| Поле                      | Формат и смысл                                                                                                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `documentKind`            | `specification` — ТЗ; `description` — описание; `rules` — правила; `instruction` — инструкция; `proposal` — предложение; `decision` — принятое решение; `research` — исследование. |
| `documentStatus?`         | `draft`, `active`, `archived`; независим от типа и не подтверждает истинность текста.                                                                                              |
| `sectionId?`              | ID раздела либо null (без раздела).                                                                                                                                                |
| `pinned?`                 | Boolean, закрепление для всех участников.                                                                                                                                          |
| `relations?`              | До 100 объектов `{target:{kind,id},type,description}`. Все поля объекта обязательны во входной схеме: для отсутствующего пояснения передайте `description:""`.                     |
| `relations[].target.kind` | Любой из 11 основных видов, не этап/критерий/комментарий.                                                                                                                          |
| `relations[].target.id`   | Постоянный ID, не читаемый ключ, до 128 символов формата `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`.                                                                                     |
| `relations[].type`        | `references` — материал для чтения сущностью; `documents` — документ описывает сущность.                                                                                           |
| `relations[].description` | Пояснение Markdown до 16 КиБ, может быть пустым.                                                                                                                                   |
| `targets`                 | Только generic-инструменты: до 100 строк ключей/ID продуктовых областей. `[]` снимает эти области.                                                                                 |
| `links`                   | Только продуктовый ввод: обязательный массив до 1000 типизированных продуктовых областей, формат ниже. Для отсутствия областей передайте `[]`.                                     |

При отсутствии метаданных чтение трактует состояние как active, закрепление как false,
раздел как null. Для создания с другой семантикой задайте их явно; при частичном
update пропущенные метаданные сохраняются.

`links[]` допускает `{kind:"product"}`, `{kind:"feature",id}`,
`{kind:"scenario",id}`, `{kind:"application",id}`,
`{kind:"implementation",applicationId,id}`. В этих полях продуктового ввода
принимаются ключи или ID. `targets`/`links` — совместимые продуктовые области;
`relations` — адресные отношения ко всем видам. Не считайте замену одного поля
неявной очисткой другого. Для полного снятия учитывайте обе прочитанные формы.

Для управления разделами сначала `entity_get({ref:"PROJECT"})`, затем
`entity_project_update` с R и полным `documentSections`:
массив до 100 объектов `{id,name}` в нужном порядке. ID уникальны, формат
`^[a-zA-Z0-9_-]{1,64}$`; name — непустая строка до 80 байт UTF-8.
Добавление объекта создаёт раздел, изменение name при том же ID переименовывает,
порядок массива задаёт порядок разделов, исключение объекта удаляет раздел.
Документы удалённого раздела не удаляются и отображаются без раздела.
`documentSections:[]` очищает перечень. Это не действие settings и не удаление документов.

Пример создания документа в выбранном workspace-проекте:

```text
entity_document_create({
  project: "alpha", actor: "agent", requestId: "agent-docs-001",
  name: "Правила проверки", summary: "Когда и как проверять результат",
  body: "## Проверка\n\nСохранить команду, результат и ограничения проверки.",
  documentKind: "instruction", documentStatus: "active",
  targets: [], relations: []
})
```

Из ответа возьмите ref/ID и ревизию, прочитайте полный документ. Чтобы изменить
только закрепление у реально прочитанного `DOC-1` с ревизией 1:

```text
entity_document_update({
  project: "alpha", ref: "DOC-1", ifRevision: 1,
  actor: "agent", requestId: "agent-docs-002", pinned: true
})
```

Примеры не предназначены для безусловного повторения. ID, ключи и ревизии заменяйте
результатами чтения своей базы. Прикрепления требуют существующих допустимых целей;
ссылка в Markdown не создаёт отношение.

### Полное сохранение записей

Общие аргументы **S**: W, `action` (`create`/`update`), `id?`, `key?`,
`ifRevision?` (целое ≥0), `ifVersion?` (строка версии продукта).
При update нужны id и прочитанная ifRevision, даже если discovery обозначает
их optional для единой схемы create/update. ifVersion берите из product_overview
или предметного контекста, когда нужна защита версии. key — явная смена адреса,
а не новая идентичность. Для большинства новых записей ключ выдаёт Core.

| Инструмент                 | Аргументы кроме S и общих                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `product_passport_save`    | `name`, `summary`, `description`.                                                                             |
| `product_feature_save`     | `name`, `summary`, `description`.                                                                             |
| `product_scenario_save`    | `featureId`, `name`, `description`; featureId — ключ/ID, принадлежность существующего сценария не меняется.   |
| `product_application_save` | `name`, `summary`, `description`, `slug`, `type`, `prefix?`; при update не меняйте прочитанные slug/prefix.   |
| `product_document_save`    | `name`, `summary`, `body`, `documentKind`, `links`, `sectionId?`, `documentStatus?`, `pinned?`, `relations?`. |

Формат текстов и полей документа описан выше. `slug`: до 64 символов,
строчные латинские буквы/цифры с одиночными дефисами между группами;
`product`, `infrastructure`, `new` зарезервированы.
`prefix`: 2–16 заглавных латинских букв/цифр, первая буква.
`type`: frontend/backend/internal. Эти save-инструменты заменяют содержательные
поля: для точечного изменения используйте generic update, а не неполное тело save.

### Реализации и состав приложения

| Инструмент                      | Аргументы сверх общих                                                                           | Действие                                                                                                                                                 |
| ------------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `product_scope_replace`         | W, `applicationId`, `contracts`, `ifRevision`, `ifVersion`                                      | Полная замена активного состава приложения. ifRevision=0 при первом сохранении состава, иначе его прочитанная ревизия; ifVersion обязательна и непустая. |
| `product_contract_update`       | W, `applicationId`, `contractId`, `status`, `title?`, `description?`, `ifRevision`, `ifVersion` | Изменить один контракт, сохраняя остальные. Ревизия относится к составу; версия — ко всему продукту.                                                     |
| `product_implementation_update` | R, `title?`, `description?`, `status?`, `key?`                                                  | Частичное изменение реализации по её собственной ревизии, не ревизии состава.                                                                            |

В scope/contract applicationId, contractId, featureId, scenarioId принимают ключи/ID.
`contracts` — до 10000 объектов:

```text
{ featureId, scenarioId, title, description, status, key?, revision? }
```

featureId обязателен; scenarioId обязателен и равен null для FI либо адресу сценария
для SI. title/description — непустые тексты реализации, status обязателен:
none/partial/done. key/revision — прочитанные ключ и положительная ревизия реализации;
замена состава не переименовывает ключи и защищается общей версией продукта.
`contracts:[]` снимает активное участие, сохраняя адреса; не удаляет реализации.
SI требует FI той же фичи. Передайте весь желаемый состав, не только добавляемый элемент.
Правила участия — [продукт](../../../docs/domain/PRODUCT.md).
Совместимый status не переопределяет вычисляемую готовность, даже если описание
инструмента говорит о подтверждении требований.

### Совместимый универсальный ввод

`product_save` принимает общий selector, обязательные `actor` и `command`.
Предпочитайте именованные инструменты выше. Полная схема command:

```text
{ action, id?, key?, fields, ifRevision?, ifVersion?, requestId, actor? }
```

action/id/key/ревизии имеют смысл S. Автор операции задаётся **внешним actor**,
а не вложенным совместимым command.actor. `fields` — объект одного варианта:

| `fields.kind`    | Остальные поля                                                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `passport`       | name, summary, description — как product_passport_save.                                                                             |
| `feature`        | name, summary, description — как product_feature_save.                                                                              |
| `scenario`       | featureId, name, description — как product_scenario_save.                                                                           |
| `application`    | name, summary, description, slug, type, prefix? — как product_application_save.                                                     |
| `document`       | name, summary, body, documentKind, links, sectionId?, documentStatus?, pinned?, relations? — как product_document_save.             |
| `scope`          | applicationId, contracts — как product_scope_replace; требуются ifRevision и ifVersion команды.                                     |
| `contract`       | applicationId, contractId, status, title?, description? — как product_contract_update; требуются ревизия состава и версия продукта. |
| `implementation` | applicationId, featureId, scenarioId (null для FI), title, description, status — добавить одну реализацию без замены остальных.     |

Для command.fields.kind=scope/contract адрес состава определяется по applicationId,
поэтому отдельный command.id при update не обязателен. contract требует action=update;
implementation — action=create. Для изменения существующей реализации используйте
product_implementation_update или entity_implementation_update.

После смысловых записей перечитайте их, при необходимости выполните product_lint.
Предупреждение lint не является запретом Core и не подтверждает полноту требований.

Колонки: `inbox`, `ready`, `in-progress`, `review`, `done`, `cancelled`.
Блокировка вычисляется, отдельной колонки blocked нет. Работа над задачей не требует
плана или вызова plan_start. Условия завершения и допустимые цели досок —
[контракт задач](../../../docs/domain/TASKS.md).

| Инструмент         | Аргументы сверх общих             | Результат                                                                    |
| ------------------ | --------------------------------- | ---------------------------------------------------------------------------- |
| `boards_list`      | P(50)                             | Доски с именами, slug и префиксами.                                          |
| `board_tasks_list` | P(40), фильтры ниже               | Краткие задачи без полного Markdown, блокеры и готовность.                   |
| `board_task_get`   | `reference`                       | Полный Markdown задачи, ID, ключ, ревизия, блокеры.                          |
| `board_task_links` | `reference`, P(40), те же фильтры | Зависимости, обратные blocks, parent/child и related с текущими состояниями. |

Фильтры списков задач/связей (все optional):
`parentId` — прямые дети ключа/ID; `productTarget` — ключ/ID продуктовой цели
до 128 символов, задачи полного состава; `board` — slug/префикс/ID до 128 символов;
`column` — колонка; `completion` — unfinished (без done/cancelled) или finished
(только done/cancelled); `searchIn` — title (ключ/ID/заголовок) или all
(также Markdown, по умолчанию); `q` — до 1024 символов;
`readiness` — blocked или ready (колонка ready без блокеров).

| Инструмент          | Аргументы сверх общих                                                                                                                                               | Действие                                                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `board_task_create` | W, `board`, `title?=""`, `description?=""`, `productLinks?`, `parentId?`, `dependencies?`, `related?`, `column?=inbox`, `acceptanceCriteria?`, `includeTask?=false` | Создать задачу; ключ выдаётся автоматически. includeTask возвращает также первоначальную карточку в текущем ответе, не сохраняет её для повтора. |
| `board_task_update` | W, `reference`, `ifRevision`, `title?`, `description?`, `productLinks?`                                                                                             | Частичная правка; productLinks заменяет весь набор, [] очищает.                                                                                  |
| `board_task_move`   | W, `reference`, `ifRevision`, `column`, `board?`, `beforeId?=null`, `ifVersion?`                                                                                    | Колонка, порядок или доска; beforeId — ключ/ID следующей задачи, null — конец полной колонки, ifVersion защищает порядок списка.                 |
| `board_task_link`   | W, `reference`, `ifRevision`, `target`, `relation`, `remove?=false`                                                                                                 | Установить/снять depends-on, related или parent. target — другая задача выбранного проекта.                                                      |

title до 1024 байт и description до 256 КиБ могут быть пустыми.
`parentId`, элементы dependencies/related — ключи или ID; массивы создания до 100.
`productLinks` — до 100 объектов `{kind,id}`, kind = feature/scenario/implementation,
id — ключ/ID до 128 символов. Для общей продуктовой доски выбирают фичи/сценарии,
для доски приложения — реализации этого приложения; инфраструктурная доска без целей.
Цели необязательны, искусственная фича ради технической задачи не нужна.

`acceptanceCriteria` — до 100 объектов `{title,summary?="",description?=""}`.
Это первоначальные невыполненные критерии, не ID существующих критериев.
Название критерия непустое, до 1024 байт, summary до 4096 байт, description до 64 КиБ.
При переносе доски меняется ключ, но не ID; несовместимые цели снимите явно заранее.
`relation:"parent"` назначает target родителем текущей задачи, не наоборот.

Критерии изменяются по ревизии задачи; в done сначала верните задачу в работу.

Её результат содержит commentId и revision ленты (последовательный номер),
которую нельзя использовать как ifRevision задачи.

У комментария title — непустая строка до 1024 байт; description — непустой Markdown
до 256 КиБ; actorRole = `operator`, `orchestrator`, `worker`.
entryId — строковый номер формата `^[1-9]\d{0,14}$`, возможны пропуски.
cursor — непрозрачная строка до 2048 символов, after — целое ≥0:
для новых сообщений после снимка используйте его snapshot как after.
actor фильтрует точное имя; action допускает только `comment-publish`.
Продолжайте чтение до nextCursor:null с теми же фильтрами.
Повтор публикации создаёт новое сообщение. Редактирования/удаления комментария нет.

## Планы и этапы

Все записи планирования требуют W; изменение плана, его этапов или состава —
его положительной ifRevision. Этап имеет внутренний `stage` ID, не вид phase
и не самостоятельный корень контекста. Правила — [планирование](../../../docs/domain/PLANNING.md).

### Чтение

| Инструмент              | Аргументы сверх общих                                             | Результат                                                                                 |
| ----------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `plans_list`            | P(12), `q?` до 1024 символов, `status?`                           | Планы, полные показатели и счётчики состояний; status = draft/active/completed/cancelled. |
| `plan_get`              | `ref`                                                             | Полные реквизиты, цель и итог, ревизия и показатели; этапы отдельно.                      |
| `plan_stages_list`      | `ref`, P(12)                                                      | Этапы в предметном порядке, показатели, planRevision.                                     |
| `plan_tasks_list`       | `ref`, `stage`, P(12)                                             | Текущие задачи этапа; полное описание через board_task_get.                               |
| `task_plan_memberships` | `ref` задачи, P(12)                                               | Участие задачи в текущих и закрытых планах, признак current; не журнал перемещений.       |
| `plan_task_candidates`  | P(12), `q?`, `board?`, `plan?`, `stage?`, `availableOnly?="true"` | Поиск задач и их текущая принадлежность.                                                  |

У candidates q до 1024 символов; board — ключ/slug/ID; plan — ключ/ID;
stage — внутренний ID и требует plan; availableOnly — строка `"true"`/`"false"`.
По умолчанию возвращаются свободные задачи и текущий состав выбранного этапа.

### Поля и запись

**F** — поля плана: `title` (непустая строка до 160 байт), `summary?=""`
(обычный текст до 16 КиБ), `goal?=""`, `rationale?=""`, `boundaries?=""`,
`expectedResult?=""` (Markdown до 256 КиБ каждый), `scope?=[]`, `participants?=[]`.
scope — до 100 объектов `{kind,id}`; kind = project/product/application/feature/scenario/implementation,
id — постоянный ID, не ключ. participants — до 100 строк авторов, не права доступа.

**E** — поля этапа: `title` (до 160 байт, непустой), `summary?=""` (до 16 КиБ),
`outcome?=""`, `completionConditions?=""` (Markdown до 256 КиБ каждый).
Условия завершения — текст, не исполняемая формула.

| Инструмент           | Аргументы сверх общих                                                              | Действие                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `plan_create`        | W, F                                                                               | Создать draft, без автоматического начала задач.                                                                 |
| `plan_update`        | R, любое из F, все поля F optional без defaults                                    | Частичная правка; пустые строки очищают тексты кроме title, [] очищает scope/participants.                       |
| `plan_start`         | R                                                                                  | Явно начать draft с целью и непустым составом. Не требуется для выполнения задач или завершения плана.           |
| `plan_complete`      | R, `result`                                                                        | Завершить draft/active с непустым итогом Markdown до 256 КиБ; Core проверяет полный непустой выполненный состав. |
| `plan_cancel`        | R, `result`                                                                        | Отменить с непустой причиной Markdown до 256 КиБ, сохранив задачи.                                               |
| `plan_stage_create`  | R, E                                                                               | Создать этап внутри плана.                                                                                       |
| `plan_stage_update`  | R, `stage`, любое из E, все поля E optional без defaults                           | Хотя бы одно содержательное поле; title не обязателен, пустая строка очищает остальные тексты.                   |
| `plan_stage_remove`  | R, `stage`                                                                         | Удалить только пустой этап; задачи сначала исключаются явно.                                                     |
| `plan_stage_move`    | R, `stage`, `before`                                                               | before — внутренний ID следующего этапа либо null для конца полного списка; direction в MCP не принимается.      |
| `plan_tasks_include` | R, `stage`, `tasks`                                                                | Включить до 2000 строк ключей/ID задач, остальные включения сохраняются.                                         |
| `plan_tasks_exclude` | R, `stage`, `tasks`                                                                | Явно исключить до 2000 задач, не удаляя сами задачи.                                                             |
| `plan_task_transfer` | R исходного плана, `task`, `targetPlan`, `targetStage`, `targetRevision`, `reason` | Перенос между этапами/планами с ревизиями обеих сторон одной операцией.                                          |

В transfer task/targetPlan — ключи или ID, targetStage — внутренний ID,
targetRevision — положительная ревизия целевого плана, reason — непустой Markdown
до 16 КиБ. Ответ даёт новую revision и при переносе targetRevision, при работе
с этапом — stageId. Все stage ID имеют формат `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`.

У задачи одно текущее включение среди draft/active; закрытая принадлежность не мешает
новому текущему включению. Родитель не включает детей автоматически. Включение
не меняет колонку, доску и описание задачи. Закрытые планы неизменяемы; открытия
и удаления плана нет. Максимум 200 этапов в плане, до 2000 задач в каждом.

## Релизы

Текущий релиз — **проектная запись с planIds, без applicationId**.
Назначить приложение нельзя. Принятая целевая принадлежность приложению и её отличие
от текущего действия описаны в [контракте релизов](../../../docs/domain/RELEASES.md).
Основной рабочий путь — сформировать выпуск из выполненных планов; текущий интерфейс
также позволяет заранее сохранить planned с незавершёнными планами.

| Инструмент           | Аргументы сверх общих                   | Результат / действие                                                                              |
| -------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `releases_list`      | P(12), `q?` до 1024 символов, `status?` | Каталог и полные счётчики; status = planned/released/cancelled.                                   |
| `release_get`        | `ref`                                   | Полные реквизиты, текущая готовность, releasedAt/releasedBy.                                      |
| `release_plans_list` | `ref`, P(12)                            | Текущие планы состава и готовность, не архивный снимок.                                           |
| `release_preview`    | `plans`, P(12)                          | Готовность до сохранения; до 200 ключей/ID планов, [] допустим для пустого выбора. Только чтение. |
| `release_create`     | W, поля выпуска ниже, `status?=planned` | Создать релиз; released сразу проверяет готовность и фиксирует выпуск.                            |
| `release_update`     | R, поля выпуска ниже, `status`          | Заменить полные реквизиты и состав, явно задать состояние. Это не частичный patch.                |
| `release_plan`       | R                                       | Явно перепланировать отменённый релиз.                                                            |
| `release_cancel`     | R                                       | Отменить planned, сохранив планы и задачи.                                                        |
| `release_publish`    | R                                       | Зафиксировать выпуск, автора и дату после проверки всего состава.                                 |

Поля выпуска: `title` (непустой, до 160 байт), `version` (непустое пользовательское
обозначение до 80 байт, **не ревизия и не версия страницы**), `summary?=""`
(до 16 КиБ), `description?=""` (Markdown до 256 КиБ), `planIds`
(1–200 уникальных постоянных ID планов, не ключи), `plannedFor?=""`
(дата YYYY-MM-DD либо пустая строка). В update пропуск summary/description/plannedFor
применяет пустое значение: передавайте прочитанное полное содержание.

Для выпуска нужны планы со статусом completed и фактически готовым составом.
Выпущенный релиз неизменяем; выпуск не запускает CI/CD и не доказывает внешнюю
поставку. Готовность может измениться после выпуска, released при этом сохраняется.
Отмену релиза не следует смешивать с отменой его планов.

| Инструмент                | Аргументы сверх общих | Область                                                        |
| ------------------------- | --------------------- | -------------------------------------------------------------- |

| `implementation_progress` | `ref`, P(20)          | Реализация и её собственная работа.                            |
| `scenario_progress`       | `ref`, P(20)          | Сценарий и реализации.                                         |
| `feature_progress`        | `ref`, P(20)          | Фича и обязательные составляющие.                              |
| `application_progress`    | `ref`, P(20)          | Приложение; продуктовая работа и все задачи доски различаются. |
| `product_progress`        | P(20); без ref        | Продукт и страница фич.                                        |

следуйте offset/version и адресам причин. Колонка done, сохранённое completed,
вычисляемое completed и released имеют разный смысл. Прогресс не записывает
историю и не подтверждает внешние проверки. Формулы и пустые обязательства —

## Ошибки и границы интерфейса

| Ситуация                                | Что делать                                                                                                                                                       |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Не подключается HTTP-клиент             | Проверить работающий Server, URL MCP с /mcp, порт, транспорт Streamable HTTP и Host/Origin. Успех процесса не равен discovery.                                   |
| Discovery не содержит инструмента       | Проверить установленную версию, обновить процесс и переподключить клиент. Не вызывать выдуманное имя.                                                            |
| `PROJECT_REQUIRED`, `PROJECT_NOT_FOUND` | Вызвать projects_list и выбрать существующую регистрацию; не подставлять соседний проект.                                                                        |
| Ошибка аргументов                       | Сверить required/optional, ключи/ID, вложенные поля и строковые true/false фильтров. Не добавлять неизвестные поля.                                              |
| Конфликт ревизии/версии                 | Сохранить намерение, перечитать запись/страницу, согласовать изменения. Не присваивать старому телу свежую ревизию.                                              |
| `RESPONSE_TOO_LARGE`                    | Уменьшить страницу или увеличить maxBytes до допустимого предела. Контекст нельзя сокращать depth/limit. После ошибки ответа записи сначала проверить состояние. |
| Потеря ответа на запись                 | Прочитать текущее содержание, отношения или комментарии; затем решить, нужно ли новое действие. Автоповтора и сохранённой квитанции нет.                         |
| Пустой список                           | Успешная пустая выборка в данной области, не доказательство отсутствия данных в других страницах/проектах.                                                       |
| Краткий текст скрывает содержание       | Проверить structuredContent в клиенте; discovery и серверный JSON сами по себе не доказывают, что агент получил полный Markdown.                                 |

MCP **не предоставляет** инициализацию базы, миграцию, reindex, reconcile-relations,
предпросмотр/каскадное удаление сущностей, ограниченный постраничный диагностический
граф, запись/изменение/удаление произвольных рёбер или пакет графовых операций.
Наличие этих операций в Core/REST не создаёт MCP-инструментов. Снятие targets/relations,
удаление критерия, пустого этапа или регистрации — другие действия, не удаление сущности.
Нет самостоятельного создания/удаления доски, удаления/возобновления плана,
удаления/отзыва выпущенного релиза, редактирования/удаления комментария,
автоматического аудита, истории команд и исторического снимка состава релиза.

Для доступных альтернатив используйте [матрицу возможностей](../../../docs/CAPABILITIES.md),
[восстановление](../../../docs/guides/RECOVERY.md) и
[HTTP API](../../../packages/server-runtime/docs/API.md). Не обходите отсутствующую
предметную операцию диагностическим ребром или прямой правкой файлов.
