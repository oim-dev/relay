# Работа в MCP

Инструкция для любого исполнителя и QA в `apps/mcp`; общие правила —
[корневой AGENTS.md](../../AGENTS.md). Здесь агентский интерфейс и его процесс,
не предметная логика. Изменения других владельцев согласуйте с оркестратором.

## Перед изменением

- Прочитайте [README](README.md), контракт инструмента в [MCP](docs/MCP.md)
  и [DEVELOPMENT](docs/DEVELOPMENT.md) до изменения регистрации/обработчика.
- Если контекст неизвестен, начните с [PRODUCT](../../docs/PRODUCT.md) и
  [ARCHITECTURE](../../docs/ARCHITECTURE.md); далее читайте только нужную
  [возможность](../../docs/CAPABILITIES.md) и [предметный контракт](../../docs/domain/README.md).
  Все общие документы читать не требуется.
- Подключение принадлежит [CONFIGURATION](../../packages/project-runtime/docs/CONFIGURATION.md),
  транспорт — [REST API](../../packages/server-runtime/docs/API.md), переносимые схемы —
  [Contracts](../../packages/contracts/docs/API.md). Гарантии и актуальные версии
  хранения берите из [STORAGE](../../docs/domain/STORAGE.md), не старых профилей.

## Инструменты и транспорт

- MCP вызывает общий HTTP Backend отдельно запущенного Server: без открытия базы,
  автозапуска API, local fallback и копирования бизнес-логики Core.
- Используйте общие регистрацию, выбор проекта и output. Проект/автор принадлежат
  вызову; одно предметное действие согласует данные и связи внутри Core.
- Discovery должен понятно описывать назначение и каждый публичный аргумент
  по-русски, включая вложенные свойства, варианты и элементы массивов.
  Сверяйте input/output, optional/default/null и annotations с реальным контрактом.
- Чтение предоставляет полное содержание; краткая карточка его не заменяет.
  Согласуйте `content` и `structuredContent`, бюджет всего ответа и продолжение страниц.
  Полный контекст не сокращайте до успешного частичного результата.
- Не делайте автоматический retry мутаций и не обещайте replay по `requestId`.
  Потеря ответа требует чтения состояния, конфликт — согласования ввода.
- При API-клиенте/codegen-логике загрузите `rest-api-codegen-ru` через skill tool;
  generated SDK не правьте. Настроенный URL Server отличается от источника OpenAPI.
  Другие внешние инструменты применяйте по задаче, не по названию приложения.

## Проверка и знания

- Выбирайте проверки из DEVELOPMENT: `pnpm --filter @oim-dev/relay-mcp run typecheck`,
  `pnpm run test:mcp` либо адресный discovery. Собственного lint нет.
- Полный `tools/list` включает динамические регистрации; in-memory discovery
  доказывает metadata, но не HTTP или выполнение действия. Корректный structuredContent
  не доказывает доступность полного текста в целевом клиенте: это отдельная проверка
  после обновления процесса и переподключения, включая отображение вызова.
- Следуйте [DOCUMENTATION](../../docs/DOCUMENTATION.md), обновляйте индекс MCP.md.
  Для Markdown достаточно адресных проверок; всю систему запускать не требуется.
