# Маршруты и навигация Web

Карта описывает адреса, зарегистрированные в
[app-router.tsx](../src/app/router/app-router.tsx), и канонизацию экранов.
Это справочник URL, не реестр готовности: ограничения сценариев — в [USAGE](USAGE.md),
покрытие интерфейсов — в [общей матрице](../../../docs/CAPABILITIES.md).

## Проектная область

Ниже `P` означает `/projects/:project`; `:project` — текущий slug проекта.
Идентичность запросов задаёт постоянный ID, не slug. Ссылки на сущности относятся
только к выбранному проекту; совпадение ключей не объединяет разные базы.

- `/` в local переходит в единственный проект; непроектный путь получает проектный префикс.
- `/` в workspace предлагает выбор проекта, а не молчаливую запись в первый доступный.
- ID и ключ регистрации проекта разрешаются в канонический slug с сохранением суффикса,
  query, hash и `location.state` через replace. Старый slug не является постоянным алиасом.
- Недоступный или неизвестный проект не переключает пользователя на другую базу.

## Карта канонических URL

Параметры `feature`, `scenario`, `application`, `implementation` ниже обозначают
разрешённый адрес соответствующей записи; продуктовые экраны используют её
канонический ключ, если он предоставлен, либо ID.

| URL                                                                        | Экран / действие                                          |
| -------------------------------------------------------------------------- | --------------------------------------------------------- |
| `P`                                                                        | «Обзор»: срез проекта и переходы в разделы                |
| `P/settings`                                                               | «Настройки проекта»: имя, slug, постоянный ID             |
| `P/product/passport`                                                       | Паспорт продукта                                          |
| `P/product/passport/edit`                                                  | Редактор паспорта                                         |
| `P/product/features`                                                       | Каталог фич                                               |
| `P/product/features/new`                                                   | Новая фича                                                |
| `P/product/features/:feature`                                              | Фича и её сценарии                                        |
| `P/product/features/:feature/edit`                                         | Редактор фичи                                             |
| `P/product/features/:feature/scenarios/new`                                | Новый сценарий этой фичи                                  |
| `P/product/features/:feature/scenarios/:scenario`                          | Сценарий                                                  |
| `P/product/features/:feature/scenarios/:scenario/edit`                     | Редактор сценария                                         |
| `P/product/applications`                                                   | Каталог приложений                                        |
| `P/product/applications/new`                                               | Новое приложение                                          |
| `P/product/applications/:application`                                      | Приложение и его реализации                               |
| `P/product/applications/:application/edit`                                 | Редактор приложения                                       |
| `P/product/applications/:application/scope`                                | Состав приложения                                         |
| `P/product/applications/:application/implementations/:implementation`      | Реализация фичи или сценария                              |
| `P/product/applications/:application/implementations/:implementation/edit` | Редактор вклада активной реализации                       |
| `P/documents`                                                              | «Библиотека знаний»                                       |
| `P/documents/new`                                                          | Новый документ                                            |
| `P/documents/:documentId`                                                  | Документ и прикрепления                                   |
| `P/documents/:documentId/edit`                                             | Редактор документа                                        |
| `P/boards/:boardSlug`                                                      | Канбан продуктовой, инфраструктурной или прикладной доски |
| `P/boards/:boardSlug/:taskId`                                              | Центральное окно задачи над доской                        |
| `P/plans` / `P/plans/:planId`                                              | Каталог / план с этапами и материалами                    |
| `P/releases` / `P/releases/:releaseId`                                     | Каталог / релиз с текущими планами                        |
| `P/relations`                                                              | Браузер связей и диагностические действия                 |
| `P/relations/context`                                                      | «Контекст сущности»: дерево, граф, список                 |
| `P/infrastructure`                                                         | Будущий раздел инфраструктуры: пока «В разработке»        |

Создание и изменение плана/релиза открывается в UI каталога или карточки,
отдельных `/plans/new`, `/releases/new` и `/edit` роутер не объявляет.
Этап не имеет собственной страницы. Наличие старого компонента с адресом `/product/work`
в исходниках не делает этот URL зарегистрированным маршрутом.
Неизвестный путь внутри проекта показывает «Страница не найдена».

«Обзор» (`P`, крошка «Обзор») не использует query-параметров и открывается прямой ссылкой,
reload и Back/Forward без предшествующей истории. Его переходы ведут на канонические адреса:
`P/product/passport` или `P/product/passport/edit` при отсутствии паспорта,
`P/product/features`, `P/boards/product` и `P/boards/:boardSlug`,
`P/boards/:boardSlug/:taskId` для задач раздела «Требует внимания», `P/plans` и
`P/plans/:planId`, `P/releases` и `P/releases/:releaseId`, `P/documents`,
`P/documents/:documentId` и `P/documents?view=pinned`.

## Совместимость и канонизация

- `P/product` → `P/product/passport`.
- `P/product/documents/*` → `P/documents/*`, включая создание и редактирование.
- `P/boards` → `P/boards/product`.
- `P/tasks/:id` → `P/boards/:actualBoardSlug/:taskId` после чтения задачи.
  Читаемый ключ и старый адрес доски также уточняются по фактической записи;
  перенос задачи не меняет её постоянный ID.
- `P/boards/:boardSlug?task=:ref` открывает канонический путь задачи;
  служебные `task` и `column` удаляются, прочие query и hash сохраняются.
  `task=new` не является командой создания: используйте «Создать задачу».
- `P/product/scenarios/:ref` → вложенная страница сценария своей фичи.
- `P/product/implementations/:ref` и её `/edit` → вложенный адрес приложения.
  Несоответствие родителя в уже вложенном адресе показывает ошибку принадлежности.

Канонизирующие переходы продукта и задачи сохраняют query, hash и состояние навигации.
Преобразование старого `?task=` отдельно формирует фон доски, поэтому не обещает
переноса произвольного прежнего `location.state`.

## Query-параметры

| Страница                  | Поддерживаемые параметры                                                                  |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| Доска                     | `q` — поиск; `blocked=1` — «С блокерами»; `cancelled=1` — показать отменённые             |
| Каталог фич               | `q`, `status`, `app` — поиск, готовность и приложение                                     |
| Приложение                | Повторяемый `open` — раскрытые фичи; якорь `#application-features` для возврата к составу |
| Состав приложения         | `feature`, `scenario` — начальный выбор цели                                              |
| Библиотека                | `q`, `kind`, `target`, `section`, `view`, `sort`, `offset`, `version`                     |
| Новый документ            | `target` — начальное прикрепление; `section` — начальный раздел                           |
| Каталоги планов и релизов | `q`, `status`, `limit` — поиск, состояние и показанный объём                              |
| План                      | `tab=stages` — «Этапы и задачи»; `tab=overview` — «Материалы»                             |
| Связи                     | `root` — адрес корня; `view=chain` — цепочка, иначе прямые связи; `depth` для цепочки     |
| Визуальный контекст       | `root`, `mode=tree\|graph\|list`, `depth`, `direction=both\|incoming\|outgoing`, `type`   |

Библиотечный `view` принимает `all`, `draft`, `pinned`, `none`, `archived`;
`sort` — `updated` или `title`. Размер страницы — 40. Смена фильтра сбрасывает
`offset/version`, «Далее» передаёт версию полученного списка. По умолчанию архив скрыт.
`kind` выбирается из семи типов, перечисленных в [USAGE](USAGE.md#библиотека-знаний).

У диаграммы глубина нормализуется в диапазон 1–100, по умолчанию 1;
у цепочки — 2–100, по умолчанию 3. `mode=diagram` совместим с `graph`;
неизвестный режим открывает дерево. Query отображения не расширяет гарантии полноты API.

## Возвраты, крошки и прямые ссылки

`returnTo` и `editorReturnTo` — поля `location.state`, не query-параметры.
Они сохраняют контекст перехода и путь от редактора к просмотру; helper принимает
возврат только внутри переданной проектной или продуктовой базы. Без state применяется
адрес родителя/каталога: скопированная ссылка не должна требовать предшествующей истории.

Открытие задачи с доски сохраняет фон и фильтры. Закрытие использует Back, если переход
был создан с таким контекстом; прямой URL возвращает к фактической доске задачи.
Это не вложенная самостоятельная страница с собственными крошками в окне задачи.

Крошки принадлежат общему виджету и метаданным роутера. Внутренние Markdown-ссылки
обрабатывает RelayMarkdownLink через React Router, без перезапуска SPA.
Продуктовый layout восстанавливает прокрутку по pathname + search с областью ID проекта.
Не переносите эту гарантию автоматически на любой каталог: например, «Все планы»
и «Все релизы» ведут к базовому каталогу, а не восстанавливают все прежние фильтры.
