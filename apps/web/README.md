# Relay Web

Браузерный интерфейс рабочей памяти проекта Relay. Здесь человек читает требования
и основания решений, редактирует знания и задачи, следит за планами и релизами.
Web работает с [Relay Server](../server/README.md) и общими с [CLI](../cli/README.md)
и [MCP](../mcp/README.md) данными. Собранный интерфейс входит в дистрибутив Server;
отдельный Vite-сервер нужен только для разработки.

В режиме local открывается один проект, в workspace доступен выбор независимых проектов.
Страницы имеют адреса `/projects/:project`, где `:project` — slug проекта.

## Возможности

- **Продукт:** паспорт, возможности (фичи), сценарии, приложения и их реализации.
- **Доски и задачи:** канбан, поиск, фильтры, создание и перенос задач, критерии приёмки,
  зависимости и обсуждения. Задача открывается центральным окном над доской
  по постоянному адресу `/projects/:project/boards/:boardSlug/:taskId`.
- **Библиотека знаний:** серверный поиск документов, разделы, черновики, закреплённые
  материалы и архив; чтение и редактирование Markdown, связи с сущностями проекта.
- **Планы:** цели, вложенные этапы и выбранные задачи. **Релизы:** версия, статус выпуска
  и актуальный состав из планов. Оба раздела используют постоянные серверные данные.
- **Связи проекта:** исследование отношений и визуальный контекст в режимах
  «Дерево», «Граф» и «Список».
- **Настройки:** имя и slug проекта. Доступны светлая и тёмная темы, мобильная навигация.

Уведомления об изменениях других клиентов поступают через SSE, данные перечитываются с сервера.
Черновики редакторов разделены по проекту и вкладке; ошибки сохранения оставляют ввод,
а конфликты требуют явного решения пользователя.

`requestId` служит корреляции HTTP-запроса, а не дедупликации. Web не повторяет мутации
автоматически. При потере ответа нужно перечитать текущее состояние перед новой отправкой:
операция могла выполниться. Для комментария повторная публикация требует явного подтверждения
проверки обсуждения; черновик при этом сохраняется. Клиентского журнала запросов нет;
старые данные браузера автоматически не удаляются.

### Ограничения

«Обзор» и «Инфраструктура» пока показывают «В разработке».
Журнал истории изменений не ведётся; обсуждения задач содержат пользовательские комментарии.
Диаграмма контекста предназначена для просмотра, не для создания или переподключения связей.
Для работы с данными нужен Relay Server. Проекты workspace добавляются через конфигурацию
или CLI, а не через Web.

## Запуск для разработки

Используйте Node.js 24 и pnpm 11.18.0, закреплённый в корневом `package.json`.
Команды выполняются из корня репозитория:

```bash
pnpm install --frozen-lockfile
pnpm run dev
```

Откройте `http://127.0.0.1:5173`. По умолчанию `dev` и `dev:server` используют
workspace `apps/playground/relay.workspace.json`: изменения в интерфейсе затрагивают
подключённые к нему проекты. Для своего существующего проекта задайте конфигурацию:

```bash
RELAY_CONFIG=/absolute/path/to/project/.relay/config.json pnpm run dev
```

Для workspace укажите путь к `relay.workspace.json`. Сервер и Web также можно запускать
в отдельных терминалах: `pnpm run dev:server` и `pnpm run dev:web`.
Команда `dev:web` сама API не запускает.

Переменные окружения:

- `RELAY_CONFIG` — конфигурация проекта или workspace для сервера.
- `RELAY_PORT` — порт сервера, переопределяющий порт из конфигурации.
- `RELAY_API_URL` — адрес API для Vite-прокси; по умолчанию `http://127.0.0.1:4700`.
- `RELAY_WEB_PORT` — порт Web; по умолчанию `5173`. Занятый порт вызывает ошибку запуска.

Vite проксирует `/api` на `RELAY_API_URL`. При изменении порта сервера укажите
соответствующий адрес API; при раздельном запуске передайте `RELAY_WEB_PORT` также серверу.

## Разработка и проверки

Стек: React, TypeScript, Vite, Mantine, React Router, SWR, dnd-kit, Markdown/CodeMirror,
React Flow и ELK. Запросы проходят через общий [REST SDK](../../packages/rest-sdk/README.md).
Компоненты создаются по [инструкции локальных шаблонов](.templates/README.md).

```bash
pnpm run lint:web
pnpm run typecheck:web
pnpm run build:web
```

Корневые команды собирают необходимые зависимости через Turbo; результат сборки —
`apps/web/dist`. Браузерные сценарии проверяются через agent-browser на временных данных
в отдельной headless-сессии. Справка: `pnpm --filter @relay/web run browser --help`.
Автотесты фронтенда не добавляются; сборка не заменяет проверку интерфейса.
