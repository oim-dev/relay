# Работа в CLI

Для любого исполнителя и QA в `apps/cli` действуют [общие правила](../../AGENTS.md).
Здесь владелец команд, ввода, help и представления; изменения Core/Backend/SDK
согласуйте с оркестратором, не реализуйте недостающий предметный сценарий в CLI.

## До изменения

- Прочитайте [README](README.md), нужную команду в [CLI](docs/CLI.md) и
  [EXTENDING](docs/EXTENDING.md); представление — [TERMINAL](docs/TERMINAL.md),
  поставка — [RELEASING](docs/RELEASING.md). Контракт читается до реализации.
- Если продукт и границы неизвестны, прочитайте [PRODUCT](../../docs/PRODUCT.md)
  и [ARCHITECTURE](../../docs/ARCHITECTURE.md); далее только затронутую
  [возможность](../../docs/CAPABILITIES.md) и [domain-контракт](../../docs/domain/README.md),
  не все общие документы.
- Подключение сверяйте с [CONFIGURATION](../../packages/project-runtime/docs/CONFIGURATION.md),
  HTTP — с [API](../../packages/server-runtime/docs/API.md). Актуальные гарантии
  сохранения и версии — в [STORAGE](../../docs/domain/STORAGE.md), не старых профилях.

## Правила команды

- Используйте общую регистрацию, Backend и Result. Предметное действие и отношения
  согласует Core; не добавляйте клиентский второй запрос графа или файловый обход HTTP.
- Разрабатывайте собственное human-представление и стабильный JSON отдельно.
  Не заменяйте human универсальным обходом DTO; не печатайте ad-hoc stdout из обработчика.
  Текст всегда без цветного ANSI; `--color` отсутствует. TTY, NO_COLOR и FORCE_COLOR
  не включают ANSI-оформление. JSON без ANSI/баннеров; пользовательские управляющие
  последовательности не исполняются в терминале. Сохраняйте Markdown, отступы,
  карточки и таблицы; ширина терминала продолжает учитываться.
- CLI не ограничивает вывод байтовым бюджетом и не предоставляет `--max-bytes`.
  Лимиты ввода, Core, HTTP и MCP сохраняются. Полное описание не усекайте;
  большие вложенные коллекции выносите в отдельные списки.
- Списки используют `--limit`/`--cursor` и единый `Result.page`: общий footer в text,
  `meta.page` в JSON. Курсор привязан к команде, ref, фильтрам, проекту и транспорту;
  сохраняйте исходную версию, различайте snapshot и live. Snapshot guard offset-страниц
  проверяет неизменность текущего состояния, не предоставляет исторический снимок.
- Text — формат по умолчанию независимо от config format; JSON включается явно
  через `--format json`. Подсказки начинаются с `npx @oim-dev/relay-cli`, сохраняют
  config/project/server/local и не получают жёстких переносов строк.
- Update передаёт только явно предоставленные поля. Текстовые поля используют общие
  средства command-kit: `--field` либо `--field-file <path|->`, без конфликта
  источников и не более одного потребителя stdin. Прочитайте ввод до мутации.
- Help с русскими аргументами и примерами должен работать без открытия проекта.
  Полный Markdown не нормализуйте и не превращайте в дисковый массив строк.
- Не добавляйте скрытых повторов запросов. После потери ответа перечитайте состояние;
  конфликт не исправляется подстановкой свежей ревизии к старому телу.
- При API-клиенте/codegen-логике загрузите `rest-api-codegen-ru` через skill tool.
  Generated SDK не правьте; пользовательский URL не является источником генерации.
  Внешние инструменты выбирайте по применимости, HTTP-ошибка не разрешает local fallback.

## Проверки

- Выберите сценарии EXTENDING и адресные тесты; доступны
  `pnpm --filter @oim-dev/relay-cli run typecheck` и `pnpm run test:cli`.
  Учитывайте требуемую тестами сборку; собственного lint нет.
- По изменению проверяйте human/JSON, help, Unicode/pipe, страницы и полноту вывода,
  local/HTTP и ошибки. Сборка не доказывает читаемость или сохранённые отношения.
- Следуйте [DOCUMENTATION](../../docs/DOCUMENTATION.md); синтаксис храните в CLI.md,
  не в новом реестре. Markdown проверяйте адресно без обязательной сборки репозитория.
