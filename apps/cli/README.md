# Relay CLI

`@oim-dev/relay-cli` — интерфейс памяти проекта Relay прежде всего для агентов,
также для человека в терминале. Читает знания, задачи, планы и связи, сохраняет
предметные изменения через Core или необязательный HTTP-сервер. Требуется Node.js 22+.

Первый запуск для агента: установите Relay skill по руководству, затем подготовьте проект.
Подробности — [начало работы](https://github.com/oim-dev/relay/blob/main/docs/guides/GETTING_STARTED.md).

```bash
npx skills add oim-dev/relay
npx @oim-dev/relay-cli init
```

Далее агент сохраняет и уточняет знания проекта, а затем создаёт задачи на их основе.
Skill — подготовка агентского сценария, не runtime-зависимость CLI: обычное чтение
и ручное обслуживание доступны без него. Например, проверить чтение списка можно так:

```bash
npx @oim-dev/relay-cli task list
```

Запускайте команды через npx без глобальной установки. `--help` работает без проекта.
Агент читает обычный человекочитаемый вывод: пользователь видит команды, знания и результаты.
Формат по умолчанию — `text`, настройка format
в конфиге на него не влияет. JSON выбирается только явно: `--format json`.
Справочник описывает текущее дерево исходников; синтаксис установленной версии
проверяйте через `npx @oim-dev/relay-cli --help`.

Общие правила интерфейса:

- Текст всегда без цветного ANSI, параметра `--color` нет. TTY, `NO_COLOR` и
  `FORCE_COLOR` не включают ANSI-оформление. Markdown, отступы, карточки и таблицы
  сохраняются; представление учитывает ширину терминала и обезвреживает управляющие символы.
- Результат — карточка, страница списка, квитанция действия, прогресс или ошибка.
  `get` показывает полное описание; большие связанные коллекции читаются отдельными списками.
- Списки принимают `--limit` и `--cursor`. Подсказка продолжения сохраняет контекст
  подключения и фильтры; в JSON сведения о странице находятся в `meta.page`.
  Snapshot guard проверяет неизменность текущих данных, не открывает исторический снимок.
- Update изменяет только переданные поля. Текстовое поле передаётся через `--field`
  либо `--field-file <path|->`; `-` означает stdin. Имена доступных полей задаёт команда.
  Два источника одного поля и несколько потребителей stdin недопустимы.
- Байтового ограничения вывода CLI и `--max-bytes` нет. Лимиты ввода, Core и
  транспорта продолжают действовать; успешное чтение не должно скрытно усекать содержание.

`init` создаёт `.relay/config.json` и хранилище в текущем проекте. Конфиг ищется
вверх от рабочего каталога. Для уже настроенного workspace нужен выбранный проект;
сервер с Web запускается отдельно пакетом `@oim-dev/relay-server`.

```bash
npx @oim-dev/relay-cli a task list
npx @oim-dev/relay-cli task get PRODUCT-1 \
  --server-url http://127.0.0.1:4700 \
  --project a
```

Автор предметной записи — `--actor` или `RELAY_ACTOR`; обновление требует прочитанной
ревизии. После потери ответа сначала прочитайте состояние: `requestId` — корреляция,
не гарантия безопасного повтора. Скрытых повторов нет, конфликт нельзя исправлять
автоматической подстановкой свежей ревизии к старым полям. После записи перечитайте
карточку и проверьте содержание и отношения. Для обычного локального проекта `--local` и
`--config` не нужны; они полезны для обслуживания или выбора нестандартной базы.
