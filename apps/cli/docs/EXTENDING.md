# Разработка и расширение Relay CLI

Руководство для разработчика команд, ввода и представления CLI. Пользовательский
синтаксис поддерживается в [CLI.md](CLI.md), оформление — в [TERMINAL.md](TERMINAL.md).
Исходники находятся в [репозитории Relay](https://github.com/oim-dev/relay/tree/main/apps/cli),
не в обязательном составе npm-пакета. Все команды разработки ниже выполняются
из корня checkout, если явно не указано иное.

## Граница приложения

CLI разбирает аргументы, подключает backend, вызывает предметное действие и
представляет результат. CLI не владеет хранением и предметными инвариантами.
Общие правила находятся в [domain](https://github.com/oim-dev/relay/blob/main/docs/domain/README.md),
границы компонентов — в [архитектуре](https://github.com/oim-dev/relay/blob/main/docs/ARCHITECTURE.md).
Backend прямого Core и HTTP должен давать одинаковый предметный результат.

Новая возможность требует сначала определить пользователя (агент/человек), цель,
вход, наблюдаемый результат и владельца действия. Отделяйте ошибки разбора,
подключения, предметной операции и представления. Изменение text не должно менять
JSON или аргументы. Наличие метода SDK не означает готовности команды.

## Запуск и проверки

Для checkout требуются Node.js 22.13+ и pnpm 11.18.0+ согласно корневому manifest,
а также установленные зависимости workspace. `apps/cli/package.json` содержит
скрипты build/dev/typecheck/test/docs:check/package:check; отдельного lint-скрипта нет.

```bash
pnpm run build:cli
pnpm --filter @oim-dev/relay-cli run typecheck
pnpm run test:cli
pnpm --silent run dev:cli task list --help
```

Собранный вход — `apps/cli/dist/cli/main.js`, установленная команда — `relay-cli`.
`apps/cli/scripts/dev.mjs` сохраняет каталог вызывающего процесса через `INIT_CWD`:
при сценарии с данными это влияет на поиск конфигурации. `--silent` убирает
служебный вывод pnpm из JSON, но не меняет формат CLI; его задавайте явно.

Тестовый helper `apps/cli/test/helpers/cli.ts` по умолчанию запускает собранный
бинарник. Перед адресным тестом нужна актуальная сборка:

```bash
pnpm run build:cli
pnpm --filter @oim-dev/relay-cli exec node --import tsx --test test/cli-ux.test.ts test/presentation.test.ts
```

`RELAY_CLI_TEST_SOURCE=1` выбирает исходник, но требует TypeScript-загрузчика также
в дочернем процессе; один флаг не заменяет подготовку окружения. Проверяйте сценарии
на отдельной тестовой базе, не на рабочей памяти пользователя.

## Маршрут команды в коде

| Участок                                  | Ответственность                                                      |
| ---------------------------------------- | -------------------------------------------------------------------- |
| `src/main.ts`, `src/run.ts`              | Запуск, проектный префикс, ошибки Commander, exit code, EPIPE        |
| `src/program.ts`                         | Дерево команд и глобальные параметры                                 |
| `src/command.ts`                         | CommandDefinition, registerCommand, группы и общая справка           |
| `src/context.ts`                         | Runtime, подключение Backend, автор, параметры вывода, печать Result |
| `src/commands/`                          | Предметные адаптеры CLI                                              |
| `src/backend/connect.ts`                 | Выбор подключения через project-runtime                              |
| `src/input.ts`, `src/text-input.ts`      | Общие средства чтения ввода                                          |
| `src/presentation/`                      | Представления конкретных семейств                                    |
| `src/queries/result.ts`, `src/output.ts` | Конверт, сериализация и полный бюджет ответа                         |
| `src/terminal.ts`                        | TTY, ширина и цвет                                                   |

Текущий `CommandContext` содержит `backend`, `workspace` (сведения о проекте),
`runtime`, `output`, `globals`. В нём нет прежнего `context.tasks`; числовая доска
не является текущим входом. Общий Backend и адаптеры находятся в
`packages/project-runtime/src/backend`. Прямой доступ к файловой базе допускается
в явно локальном обслуживании, не как обход отсутствующего HTTP-метода команды.

## Добавление команды

1. Найдите предметный метод Backend и его контракт. Если операция отсутствует,
   согласуйте её у владельца Core/Backend, не имитируйте последовательностью
   клиентских правок и не добавляйте отдельный запрос синхронизации графа.
2. Определите `CommandDefinition` в соответствующем семействе `src/commands/`.
   Для нового семейства подключите регистрацию в `src/program.ts`.
3. Через `configure` задайте аргументы и параметры. `requiredOption` обозначает
   синтаксически обязательный параметр; предметные условия проверяются схемой/Core.
4. Обработчик получает `context.backend` и `CommandInput`. Возвращает `data` и
   собственный `text` либо функцию рендеринга; общий адаптер печатает один ответ.
5. Добавьте справочник, тесты и согласуйте покрытие в общем каталоге возможностей.

Ниже самостоятельный пример формы регистрации существующего действия чтения,
а не предложение добавить вторую копию `task get`:

```ts
registerCommand(group, runtime, {
  name: "get <reference>",
  description: "Прочитать задачу с полным содержанием",
  arguments: { reference: "Ключ или постоянный ID задачи" },
  details: "Полученную ревизию используйте при следующем изменении.",
  examples: [["relay-cli task get PRODUCT-1", "Прочитать задачу"]],
  async run(context, input) {
    const data = await context.backend.boardTasks.get(input.argument());
    return { data, text: (options) => boardTaskText(data, options) };
  },
});
```

`registerCommand` и `commandGroup` импортируются из `src/command.ts`, представление —
из `src/presentation/board-tasks.ts`. `group` и `runtime` передаёт регистрация семейства.
`input.options` содержит локальные опции команды, `context.globals` — глобальные;
`input.argument(index)` читает обязательный позиционный аргумент,
`optionalArgument(index)` — необязательный.

## Справка и совместимость

У каждой команды нужны русские назначение, объяснения позиционных аргументов и
параметров, ограничения и исполнимые примеры. `details` дополняет основной синтаксис,
а не скрывает обязательные поля. Группа без команды показывает help; help работает
без проекта и без открытия данных. Синтаксическая ошибка должна указывать help
того уровня, где она возникла.

Глобальный `--version` показывает версию CLI. Новые страницы используют
`--snapshot-version`, а не копируют старые локальные `--version` из task/boards.
Для существующего аргумента проверяйте совместимость по фактической регистрации.
Не добавляйте обещания истории и безопасного повтора: requestId — только корреляция.

Канонический справочник содержит отдельный заголовок `### полный путь команды`
для каждого реального листа, например `### task get`, а также все параметры.
Общие наборы флагов можно объяснять один раз с явной привязкой к командам.
Документ должен объяснять действие без обязательного чтения исходника или help.

## Ввод и предметная запись

Передавайте Markdown строкой, сохраняя пустые строки и значимые пробелы. Не
преобразовывайте его в массив строк JSON-хранилища: это задача Core. Не навязывайте
временные файлы. Наличие `textInputOptions`/`readTextInput` в исходниках не делает
`--stdin`/`--file` глобальными: флаги доступны только при явной регистрации команды.
Нынешние предметные поля обычно принимают текст непосредственно аргументом.

При добавлении чтения файла/stdin используйте общий InputReader, проверяйте
конфликт источников, UTF-8, размер и ошибки. Полностью считайте ввод **до** предметной
мутации и её блокировки, чтобы не удерживать запись базы в ожидании stdin.

Для записи получите автора через `author(context)`. Передайте прочитанную ревизию
или версию и requestId по контракту метода. После конфликта нельзя автоматически
подставлять свежую ревизию; после потери ответа нельзя безусловно повторять.
Публикация комментария не требует ревизии задачи, но повтор может дублировать сообщение.
Формат 4 обслуживается `storage migrate`; совместимые product/graph migrate не
являются альтернативной миграцией. Команд истории не добавляйте под видом диагностики.

## Представление и транспорт

Не печатайте напрямую из предметного обработчика: верните `Result`, чтобы сохранить
общий конверт, UTF-8 бюджет и ошибку `RESPONSE_TOO_LARGE`. JSON:
`{ok:true,data,meta?}` / `{ok:false,error:{code,message,details?}}`. Штатные ответы и
ошибки идут в stdout. Help и версия — отдельные текстовые исключения, EPIPE — код 0.

Для человека нужен предметный рендерер: результат, метаданные, содержание и следующий
шаг. Универсальный обход DTO не заменяет его. Используйте существующий безопасный
текст, `renderMarkdown`, `cli-table3`, `string-width`, `wrap-ansi`; не измеряйте
экранную ширину через `.length` и не исполняйте ANSI пользователя. Цвет не единственный
носитель смысла. Подробнее — [терминальное представление](TERMINAL.md).

Подключение должно выбираться до открытия локальной базы. HTTP-ошибка не разрешает
fallback на локальные данные. Workspace требует проект и сервер; remote-only с
явным URL не требует конфиг. Явный проект сохраняется в `meta.project`.
Точные правила у [project-runtime](https://github.com/oim-dev/relay/blob/main/packages/project-runtime/docs/CONFIGURATION.md).
REST-контракт принадлежит [server-runtime](https://github.com/oim-dev/relay/blob/main/packages/server-runtime/docs/API.md),
генерируемый SDK не правится как источник контрактов.

## Достаточная проверка изменения

Выберите сценарии по изменению, не заменяйте их одной типизацией:

- help без конфига, группа без подкоманды, неизвестный параметр/команда;
- human и JSON, чистый stderr, ненулевой exit code ошибки, EPIPE;
- пустота, Unicode, полный многострочный Markdown, узкая ширина, ANSI, pipe;
- границы бюджета, неделимый большой ответ и подсказка продолжения;
- страницы со всеми фильтрами, проектом, конфигом и конфликтом снимка;
- local/HTTP, ошибка сервера без локального fallback;
- успешная запись и отдельное чтение сохранённых отношений;
- потеря ответа, повтор как новая попытка, конфликт прочитанной ревизии.

Адресные тесты: `cli-ux.test.ts`, `presentation.test.ts`, `remote.test.ts`,
`projects.test.ts`, `pagination.test.ts`, `source-command.test.ts` и тесты семейств
в `apps/cli/test/`. `documentation.test.ts` сверяет дерево Commander с заголовками
и флагами справочника; путь его входного документа должен соответствовать локальному
каноническому CLI.md. Успешная сборка не доказывает читаемость терминала или сценарий HTTP.

Для адресной проверки Markdown можно вызвать существующий helper без сборки приложения:

```bash
pnpm exec prettier --check apps/cli/README.md 'apps/cli/docs/*.md'
node --input-type=module -e 'import {checkDocumentation} from "./apps/cli/scripts/lib/documentation.mjs"; console.log(await checkDocumentation(process.cwd(), ["apps/cli/README.md", "apps/cli/docs/CLI.md", "apps/cli/docs/EXTENDING.md", "apps/cli/docs/TERMINAL.md", "apps/cli/docs/RELEASING.md"]));'
git diff --check -- apps/cli/README.md apps/cli/docs
```

Helper проверяет локальные переходы и якоря, не доступность внешних HTTPS-страниц.
Полный `docs:check` охватывает документацию репозитория и установленный скилл;
его результат не равен адресной проверке этих пяти файлов.

## Документация и поставка

Поддерживайте точный синтаксис в локальном CLI.md, общую семантику — у владельца
domain, общий реестр покрытия — только в CAPABILITIES. Производные материалы скилла
не являются вторым авторским справочником. При изменении источников его действующая
сборка проверяется отдельно через `pnpm run skills:build` и `pnpm run skills:check`.

README пакета должен быть коротким и понятным на npm. Поставляемые документы входят
в `files: [dist, README.md, CHANGELOG.md, docs]`: соседние docs могут ссылаться друг
на друга относительно, а внешние общие документы — через HTTPS GitHub `main` по
каноническим путям. Не полагайтесь на наличие корневой `docs/` в архиве.

Проверка установленного комплекта — `pnpm run package:check`; это отдельная проверка
поставки, не обязательное действие каждой Markdown-правки. Процесс версий и публикации
не копируется сюда: [руководство поставки](RELEASING.md). Сообщайте фактически выполненные
команды, ограничения и оставшиеся процессы отдельно от прочитанного кода.
