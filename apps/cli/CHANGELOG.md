# История изменений

## 0.6.1

- Подготовка первого npm-выпуска `@oim-dev/relay-cli@0.6.1` в согласованном комплекте
  с `@oim-dev/relay-server@0.6.1` и `@oim-dev/relay-mcp@0.6.1`.
- Для этого выпуска предусмотрена ручная публикация проверенного самодостаточного
  npm-архива: рабочая копия монорепозитория для запуска не требуется.
- В состав архива включаются `CHANGELOG.md` и пользовательская документация в `docs`;
  ссылки README рассчитаны на чтение вне монорепозитория.

После публикации проверить доступную справку можно командой:

```bash
npx @oim-dev/relay-cli@0.6.1 --help
```

## 0.3.1

### AI skill и рабочий процесс

- Самодостаточный `skills/tasks-cli`: основной SKILL.md и шесть справочных материалов.
  Установка: `npx skills add gromlab-ru/tasks-cli --skill tasks-cli`.
- Оркестратор создаёт и назначает задачи, управляет статусами и принимает результаты.
  Субагент получает конкретный ID, читает контекст и пишет отчёты и summary.
- Основной способ подключения — `server.url` в конфиге проекта. Субагенту не нужны
  переменные URL и самостоятельный `claim`. Сценарий подтверждён сквозным тестом.
- Проектные копии `.agents/skills` исключены из Git; четыре внешних скилла
  восстанавливаются командой `pnpm run skills:install` из `skills-lock.json`.

### Документация и поставка

- Единая README-витрина для GitHub и npm с иллюстрацией доски и разделом AI skill.
- Навигатор документации, руководства для оркестратора и субагентов, полные справочники
  CLI/API, конфигурации, JSON-вывода, ошибок, Git и восстановления.
- Сохранены переходы со старых адресов справки; добавлены проверки ссылок, якорей
  и самостоятельности установленного скилла.
- npm-архив включает пользовательскую документацию; README содержит версионные ссылки
  на иллюстрацию, руководства и скилл. Проверяется установка готового архива.
- После успешной npm-публикации workflow автоматически создаёт GitHub Release
  с описанием из changelog.

Документы задач v2 и конфигурация v1 совместимы с 0.3.0 без миграции.

### Исправления

## 0.3.0

### HTTP-режим и параллельные агенты

- CLI выбирает HTTP по `--server-url`, `TASKS_SERVER_URL` или `server.url`. Глобальный
  `--local` принудительно включает Core; при сетевой ошибке локальная запись автоматически не включается.
- Единый интерфейс операций с локальным и HTTP-адаптерами. Существующий `@relay/rest-sdk`
  включён в npm-дистрибутив. В HTTP-режиме рабочая копия агента не открывает `.tasks` и `.tasks-runtime`.
- API получает автора каждой мутации отдельно; `claim`, записи и метаданные сохраняют
  `--actor` / `TASKS_ACTOR` конкретного агента. Автор сервера остаётся значением по умолчанию для UI.
- Рабочие команды поддерживают HTTP, включая `overview`, дерево, зависимости, фильтры
  истории, проверку проекта, JSON, текст и курсоры. `init`/`migrate` обслуживают локальные данные.
- `--request-id` у добавления логов и комментариев: дедупликация в Core внутри документа,
  сохранение ключа при перезапуске, повтор через HTTP или `--local`; другой текст или автор дают конфликт.
- Явная `--if-revision` сохраняет проверку версии. Запросы без неё используют текущий
  документ под блокировкой, как в прежнем локальном CLI.
- Проверки десяти Git worktree, потерянного ответа после записи, остановки сервера,
  аварийного `--local` и установленного npm-архива.

### Обзор и веб-доска

- Команда `overview [id]`: прогресс родительских задач, доступная работа, настраиваемые
  статусы проверки и рейтинг блокеров по прямому влиянию и будущей готовности к `claim`.
- Обзор использует один снимок Core, учитывает внешние зависимости дерева и сохраняет
  полные счётчики при ограничении строк и байтов в текстовом и JSON-выводе.
- Демонстрационный проект на 190 задач; группы со счётчиками и общая прокрутка доски.
- Подгрузка сохраняет карточки и позицию прокрутки; ссылки Markdown используют React Router.
- SSE heartbeat, восстановление после dev-прокси 502 и устойчивый жизненный цикл подписки при перемонтировании.

## 0.2.0

Обновление с `0.1.x` требует миграции старого хранилища:
`npx @gromlab/tasks-cli@0.2.0 migrate --actor human`, затем `validate`.
Конфиг версии 1 совместим; секция `server` необязательна.

### Веб-доска и поставка

- CLI публикуется из `apps/cli` в pnpm workspaces/Turbo-монорепозитории; приватные Core, Contracts и Server Runtime включаются в самодостаточный архив вместе с веб-интерфейсом.
- Зависимости монорепозитория управляются pnpm 11.18.0: общий `pnpm-lock.yaml`, внутренние ссылки `workspace:*`, установка в CI с `--frozen-lockfile`. Готовый архив проверяется через npm/npx и публикуется в npm registry.

- Dev-сервер запускается из TypeScript-исходников и сохраняет работоспособность при очистке `dist`; проверка типов работает отдельным watch-процессом.
- CLI и самостоятельная точка входа сервера находятся в `apps/`, общий NestJS runtime, ядро и API-контракты — в `packages/`; тесты находятся внутри приложений и пакетов.
- Реализован NestJS/Fastify API с OpenAPI 3.1 и Swagger: задачи, доска, назначения, комментарии и отчёты напрямую через Core.
- Курсорная пагинация снимков доски и истории, проверка ревизий и единый формат HTTP-ошибок; схемы запросов и документации на основе Zod/Core.
- SSE отслеживает изменения из API/CLI, замену файлов и конфигурации; HTTP/OpenAPI и потоковые интеграционные тесты.
- Команда `server` поднимает общий сервер с React-доской на `/`: готовые HTML, JS, CSS и шрифты включены в npm-пакет в `dist/web`. API и Swagger работают на том же порту; SPA-маршруты изолированы от API и отсутствующих ресурсов.
- `build:server` собирает статику `apps/web` вместе с backend; standalone-сервер раздаёт её из `apps/web/dist` независимо от рабочего каталога.
- Настройка порта: `--port` → `TASKS_PORT` → `server.port` в `tasks.config.json` → `3000`. Значение `0` выбирает свободный порт. `init` создаёт настройку, `config get` показывает её, старые конфиги используют `3000`.

### Хранилище и команды

- Плоское хранилище `.tasks/<id>.json`; миграция прежней структуры, служебные файлы вне каталога задач.
- Сохраняемый порядок карточек и чтение через `list --sort board`.

- Единственный числовой `id` задачи: от 1, следующий равен максимальному существующему плюс один. Файлы и все ссылки используют тот же ID; поле `number` удалено.
- Формат задач v2 и команда `migrate`: перенос UUID-документов со всеми связями и контекстом, сохранение исходников и возобновление после прерывания.
- Рабочий `list`: все незавершённые задачи по группам, включая заблокированные; `--all` включает конечные статусы, явный `--status` выбирает заданный статус.
- Количество задач в `list` ограничено только байтовым бюджетом или явным `--limit`; большие списки имеют продолжение и счётчик «показано N из M». `--all` совместим с `--limit` / `--cursor`.
- ID блокеров рядом со статусом; подсказка истории для пустого рабочего списка.
- Цвет каждого статуса в конфиге через `statuses.<имя>.color`.
- Справка всех команд с объяснениями, аргументами, общими параметрами и примерами; подсказки при ошибках.
- `create "Название"` в дополнение к `--title`; `claim --status` для атомарного назначения и перехода.
- Единый формат регистрации команд, общие источники текстового ввода и руководство расширения CLI.
- Прямое чтение карточки и её связей; один снимок графа на изменение вместо повторного чтения всей базы.
- README со сквозным жизненным циклом задач через `npx`: постановка, зависимости, проверка, доработка, передача работы, завершение и отмена; playground в новом формате.

### Терминал

- Цветные статусы, таблицы, карточки, дерево связей и оформление комментариев и отчётов.
- Подсветка Markdown и распространённых блоков кода; перенос по ширине терминала.
- Управление цветом через `--color auto|always|never`, `NO_COLOR` и `FORCE_COLOR`.
- Текстовые ответы для всех команд и ошибок; JSON-режим без ANSI-последовательностей.
- Байтовая пагинация учитывает полное оформление, включая цветовые коды.
