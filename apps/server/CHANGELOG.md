# Изменения Relay Server

## 0.13.0

- Исправлена блокировка записи `STORAGE_BUSY` при работающем Server и медленном origin.
  HTTP-операции сохраняют данные локально без ожидания fetch/push. Недоступный VPN
  и Git-конфликт приостанавливают доставку, сохраняя чтение и запись в локальную базу.
- Добавлены `GET /context/sync` для состояния очереди и `POST /context/sync` для запроса
  фоновой попытки с ответом 202, включая проектные маршруты workspace. Возможность
  объявляется как `relay-background-sync-v1`; контекст сообщает `synchronizationMode`.
  OpenAPI и общий REST SDK обновлены согласованно.
- Web показывает неблокирующий статус доставки, число коммитов без подтверждения origin,
  изменения вне коммитов и последнюю ошибку. «Повторить сейчас» запускает фоновую попытку.
  При недоступном origin или конфликте формы остаются доступны и сохраняют введённый текст.
- Локальные Git-коммиты продолжают создаваться во время сетевого ожидания. Фоновое
  применение проверяет HEAD и отпечаток базы, сохраняя новые локальные изменения;
  очередь отправляется после восстановления связи.
- Поддержано подключение независимых баз, созданных CLI из полного Git-шаблона,
  в том числе одновременная работа с несколькими такими проектами в workspace.
- Совместный выпуск с `@oim-dev/relay-cli@0.13.0` и `@oim-dev/relay-mcp@0.13.0`.
  После обновления перезапустите Server. Физический формат 4 и профиль данных 3
  не изменены; дополнительная миграция актуальной базы не требуется.

## 0.12.0

- Server подключает внешний worktree базы `relay-data` и использует общий с CLI механизм
  синхронизации, восстановления и блокировок. Уже существующая база подключается
  автоматически; новую базу создаёт явный CLI `init`.
- Конфликт Git-синхронизации возвращает HTTP 409 и уведомляет Web через SSE.
  Web показывает блокировку с адресной командой восстановления, сохраняет черновики
  при ошибках обновления и снятии блокировки; исправлена обработка Escape в редакторе.
- Уточнены создание досок и оформление канбана. Новый проект получает только продуктовую
  доску, ранее созданные инфраструктурные доски сохраняются.
- Git-управление и перенос базы выполняются локальным CLI; отдельных REST-операций
  `sync` нет. Физический формат 4 и профиль модели данных 3 не изменены.
- Совместный выпуск с `@oim-dev/relay-cli@0.12.0` и `@oim-dev/relay-mcp@0.12.0`.
  После обновления перезапустите Server.

## 0.11.0

- Добавлены REST и OpenAPI для истории агентской работы: сессии, участия, checkpoints,
  делегирование, принятие результатов и продолжение работы. Операции доступны в local
  и проектных маршрутах workspace; общий Backend и SDK согласованы с контрактами.
- В Web добавлен экран «История» с графом времени проекта, ветками делегирования,
  обозначением незавершённой работы и адресным чтением полных материалов точек.
  Модальное окно показывает Markdown, автора, контекст и постраничный список точек ветки.
- Граф читается компактными страницами с явными границами и последними точками
  незавершённых веток. Визуальное завершение ветки отделено от явного принятия результата
  родителем; Web предоставляет просмотр истории, запись выполняется через CLI или REST.
- Серверный обзор проекта дополнен сводкой сессий. Улучшены отображение Markdown
  и навигация по материалам истории в поставляемом Web.
- Профиль модели данных повышен до 3 при сохранении физического формата 4. Базы
  предыдущего профиля требуют явной миграции через локальный CLI; запуск Server
  не переносит данные автоматически.
- Совместный выпуск с `@oim-dev/relay-cli@0.11.0` и `@oim-dev/relay-mcp@0.11.0`.
  После обновления и миграции базы перезапустите Server.

## 0.10.0

- При занятом порте Server выбирает следующий свободный. Сообщение запуска, Web
  и `--open` используют фактический адрес; `--port 0` по-прежнему поручает выбор ОС.
- Расширены REST и OpenAPI: библиотека документов и её связи, продуктовые чтения
  и состав приложений, компактные проекции планов и релизов, адресные зависимости
  задач и каталог возможностей сервера. Backend и генерируемый SDK согласованы с API.
- Каталог проектов workspace читается серверными страницами с проверкой продолжения;
  добавлены компактные квитанции регистрации и удаления. Проектные контексты сохраняют
  изоляцию зарегистрированных баз и не создают отсутствующие данные при чтении.
- Исправлены предметные чтения, проверки связей и расчёты готовности в общем Core.
  Удаление и изменения состава сохраняют исходные проверки ревизий и атомарность.
- Server явно сообщает несовместимость версий данных и необходимость обслуживания.
  Web отображает эти ошибки вместо пустого проекта; миграция выполняется отдельно
  локальным CLI, без скрытого переноса при запуске сервера.
- Совместный выпуск с `@oim-dev/relay-cli@0.10.0` и `@oim-dev/relay-mcp@0.10.0`.
  После обновления перезапустите Server; перед работой с прежней базой проверьте её
  через CLI `storage status` и при необходимости выполните явную миграцию.

## 0.9.2

- Переработан Web-экран «Обзор»: паспорт, диаграмма шести колонок задач, текущая работа
  и блокировки, планы и релизы, размер проекта, знания, доски и закреплённые документы.
  Собственные статусы задач, планов и релизов отделены от фактической готовности.
- Добавлены показатели оператора с полными постраничными списками: обязательства задач
  на проверке, влияние прямых блокеров и затронутые задачи, работа вне открытых планов,
  незавершённая работа по доскам, открытые планы с выполненным составом и подготовка выпуска.
  Обзор только читает данные, не меняет статусы и не подтверждает внешнюю проверку или публикацию.
- Обзор обновляется по SSE; раскрытые списки показателей перечитываются с сохранением
  загруженного объёма. Исправлен сброс загруженных страниц каталога досок при обновлении.
  Ошибки чтения и устаревшие данные обозначаются явно, а не подменяются пустым проектом.
- REST-обзор `GET /api/v1/product/overview` дополнен `snapshotVersion`, `generatedAt`
  и `snapshot` с показателями `operator`. Добавлен
  `GET /api/v1/product/overview/metrics/:metric`, включая проектный маршрут workspace:
  детализация защищена версией среза и объявлена возможностью `relay-overview-metrics-v1`.
- Формат HTTP-ответа обзора изменён: обновляйте Server, CLI и MCP согласованным комплектом
  `0.9.2`. Совместный выпуск с `@oim-dev/relay-cli@0.9.2` и `@oim-dev/relay-mcp@0.9.2`.

## 0.7.0

### REST API и Web

- Удалены общие entity/graph/task history-маршруты из REST API и OpenAPI;
  в Web убраны раздел истории и автоматические события карточек. Пользовательские
  обсуждения остаются доступны через API комментариев и в карточке задачи.
- `requestId` — только корреляция запроса, без дедупликации и сохранённого ответа.
  Web больше не повторяет мутации автоматически: после потери ответа нужно перечитать
  текущее состояние. Повторная отправка комментария может создать ещё одно сообщение.
- Планы и релизы показывают текущий результат работы, а не журнал операций.

### Хранение и обновление

- Формат хранения 4 (оболочки записей версии 3) содержит текущие данные и комментарии,
  без автоматического аудита, `events`/`planningEvents`, `receipts`/`requests`
  и сохранённых результатов команд. ID, алиасы, ревизии, связи и полные пользовательские
  комментарии сохраняются при миграции.
- Перед переходом остановите старые процессы записи, сделайте резервную копию и обновите
  используемые Server, CLI и MCP до согласованного комплекта `0.7.0`. Поддерживаемые
  legacy-базы и форматы 1/2/3 требуют явного локального `storage migrate` через CLI;
  обычное чтение и reindex не мигрируют базу.
- Удаление истории и квитанций необратимо. Для отката восстановите старую базу из резервной
  копии и используйте соответствующую версию пакетов; автоматического downgrade нет.
  После миграции проверьте базу командой CLI `validate`, затем содержание и отношения.
- CI сборки и установки использует Node.js 24; `engines` пакетов не изменён.
  Исключение Node.js 22 из CI не означает снятия его заявленной runtime-поддержки.

## 0.6.2

- Подготовка совместного выпуска `@oim-dev/relay-server@0.6.2`,
  `@oim-dev/relay-cli@0.6.2` и `@oim-dev/relay-mcp@0.6.2`:
  один GitHub Release `v0.6.2`, стабильная версия без prerelease-суффикса, npm-канал `latest`.
- Для выпуска предусмотрена автоматизированная поставка: событие GitHub Release
  `published` запускает проверки комплекта, затем проверенные npm-архивы передаются
  как артефакты для публикации через npm Trusted Publishing (OIDC).
  Push и PR запускают только проверки, без npm-публикации.
- Runtime Server не менялся: выпуск согласует версию с CLI и MCP и улучшает проверку
  поставки всего комплекта.

Это описание подготовки выпуска, а не подтверждение публикации `0.6.2` или успешного
OIDC-запуска. Совместная версия продолжает правило комплекта `0.6.1`; ручной способ
публикации в разделе `0.6.1` относится к тому историческому выпуску.

## 0.2.0

- Полное веб-приложение с отдельными разделами обзора, паспорта, планов, доски,
  требований и знаний, работы и проверок, релизов, истории и передачи контекста.
- Планы с этапами, критериями и приёмкой; общие карточки задач и фильтры по плану,
  этапу и виду работы. Подзадачи наследуют этап до явной настройки контекста.
- Поручения агентам, попытки исполнения, результаты проверок, заключения приёмки,
  вопросы и подробные сведения о багах.
- Состав релиза, установки в окружения, подтверждения результатов и точки продолжения
  со сравнением изменившихся задач и документов.
- REST-операции жизненного цикла, схемы OpenAPI, обновлённый SDK и синхронизация
  проектных документов через SSE в local и workspace.
- Адаптивная навигация, светлая и тёмная темы, сохранение черновиков и обработка
  конфликтов ревизий; разделы загружаются по мере открытия.

Задачи сохраняются в `.relay/tasks`, остальные данные проекта — в `.relay/project`.
Workspace хранит регистрации независимых проектов. Существующие базы не требуют миграции.

- Автоматические режимы local и workspace.
