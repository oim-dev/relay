# Работа в Playground

Это инструкция для workspace [Playground](../README.md) с текущими исходниками Relay.
Она не устанавливает опубликованные npm-пакеты и не разворачивает демопродукты.

Перед отдельной агентской сессией сначала подготовьте и установите доступный агенту
продуктовый скилл Relay по [инструкции его пакета](../../../packages/relay-skill/README.md).
Внешние скиллы разработки его не заменяют. Для запуска сервисов или ручных CLI-команд
без агентской сессии загрузка скилла в агента не требуется.

## Подготовка и сохранность данных

Зависимости устанавливаются из корня Relay по [инструкции разработки](../../../scripts/README.md).
Команды этого раздела выполняются из `apps/playground`:

```bash
pnpm run init
```

Эквивалент — `node init.mjs`; из корня — `node apps/playground/init.mjs`.
Инициализатор вызывает текущий CLI с явным проектным конфигом и `--local`.
Если `.relay/config.json` отсутствует, выполняется `init`; затем каждый проект
проходит `validate`. Существующие ID, конфигурация и накопленная память сохраняются.
Server для этого не нужен, автоматических seed и reset нет.

Пути привязаны к самому `init.mjs`: смена cwd не изолирует проверку.
Проверяйте повторную инициализацию или запись только на согласованной копии окружения,
не на чужих данных. Каталоги `.relay` и `.agents` игнорируются Git, но ignore не
удаляет уже отслеживаемые файлы и не является резервной копией памяти.

## Server и Web

Из **корня Relay**, не из Playground:

```bash
RELAY_CONFIG=apps/playground/relay.workspace.json pnpm run dev
```

Обычный `pnpm run dev` без `RELAY_CONFIG` выбирает тот же workspace; явно заданная
переменная переопределяет его. В Web выберите `coffee-shop` или `p2p-rental`.

- Web: <http://127.0.0.1:5173>.
- Server: <http://127.0.0.1:4700>.
- Health: <http://127.0.0.1:4700/api/v1/health>.
- Swagger: <http://127.0.0.1:4700/api/docs>.

Server и Web запускаются отдельно от агентской сессии. Перезапуск процесса
не сбрасывает память. Не останавливайте чужие процессы ради освобождения портов.
Подробные параметры — у [Server](../../server/README.md) и [Web](../../web/README.md).

## CLI из apps/playground

```bash
pnpm --silent run cli projects list --format json
pnpm --silent run cli coffee-shop boards --format json
pnpm --silent run cli p2p-rental boards --format json
pnpm --silent run cli coffee-shop product overview
pnpm --silent run cli p2p-rental product overview
pnpm --silent run cli coffee-shop task list --limit 20 --format json
```

Script `cli` запускает текущие исходники через tsx и `tasks-source`, явно передаёт
`relay.workspace.json`. Запросы идут к общему Server, настроенному в этом конфиге.
`--silent` сохраняет чистый JSON без сообщений pnpm. Ожидаются два зарегистрированных
проекта и их фактические данные, а не заранее определённый набор задач.
`task list` возвращает одну страницу, не доказательство полноты списка.

Для локальной проверки без Server:

```bash
pnpm --silent run cli --config coffee-shop/.relay/config.json --local validate
pnpm --silent run cli --config p2p-rental/.relay/config.json --local validate
```

Эти команды проверяют проекты напрямую, но не проверяют HTTP, Web или MCP.
Синтаксис и параметры выдачи принадлежат [CLI](../../cli/README.md);
локальная справка — `pnpm --silent run cli --help`.
Для записи укажите автора через `--actor` или `RELAY_ACTOR`.
Порядок наполнения и требования к содержанию — в [рабочем процессе](../../../docs/guides/WORKFLOW.md)
и [руководстве по содержанию](../../../docs/guides/CONTENT.md).

### Однопроектный режим

Если требуется только кофейня, запустите из корня отдельный выбранный режим:

```bash
RELAY_CONFIG=apps/playground/coffee-shop/.relay/config.json pnpm run dev
```

Это альтернатива workspace-серверу. Из Playground обращайтесь к нему с проектным конфигом:

```bash
pnpm --silent run cli --config coffee-shop/.relay/config.json --server-url http://127.0.0.1:4700 product overview
```

Не ожидайте двух проектов от сервера, запущенного в однопроектном режиме.

## MCP

При работающем workspace-сервере из `apps/playground`:

```bash
pnpm run mcp
```

Этот script запускает исходники MCP с тем же workspace-конфигом. HTTP endpoint:
**http://127.0.0.1:4710/mcp**. Его нужно отдельно добавить в MCP-клиент; запущенный
процесс сам не подключает инструменты к агенту. В проектных инструментах передавайте
`project: "coffee-shop"` или `project: "p2p-rental"`.

CLI, Web и MCP должны обращаться к одному Server и выбранному проекту.
После изменения кода MCP обновите свой процесс и подключение клиента.
Discovery не доказывает выполнение операций: проверьте чтение фактической записи
и доступность `structuredContent`. Параметры, пагинация и ошибки описаны у
[MCP](../../mcp/README.md).

## Проверка результата и ошибки

- Сначала проверьте health и `projects list`. Если список не тот, сверьте `RELAY_CONFIG`,
  режим сервера и адрес из `relay.workspace.json`, не запускайте повторный `init`
  как способ исправить соединение.
- После порученного изменения прочитайте запись в том же проекте через другой
  интерфейс. Не создавайте фиктивные задачи или отметки готовности ради smoke.
- Не найден конфиг: выполните инициализацию отсутствующего проекта. Если существующий
  проект не проходит `validate`, сохраните данные и разберите ошибку по
  [руководству восстановления](../../../docs/guides/RECOVERY.md), без ручного reset.
- Нет ответа Server: проверьте процесс и адрес. Локальный `validate` может работать
  при недоступном HTTP и не доказывает исправность MCP.
- Порт занят: выясните владельца процесса или выберите другое согласованное окружение;
  не завершайте чужие процессы.

У Playground нет отдельного test-script. При проверке изменения его инфраструктуры
на согласованной копии проверьте повторный init, сохранение записей после рестарта,
изоляцию проектов и понятную ошибку недоступного Server. Проверка записи должна
действительно включать запись и последующее чтение: список проектов этого не заменяет.
