# Playground Relay

Два независимых проекта для проверки Relay как памяти продукта. Агент может открыть
эту папку отдельной рабочей сессией и работать через CLI или MCP с текущим кодом Relay.

[Продуктовый контракт Playground](../../docs/product/applications/playground/README.md)
описывает назначение, сценарии и критерии. Изменения самого Playground сопровождаются
[протоколом разработки Relay](../../docs/development/PROTOCOL.md).

| Ключ проекта  | Продукт                                      | Требования                                |
| ------------- | -------------------------------------------- | ----------------------------------------- |
| `coffee-shop` | Кофейня «Тёплый круг»: предзаказ и самовывоз | [ТЗ кофейни](coffee-shop/product-spec.md) |
| `p2p-rental`  | P2P-сервис аренды техники                    | [ТЗ аренды](p2p-rental/product-spec.md)   |

Исходная поставка содержит ТЗ и инициализацию Relay, без кода демонстрационных продуктов
и автоматического наполнения. Текущее содержимое локальной памяти проверяйте через
инструменты Relay: после пользовательской работы проекты уже могут содержать записи.

## Структура

```text
playground/
  relay.workspace.json       # Общий реестр двух проектов
  init.mjs                   # Инициализация без наполнения
  coffee-shop/
    product-spec.md
    .relay/config.json
  p2p-rental/
    product-spec.md
    .relay/config.json
```

Инструкции владельца Playground — в [профиле relay-delivery](../../packages/dev-agents/src/delivery.md).

Хранилища задач и служебные каталоги создаёт Relay. Пустые каталоги Git не хранит.
Все папки `.relay` внутри Playground игнорируются. Уже отслеживаемые конфигурации
остаются в индексе Git; правило ignore не удаляет их автоматически. Недостающую
конфигурацию создаёт инициализатор, существующие ID и данные сохраняются.

## Скилл Relay

Перед первой агентской сессией и после изменения исходников скилла выполни из корня Relay:

```bash
pnpm run skills:build
```

Сборка автоматически обновляет локальный пакет `.agents/skills/relay` в playground,
включая `SKILL.md` и справочники. Повторная сборка заменяет пакет целиком, удаляя
устаревшие файлы. Весь каталог `apps/playground/.agents/` исключён из Git.

## Инициализация

Нужны Node.js 24 (рекомендуется), pnpm 11.18.0 и установленные зависимости
монорепозитория (`pnpm install --frozen-lockfile` из корня Relay).

Из этой папки:

```bash
pnpm run init
```

Или из любого каталога:

```bash
node /путь/к/relay/apps/playground/init.mjs
```

Скрипт вызывает штатный CLI для каждого проекта. Существующая конфигурация и данные
сохраняются; повторный запуск не создаёт записи и не сбрасывает результаты работы.
Скрипту не нужен запущенный Server. Создание демоданных пока не предусмотрено.

## Web и Server

Разработчик запускает Web и Server отдельно от агентской сессии. Для одновременной работы
с обоими проектами из корня репозитория Relay:

```bash
pnpm dev
```

- Web: <http://127.0.0.1:5173> — выбрать `coffee-shop` или `p2p-rental`.
- Server: <http://127.0.0.1:4700>.
- Проверка доступности: <http://127.0.0.1:4700/api/v1/health>.
- API: <http://127.0.0.1:4700/api/docs>.

`pnpm dev` и `pnpm dev:server` без `RELAY_CONFIG` используют
`apps/playground/relay.workspace.json`. Для отдельной кофейни в однопроектном режиме
передайте её конфиг явно:

```bash
RELAY_CONFIG=apps/playground/coffee-shop/.relay/config.json pnpm dev
```

Для команд workspace ниже нужен Server с `relay.workspace.json`.
Перезапуск dev-процессов не очищает данные.

Для проверки [досок](../../docs/product/entities/boards/README.md) и
[визуального контекста](../../docs/product/applications/web/README.md#визуальный-контекст)
выберите существующие записи своего проекта. Наличие конкретных карточек и связей
в локальной базе не гарантируется исходной поставкой Playground.

## CLI из папки playground

```bash
pnpm --silent run cli projects list
pnpm --silent run cli coffee-shop product overview
pnpm --silent run cli p2p-rental product overview
pnpm --silent run cli coffee-shop task list --limit 20 --format json
```

CLI запускается из актуальных исходников; workspace-конфиг передаётся явно.
Запросы идут через общий Server, адрес которого задан в `relay.workspace.json`.
Команды записи требуют автора: передавайте `--actor <имя>` или задайте `RELAY_ACTOR`.

Пример `task list` выводит первую страницу — до 20 записей.
Параметры выдачи и известное ограничение `--version` описаны в
[справочнике CLI](../../docs/reference/CLI.md).

Для локальной проверки без сервера:

```bash
pnpm --silent run cli --config coffee-shop/.relay/config.json --local validate
pnpm --silent run cli --config p2p-rental/.relay/config.json --local validate
```

Если Server запущен в однопроектном режиме кофейни:

```bash
pnpm --silent run cli --config coffee-shop/.relay/config.json --server-url http://127.0.0.1:4700 product overview
```

## MCP

При запущенном workspace-сервере из этой папки:

```bash
pnpm run mcp
```

MCP работает с исходниками Relay и подключается к общему Server.
Адрес для HTTP MCP-клиента: **http://127.0.0.1:4710/mcp**.
Сам запуск процесса не подключает инструменты к агенту: этот адрес нужно указать
в настройках MCP-клиента отдельной сессии. В инструментах указывайте
`project: "coffee-shop"` или `project: "p2p-rental"`.
После изменения кода MCP перезапустите процесс и при необходимости переподключите клиент.

CLI, Web и MCP должны обращаться к одному Server и одному проекту.
Проверить режим и зарегистрированные проекты можно через `cli projects list`.

## Требования и память проекта

ТЗ кофейни подготовлено для этого playground. ТЗ аренды скопировано без изменения
содержимого из спецификации исходного проекта.
В нём сохранены относительные ссылки и упоминания состояния исходного проекта;
связанные документы сюда не перенесены, эти упоминания не означают наличие реализации
в playground. Для инициализации доступ к исходному репозиторию не нужен.

ТЗ — источник требований, а не отчёт о выполнении. Дальнейшие решения, сценарии,
задачи и результаты проверок сохраняйте через Relay по поручению пользователя.
Справочник команд доступен через `pnpm --silent run cli --help`.
