# Playground Relay

Рабочий workspace для использования текущего Relay на двух независимых проектах.
Здесь проверяется Relay как память проекта, а не реализация приложений кофейни
или аренды. Можно открыть эту папку отдельной агентской сессией и работать через
CLI/MCP с теми же данными, которые показывает Web.

| Проект                                                       | Требования                                |
| ------------------------------------------------------------ | ----------------------------------------- |
| `coffee-shop` — кофейня «Тёплый круг», предзаказ и самовывоз | [ТЗ кофейни](coffee-shop/product-spec.md) |
| `p2p-rental` — P2P-сервис аренды техники                     | [ТЗ аренды](p2p-rental/product-spec.md)   |

Исходная поставка содержит ТЗ и инициализатор, без кода демопродуктов и seed.
В локальных базах уже могут быть накопленные записи: **их нужно сохранять**, а не
считать окружение пустым или сбрасывать ради демонстрации. ТЗ аренды перенесено
из внешнего проекта; его ссылки и заявления о реализации относятся к источнику.

## Начало работы

Для агентского использования первым шагом подготовьте и установите продуктовый
скилл Relay, чтобы он был доступен агенту перед открытием отдельной сессии Playground.
Источники, сборка и установка локального скилла описаны у
[пакета relay-skill](../../packages/relay-skill/README.md). Это скилл пользователя
Relay, не внешние скиллы разработки. Запуск сервисов и ручное обслуживание через
CLI не требуют загрузки скилла в агента.

Подготовьте зависимости по [инструкции разработки](../../scripts/README.md).
Из `apps/playground`:

```bash
pnpm run init
```

Инициализатор создаёт только отсутствующие проекты и валидирует оба без Server.
Из корня Relay запустите Server и Web:

```bash
pnpm run dev
```

Без заданного `RELAY_CONFIG` выбирается workspace Playground. Web:
<http://127.0.0.1:5173>. В отдельном терминале из `apps/playground`:

```bash
pnpm --silent run cli projects list --format json
```

Дальше: [работа через CLI, Web и MCP, проверка и устранение ошибок](docs/USAGE.md).
Смысл действий задают [рабочий процесс](../../docs/guides/WORKFLOW.md)
и [предметные контракты](../../docs/domain/README.md), а не демонстрационное наполнение.
