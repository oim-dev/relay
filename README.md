# Relay

Рабочая память проекта для людей и AI-агентов.

Relay помогает связать требования к продукту с задачами и результатами: понять,
что нужно сделать, найти контекст изменения и проверить, какие обязательства выполнены.
Он подходит для совместной работы человека, оркестратора и исполнителей, которым
нужна общая память за пределами одной беседы.

[![CLI в npm](https://img.shields.io/npm/v/%40oim-dev%2Frelay-cli?label=CLI)](https://www.npmjs.com/package/@oim-dev/relay-cli)
[![Server в npm](https://img.shields.io/npm/v/%40oim-dev%2Frelay-server?label=Server)](https://www.npmjs.com/package/@oim-dev/relay-server)
[![MCP в npm](https://img.shields.io/npm/v/%40oim-dev%2Frelay-mcp?label=MCP)](https://www.npmjs.com/package/@oim-dev/relay-mcp)

## Что можно делать

- Описывать продукт: паспорт, фичи, пользовательские сценарии и вклад приложений.
- Организовывать задачи на досках продукта, приложений и инфраструктуры; задавать
  критерии приёмки, подзадачи и зависимости.
- Объединять задачи в планы с этапами, видеть прогресс и причины неготовности.
- Составлять релизы из выбранных планов и отдельно фиксировать факт выпуска.
- Хранить Markdown-документы, прикреплять их к сущностям и исследовать связанные требования.
- Обсуждать задачи и читать историю изменений с авторством и временем.

Relay хранит сведения о работе, но не запускает агентов, тесты или CI/CD.
Статус задачи и запись о выпуске не заменяют проверку реального результата.
[Возможности и ограничения](docs/product/CAPABILITIES.md).

## Как устроена работа

**Web** — интерфейс человека: продукт, доски, планы, релизы и документы.
**CLI** предоставляет те же предметные операции в терминале и JSON.
**MCP** подключает эти операции к агентскому клиенту через **Relay Server**.
Server включает готовый Web и HTTP API; все интерфейсы используют общие правила Core.

Данные проекта хранятся в JSON рядом с кодом, по умолчанию в `.relay`.
Их можно резервировать и версионировать. В режиме local CLI работает напрямую с Core
либо через сервер. Workspace позволяет одному серверу обслуживать несколько
независимых проектных баз, не смешивая их данные.
[Конфигурация и режимы](docs/reference/CONFIGURATION.md).

## Быстрый старт

Команды npm ниже доступны после [первого ручного выпуска](docs/development/RELEASING.md)
пакетов в `@oim-dev`.
До него используйте [запуск из исходников](docs/DEVELOPMENT.md#запуск).

Нужен Node.js 22+; рекомендуется Node.js 24. В каталоге своего проекта выполните:

```bash
npx @oim-dev/relay-cli init
npx @oim-dev/relay-server --open
```

Web откроется по адресу **http://127.0.0.1:4700**. Оставьте сервер работающим,
опишите продукт и создайте первую задачу в Web или из другого терминала:

```bash
npx @oim-dev/relay-cli task create --board product --title "Описать первый сценарий" --actor human
npx @oim-dev/relay-cli task list
```

Для чтения задачи используйте `task get <ключ>` с ключом из ответа.
Для автоматизации добавьте `--format json`; параметры команды доступны через `--help`.
Используйте согласованные версии CLI, Server и MCP: опубликованный комплект может
отличаться от исходников этой ветки.
[Подробный первый запуск](docs/GETTING_STARTED.md) · [Решение проблем](docs/TROUBLESHOOTING.md).

## Подключение агента

При работающем Relay Server запустите в отдельном терминале:

```bash
npx @oim-dev/relay-mcp --server-url http://127.0.0.1:4700
```

Добавьте в MCP-клиент адрес **http://127.0.0.1:4710/mcp** с транспортом Streamable HTTP.
Проверьте доступные проекты через `projects_list`; в workspace указывайте проект
в каждом вызове. [Скилл Relay](skills/relay/SKILL.md) объясняет работу с требованиями,
задачами, безопасными повторами и фактическими результатами.
[Установка скилла](docs/development/SKILLS.md) · [Работа с агентами](docs/guides/ORCHESTRATION.md).
