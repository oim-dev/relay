# Relay

Рабочая память проекта для людей и AI-агентов.

Relay сохраняет замысел продукта, требования, документы и результаты работы,
чтобы человек и агенты могли продолжать проект с общим пониманием за пределами одной беседы.

## Рабочий цикл

1. **Собрать и сохранить знания.** Вместе с пользователем разобрать ТЗ, уточнить
   неизвестное, описать паспорт продукта, фичи, сценарии, приложения и их реализации.
   По мере анализа сохранять исходные материалы, пояснения и решения в документах,
   прикреплять их к соответствующим сущностям. Это самый важный, сложный и долгий этап:
   качество задач и планов зависит от полноты знаний, а не от скорости создания карточек.
2. **Создать задачи на основании знаний.** Организовать работу на досках продукта
   и приложений, задать критерии приёмки, подзадачи и зависимости, прикрепить документы.
3. **Спланировать, выполнить и проверить.** Собрать планы любого размера — от одной
   задачи, распределить работу по этапам. Выполнить работу и внешние проверки,
   сохранить результаты и ограничения, явно завершить планы с итогом.
4. **Сформировать релиз из выполненных планов.** Выбрать планы целиком и зафиксировать
   выпуск. Сейчас релиз — проектная запись с `planIds`; принадлежность приложению
   остаётся целевой, ещё не реализованной возможностью.

Это рекомендуемый порядок работы. Источник знаний — содержание записей и документов;
контекст показывает отношения для агента и визуализации, но не заменяет чтение содержания.
Relay не запускает агентов, тесты или CI/CD: статус задачи и запись о выпуске
не доказывают реального результата.
[Назначение продукта](docs/PRODUCT.md) · [Подробный рабочий процесс](docs/guides/WORKFLOW.md).

## Интерфейсы и данные

**Core** содержит всю предметную логику. **Web** — интерфейс людей, **CLI** и **MCP** —
интерфейсы прежде всего для агентов. **Server** обеспечивает сетевую доставку через
HTTP API и раздаёт Web. CLI работает напрямую с Core или через сервер;
MCP требует работающего Server. Покрытие интерфейсов неодинаково — доступность действий
проверяйте в [матрице возможностей](docs/CAPABILITIES.md).

Данные хранятся в JSON рядом с кодом, по умолчанию в `.relay`. Режим local обслуживает
один проект; workspace объединяет подключения к независимым проектным базам.
[Архитектура](docs/ARCHITECTURE.md) · [Конфигурация](packages/project-runtime/docs/CONFIGURATION.md).

## Быстрый старт

Нужны Node.js 22+ и npm. Из корня своего проекта выполните по порядку:

```bash
npx skills add oim-dev/relay
npx @oim-dev/relay-cli init
npx @oim-dev/relay-server --open
```

В установщике выберите скилл Relay и своего агента. Проверьте, что скилл доступен
в агентской среде; при необходимости обновите список навыков или начните новую сессию.
`init` создаст `.relay/config.json` и хранилище проекта. Server откроет Web по адресу
**http://127.0.0.1:4700**; оставьте его терминал открытым. Передайте агенту ТЗ
и начните со сбора знаний по рабочему циклу выше.

CLI доступен из другого терминала в том же каталоге. При необходимости машинного
разбора используйте `--format json`, для справки — `--help`.
Команды `npx` загружают опубликованные пакеты, которые могут отличаться от исходников ветки.
[Первый запуск и проверка подключения](docs/guides/GETTING_STARTED.md) ·
[Диагностика и восстановление](docs/guides/RECOVERY.md).

### MCP — необязательный интерфейс агента

Если ваш клиент использует MCP, при работающем Server запустите в отдельном терминале
из того же каталога проекта:

```bash
npx @oim-dev/relay-mcp
```

Добавьте в клиент адрес **http://127.0.0.1:4710/mcp** с транспортом **Streamable HTTP**.
Обновите список инструментов и проверьте доступные проекты через `projects_list`.
[Подключение и инструменты MCP](apps/mcp/docs/MCP.md).
