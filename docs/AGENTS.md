# Работа с документацией Relay

Применяй корневой `AGENTS.md`; если он не передан средой, прочитай его.
Перед изменением страницы прочитай [правила документации](DOCUMENTATION.md)
и выбери канонического владельца через [библиотеку](README.md).

- Общие предметные знания храни в `docs`, интерфейс и устройство приложения или пакета —
  у его владельца. Для таких изменений прочитай также применимые `AGENTS.md` владельца.
  Не создавай вторую копию контракта, архив, завершённое ТЗ или журнал исполнения.
- Различай принятое требование, предложение, устройство по коду и выполненную проверку.
  Сверяй утверждения с текущими схемами, справкой и операциями; не отменяй требование
  молча из-за расхождения реализации и не обновляй дату прежней проверки.
- Для новой или изменённой возможности актуализируй [матрицу](CAPABILITIES.md):
  меняй только подтверждённые ячейки Core и интерфейсов, обозначай пробелы.
  Целевое приложение или релиз в требованиях не доказывает фактическую реализацию,
  доступность интерфейса или развёртывание.
- Сохраняй смысл, происхождение и навигацию при переносах. Проверяй путь читателя:
  назначение → действие → результат → исправление ошибки; пример проверяй отдельно
  от форматирования и наличия ссылки.
- Будущий автономный пользовательский скилл собирается из канонических знаний.
  Это не утверждение об актуальности текущего bundle: без отдельного поручения
  не переписывай `packages/relay-skill`, готовый скилл и установленные копии.
- Формат и ссылки проверяй адресно: `pnpm exec prettier --check <пути>`,
  `git diff --check`, `pnpm run docs:check`. Точный запуск и helper для выбранных
  страниц — в [инструкции разработки](../scripts/README.md#сборка-и-проверки).
  При параллельном переносе согласуй общую проверку после готовности связанных файлов;
  сообщи о недоступных целях ссылок, не маскируй их выдуманным содержанием.
