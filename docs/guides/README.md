# Пользовательские руководства Relay

Relay хранит требования, документы, задачи и результаты проекта так, чтобы человек
и агент могли продолжать одну работу. Человек обычно работает в Web, агент — через
CLI через npx с читаемым выводом. MCP — только по запросу пользователя при проверенном
окружении. Интерфейсы обращаются к одним проектным данным; Server и ссылка на Web UI
нужны человеку для наблюдения за работой агента.

Начните с нужного сценария:

| Задача                                      | Руководство                                             | Результат                                                                 |
| ------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------- |
| Поднять Relay в пустом каталоге             | [Первый запуск](GETTING_STARTED.md)                     | CLI читает проект, Server работает, пользователь получил ссылку на Web UI |
| Внедрить память в существующую кодовую базу | [Существующий проект](ADOPT_EXISTING.md)                | Проверенные знания и согласованная дальнейшая работа                      |
| Подключить MCP, запускаемый клиентом        | [Проектные MCP-конфиги](../../apps/mcp/docs/CLIENTS.md) | Настройка в проекте, перезапуск и проверка инструментов                   |
| Сохранить понятные требования и факты       | [Полезное содержание](CONTENT.md)                       | Знания, понятные без исходного чата                                       |
| Пройти путь от пустой базы и ТЗ до выпуска  | [Рабочий цикл](WORKFLOW.md)                             | Знания, задачи, выполненные планы и состав выпуска                        |
| Разобраться с ошибкой без потери данных     | [Восстановление](RECOVERY.md)                           | Проверенное состояние и безопасный следующий шаг                          |

Это маршруты работы, а не копии контрактов. Значения сущностей и ограничения находятся
в [предметных правилах](../domain/README.md), доступные действия — в
[каталоге возможностей](../CAPABILITIES.md). Точные параметры установленной CLI-команды
показывает `--help`, инструменты MCP — discovery подключённого сервера.

Полные пользовательские справочники находятся у интерфейсов:
[CLI](../../apps/cli/docs/CLI.md), [MCP](../../apps/mcp/docs/MCP.md),
[REST API](../../packages/server-runtime/docs/API.md) и [Web](../../apps/web/docs/USAGE.md).
Правила выбора конфигурации, проекта и транспорта собраны в
[конфигурации](../../packages/project-runtime/docs/CONFIGURATION.md).

В примерах различаются ожидаемый результат действия и реально выполненная проверка.
Созданная задача, статус `done` и зарегистрированный релиз не доказывают, что внешние
тесты или развёртывание состоялись. После записи перечитайте содержание и отношения;
если ответ потерян, сначала выясните состояние, а не повторяйте запись вслепую.
