# Первый запуск Relay

Этот маршрут устанавливает продуктовый скилл выбранному агенту, создаёт локальную
базу Relay в вашем проекте и подключает Web, CLI и MCP. Нужны Node.js 22+, npm,
доступ к источнику скилла и npm registry, свободные порты `4700` и `4710`.
Команды выполняются из корня пользовательского проекта — пустого или уже содержащего код.
Примеры предполагают настройки по умолчанию; альтернативы описаны в
[правилах подключения](../domain/PROJECTS.md) и [восстановлении](RECOVERY.md).
`npx` загружает опубликованные пакеты, а не код из checkout Relay.

## 1. Установите скилл выбранному агенту

В терминале из корня своего проекта выполните:

```bash
npx skills add oim-dev/relay
```

В установщике выберите скилл Relay и того агента, с которым будете работать.
После установки проверьте, что навык Relay доступен в этой агентской среде.
Установка файлов не гарантирует автоматической загрузки инструкции в уже открытой
сессии: при необходимости обновите список навыков или начните новую сессию по правилам
своего клиента. Это установка продуктового скилла, не команда `skills:install`
для разработки Relay.

## 2. Инициализируйте Relay в проекте

В том же корне пользовательского проекта выполните:

```bash
npx @oim-dev/relay-cli init
npx @oim-dev/relay-cli config get
npx @oim-dev/relay-cli boards
```

Ожидаемый результат: создан `.relay/config.json` и проектное хранилище рядом с ним;
`config get` показывает выбранные пути, `boards` — системные доски `product`
и `infrastructure`. `init` не заменяет существующие данные. Инфраструктурная доска
создаётся, но в базовом [рабочем цикле](WORKFLOW.md) пока не используется.

## 3. Откройте Web

В том же каталоге запустите сервер и оставьте терминал открытым:

```bash
npx @oim-dev/relay-server --open
```

Ожидаемый результат: сервер сообщает адрес, браузер открывает
`http://127.0.0.1:4700/`. Если браузер не открылся, перейдите по адресу вручную.
Это режим **local**: один проект, без выбора из реестра. Серверный автор по умолчанию
в этом запуске — `human`. Комментарии имеют собственную атрибуцию: оператор явно
подписывает их при отправке. Имя автора обозначает происхождение записи, а не
подтверждение личности и не результат проверки.

## 4. Проверьте CLI и общую базу

Откройте второй терминал в том же каталоге. По умолчанию CLI обращается к локальной
базе напрямую через directCore, а Web — через Relay Server. При одном текущем каталоге
и настройках по умолчанию они находят один `.relay/config.json` и используют одну базу;
для этого CLI не требуется `--server-url`.

Следующая задача — необязательная проверка подключения интерфейсов, не начало
продуктовой работы вместо сбора знаний. Если подходящая задача уже есть, прочитайте её
без создания новой; иначе для проверки выполните:

```bash
npx @oim-dev/relay-cli task list
npx @oim-dev/relay-cli --actor human task create --board product --title "Проверить первый запуск" --description "Открыть одну и ту же задачу в Web, CLI и MCP."
npx @oim-dev/relay-cli task list
```

Сохраните ID и ключ из ответа создания. На новой нетронутой базе ключ первой задачи
обычно `PRODUCT-1`; если ответ дал другой ключ, используйте его:

```bash
npx @oim-dev/relay-cli task get PRODUCT-1
```

Ожидаемый результат: полное описание, ID и ревизия задачи доступны для чтения;
та же задача видна на доске продукта в Web. Для машинного разбора добавляйте
`--format json`: человеческую таблицу не следует разбирать как контракт данных.
Агент при собственных изменениях задаёт своего автора, например `--actor agent`;
альтернатива — переменная `RELAY_ACTOR`.

Если нужно отдельно проверить CLI именно через HTTP, используйте необязательный вариант:

```bash
npx @oim-dev/relay-cli --server-url http://127.0.0.1:4700 task list
```

## 5. Подключите MCP

В третьем терминале из того же корня проекта запустите HTTP MCP,
оставив Relay Server работающим:

```bash
npx @oim-dev/relay-mcp
```

MCP находит конфигурацию проекта и подключается к адресу Relay Server из неё;
при стандартных настройках это `http://127.0.0.1:4700`. В отличие от CLI, MCP
не использует directCore и требует работающего Server.

В своём агентском клиенте добавьте MCP-сервер с транспортом **Streamable HTTP**
и URL `http://127.0.0.1:4710/mcp`. Это HTTP-подключение, не команда stdio;
формат настройки зависит от клиента. Обновите discovery инструментов и вызовите:

```text
projects_list({})
board_task_get({ reference: "PRODUCT-1" })
```

Замените ключ на прочитанный на предыдущем шаге. Ожидаемый результат:
`projects_list` сообщает local, `board_task_get` возвращает ту же задачу.
Для local поле `project` можно опустить. При записи через MCP агент передаёт
`actor` в аргументах действия; автор Web не назначается агенту автоматически.

Успех запуска процесса ещё не означает успешного подключения клиента: проверьте
именно discovery и чтение задачи. Если они не работают, используйте
[проверку подключения](RECOVERY.md). Для завершения остановите MCP и Server
через `Ctrl+C` в их терминалах. Данные проекта остаются на диске.

## Отдельный пример: два проекта в workspace

Workspace — реестр независимых проектов, а не объединённая база. В другом пустом
каталоге сначала инициализируйте **оба** проекта:

```bash
npx @oim-dev/relay-cli --config ./alpha/.relay/config.json init
npx @oim-dev/relay-cli --config ./beta/.relay/config.json init
```

Создайте рядом с каталогами `alpha` и `beta` файл `relay.workspace.json`:

```json
{
  "version": 1,
  "mode": "workspace",
  "projects": {
    "alpha": { "path": "./alpha" },
    "beta": { "path": "./beta" }
  },
  "server": { "port": 4700, "url": "http://127.0.0.1:4700" }
}
```

Пути разрешаются относительно этого файла. Остановите Server и MCP предыдущего примера,
если они занимают нужные порты. Из каталога с `relay.workspace.json` запустите общий сервер:

```bash
npx @oim-dev/relay-server --open
```

В других терминалах из того же каталога выберите проект каждой CLI-команды явно
и запустите MCP для общего сервера:

```bash
npx @oim-dev/relay-cli --project alpha task list
npx @oim-dev/relay-cli --project beta task list
npx @oim-dev/relay-mcp
```

Реестр находится по текущему каталогу. Для запуска из другой области, где нужный файл
не находится поиском, добавьте `--config /путь/relay.workspace.json`.
В Web выберите `alpha` или `beta`. В MCP сначала вызовите `projects_list({})`,
затем передавайте `project: "alpha"` или `project: "beta"` во всех проектных
операциях. Даже если в реестре останется один проект, workspace требует выбора.
Ожидаемый результат: оба клиента видят один реестр, а списки задач относятся
к двум разным базам. Одинаковый ключ задачи в этих базах не означает одну задачу.
