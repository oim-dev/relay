# Единый движок и переносимые контракты основных сущностей

Решение 20 сентября 2026. Основание: пользователь согласовал девять основных видов,
общий API и адресацию ключами/ID с неизменной внутренней идентичностью.

## Решение

Переносимые схемы и определения находятся в contracts, обработчики и хранение — в Core.
Граф получает карточки из общего каталога и использует его резолвер. CLI/MCP/Web работают
с одинаковыми операциями; SDK получается из OpenAPI. Схемы не объявляются повторно в Web.

Резолвер ищет назначенный адрес в проекте. Префикс определяет политику выдачи ключей,
а не идентичность и не доказательство вида. Алиасы сохраняют старые ссылки, ID — отношения.
Все изменения проходят общий конвейер и существующие предметные правила под одной блокировкой.

## Причины и последствия

- Одна схема устраняет независимое редактирование DTO, серверных полей и валидаторов Web.
- Регистрация обработчика сохраняет предметные инварианты: произвольное обновление JSON
  не может обойти проверку зависимостей или назначить вычисляемую готовность.
- Реестр видов и динамические пространства ключей разделены: новая доска не требует
  выпуска нового enum задач или SDK.
- Сохраняются существующие данные и транзакции. Полная унификация физического хранения
  и индекс всех сущностей требуют отдельного измерения; общий API сам не устраняет сканирование.
- Версия контракта, дисковая версия и ревизия записи имеют разный смысл. Старые записи
  читаются кодеками, новые поля хранения публикуются версионированной записью.
