# JSON-хранение продуктовых записей

**Статус: принятое устройство.** Основание: уточнение пользователя при первом внедрении и последующий
[единый стандарт](../../development/INTERFACE-STANDARD.md). Эта карточка собрана
19 сентября 2026 года; она не меняет дату исходных решений.

Требования к сохранению истории и квитанций ниже **заменены**
[запретом истории операций](../../reference/STORAGE.md). JSON, точный Markdown,
ID и текущие предметные данные сохраняют своё назначение; исходные основания оставлены.

## Контекст и выбор

Пользователь потребовал хранить все постоянные записи в JSON и принимать многострочный
Markdown напрямую. Первоначальное предложение отдельных Markdown-файлов было заменено.
После уточнения дисковой схемы Markdown хранится массивами строк, а внешний API
продолжает принимать строки. Преобразование принадлежит кодеку хранения.

Состав одного приложения — агрегат `scope`: замена всех его контрактов публикуется
одним JSON под общей блокировкой. Ревизия защищает запись, версия продукта —
согласованность состава с прочитанным каталогом. Квитанция повтора сохраняется вместе с результатом.

## Последствия

- Нет отдельных файлов Markdown и транзакции между текстом и метаданными.
- Дисковая схема и DTO имеют независимые версии; менять API ради кодека не требуется.
- Миграция обязана сохранять ID, ссылки, тексты, историю и повторяемость операции.
- Исторический план со строковым Markdown описывает прежний этап, а не текущую схему.
- `basis` подтверждает актуальность текста контракта, но не заменяет тест или поставку.

Точные поля, лимиты и миграция: [справочник](../../reference/PRODUCT.md).
