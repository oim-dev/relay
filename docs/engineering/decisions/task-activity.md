# Отдельная лента обсуждений и истории задачи

**Принято 21 сентября 2026.**

**Заменено решением об отказе от общего аудита.** В [формате 3](../../reference/STORAGE.md)
полные комментарии и квитанции находятся в файле владельца; отдельной ленты аудита нет.
Ниже сохранены основания прежнего решения, а не инструкция для нового хранения.

Хранение и объём истории уточнены 23 сентября в [решении о компактных сегментах](compact-history.md):
полные комментарии сохраняются, Markdown-правки отражаются фактом изменения.

## Причина

Файл задачи читается при загрузке канбана и ограничен 16 МиБ. Хранение полного обсуждения
и прежних Markdown-описаний в этом же файле увеличивало бы каждый GET списка и ограничивало
длительность сопровождения задачи. Запись истории только в HTTP-контроллере пропускала бы CLI local.

## Решение

Правила публикации и формирования событий принадлежат Core. Лента хранится отдельно
по постоянному ID задачи; компактные страницы отделены от полных значений.
Её файлы включены в долговечные намерения канбана и графа под общей блокировкой.
У публикации собственный sequence и квитанция; она не меняет содержательную ревизию
задачи и потому не конфликтует с редактированием её описания.

Ревизия карточки продолжает защищать содержание/положение/критерии. Краткие events
сохраняют совместимость entity_history; подробные данные имеют отдельные операции.
Версии 1–4 читаются без записи, первая новая операция переносит известные старые события
и фиксирует исходный снимок. Отсутствовавшие прежние значения не восстанавливаются.

## Следствия

Количество файлов растёт с событиями, но канбан не читает их Markdown. Списки используют
курсор снимка; SSE передаёт сигнал перечитывания, а не сами данные. До чтения должны
восстанавливаться оба владельца WAL. Обратные связи/блокеры дают события в затронутых
задачах без искусственного изменения их содержательной ревизии.
При внешней ручной правке JSON достоверная история не гарантируется.
