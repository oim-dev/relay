# Состояние реализации

Разделы фиксируют устройство и результаты проверок на указанные даты.
Прежние результаты не подтверждают текущее окружение; новое изменение требует адресной проверки.

## Упрощение планирования: 25 сентября 2026

В планировании рабочее дерево использует два вида: `work-plan` и `release`.
Этапы — массив внутри плана с локальными ID и общей ревизией; отдельного вида,
ключей и целей документов у этапов нет. Core сохраняет только явно выбранные `taskIds`
и после продуктовой записи явно согласует отдельные связи задача → план.
Релиз хранит `planIds` и реквизиты выпуска; технические виды и API снимков удалены из кода.
Состав и готовность вычисляются по актуальным планам даже после выпуска.

Версии данных двух видов — `dataVersion=2`; маркер базы `storage.json` остаётся
`schemaVersion=2`. Миграция прежних планов/релизов исключена по решению пользователя;
условия адресного сброса — в [контракте хранения](../../reference/STORAGE.md#планы-и-релизы).

Core, контракты и потребители переведены на эту модель. Итоговый Core — 164/164,
включая planning12/12; REST37/37, CLI40/40, MCP12/12, project-runtime2/2.
SDK — 157 операций и 739 моделей. Сборки и сквозная приёмка завершены, включая
32 сочетания темы/ширины и исправление утечки SSE при BFCache. Production-повтор
подтвердил отсутствие AbortError и лишних потоков. История, ветки и дерево задач Web — следующие этапы.

## Предыдущая интеграция: проверено 24 сентября 2026

Интеграция `43d683b` подключила PlanningService/ReleasesService, общие операции Core,
REST/SDK, local/HTTP Backend, CLI/MCP и Web. Её прежняя модель хранения заменена
упрощением выше. Результаты того этапа не подтверждают приёмку текущей модели.

Действующие контракты: [планирование](../../reference/PLANNING.md),
[релизы](../../reference/RELEASES.md). Обязательный запрет исполнения без начатого плана
остаётся отдельной согласованной работой.

## Прогресс: реализация 24 сентября 2026

В рабочей копии поверх `bff35fe` добавлены [ProgressService](../../../packages/core/src/application/progress/service.ts),
шесть предметных обработчиков и отдельных схем Contracts, контроллер `/progress`, SDK,
local/HTTP Backend, CLI/MCP. [Контракт](../../reference/PROGRESS.md).
Фактическое выполнение учитывает критерии и транзитивные обязательства задач; прежние
блокеры и продуктовый каскад используют те же правила. Колонки автоматически не меняются.

Web читает серверные показатели вместо подсчёта `done`: продуктовая цель показывает
готовность, причины и переходы, редактор задачи — фактическое выполнение; приложения —
раздельные счётчики. Чтение под блокировкой Workspace, страницы версионированы, итоги полные.
Прогресс не пишет данные/связи, формат хранения не изменён. Производительность отложена;
полные чтения и существующие проекции каталога сохранены. В последующей интеграции добавлены
отдельные прогрессы плана и релиза, а ответ задачи дополнен текущим участием в планировании.

Core: 152/152, REST: 35/35, CLI: 37/37, MCP: 11/11; типизация и сборки прошли.
Браузерная приёмка выполнена на временной базе, обе темы и четыре ширины.
Ожидаемое поведение — в [спецификации прогресса](../../product/PROGRESS.md).

## Планирование: сверка 24 сентября 2026

Первоначальный UI-прототип поверх `41237e0` заменён постоянной интеграцией в `43d683b`:

- `plans` / `plans/:planId` подключают [композицию планов](../../../apps/web/src/compositions/widgets/planning-workspace/planning-workspace.tsx).
  `releases` / `releases/:releaseId` — [самостоятельный экран](../../../apps/web/src/compositions/screens/releases/releases.screen.tsx).
  В планах нет релизного типа и его полей; релиз хранит собственный статус и выбранные планы.
- [Планирование](../../../apps/web/src/domains/planning/index.ts) и
  [релизы](../../../apps/web/src/domains/releases/index.ts) используют общий SDK:
  GET через SWR, POST-проверка выбора — через отдельное состояние `useReleasePreview`.
  Подтверждённые данные хранятся сервером; sessionStorage используется для черновиков
  `server-v2` и неподтверждённых операций с ключами `v2`. Неподключённые
  `planning-demo`/`releases-demo` удалены. Подробности текущего механизма —
  [реализация приложений](applications.md#две-сущности-планирования-25-сентября-2026).
- [Реестр видов](../../../packages/contracts/src/entities.ts) содержит план и релиз;
  после упрощения 25 сентября этапы находятся внутри плана.
  Состав принадлежит планированию, а текущее участие задачи возвращает предметный прогресс.
  Колонка, доска и `parentId` задачи сохраняют правила канбана.
- В Web сохранились схема и компоненты прежнего прототипа `product-work-list` /
  `PRODUCT_WORK_SCHEMA`. Внешних потребителей виджета в `apps/web/src` не найдено;
  [адаптер постоянного продукта](../../../apps/web/src/domains/product-demo/helpers/create-product-view.ts)
  возвращает `work: []`. Эти остатки не являются действующей реализацией планирования.

UI проверен через agent-browser на временных проектах: обе темы, четыре ширины,
создание/редактирование, черновики, выбор, пустота, сеть, конфликты, маршруты и пагинация.
Пользовательская модель и вопросы: [направление](../../product/DIRECTION.md#связь-продукта-с-работой).
