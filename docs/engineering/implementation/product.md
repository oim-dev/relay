## Реализованное покрытие

- Паспорт, фичи, сценарии, приложения, составы и документы — отдельные постоянные записи.
- Состав одного приложения публикуется атомарно, контракты сохраняют ID при снятии участия.
- Готовность фич, сценариев и реализаций приложений вычисляется в `application/product/task-progress.ts`
  по типизированным обязательствам задач и каскаду активных имплементаций к их целям. Проекция
  общая для state, каталога продукта и каталога сущностей; после чтения файлового индекса
  статусы накладываются заново. Проектная readiness.status агрегирует имплементации
  и существующие прямые задачи; пустая активная имплементация не готова;
  participants/completed показывают участие приложений, stale=0. Сохранённый basis исторический.
  Версия каталога учитывает вычисляемые статусы; версия продукта для CAS текстов
  остаётся отпечатком продуктовых записей, чтобы перемещение задачи не конфликтовало
  с редактированием описания реализации или состава.
  Общий предметный граф задаёт рёбра FI → активные SI своего applicationId/featureId,
  проектный сценарий → его SI, проектная фича → свои FI и проектные сценарии.
  Статусы вычисляются снизу вверх с кешем узлов; productTarget обходит тот же граф
  с множеством посещённых адресов. Это сохраняет дедупликацию и согласованность состава.
- Документы имеют типизированные проверяемые ссылки и обратные представления.
- Обзор, список, состояние и контекст доступны через общие операции; контекст объясняет включение.
- Ревизии, версия продукта, автор и ключ повтора защищают запись и повторный запрос.
- Web использует постоянные данные, черновики и защиту форм; ручной статус общего сценария убран.
- Страница реализации показывает полный исходный Markdown, вклад, открытые задачи
  и прямые зависимости. Прогресс читает отдельный серверный обработчик по виду цели,
  показывает полные счётчики, фактическую готовность и страницы причин;
  список задач — 40, зависимости — 5. Ручной статус отдельного вклада убран из редактора.
- Проектные страницы используют `widgets/product-requirement` с полным Markdown,
  задачами и контекстом. Общий `product-dependencies` поднят из реализации приложения;
  `product-contributions` адресно читает только выбранную цель через entities + пакетный
  продуктовый каталог, по 5 реализаций. Сценарии фичи — компактные строки по 10.
- Приложение имеет обязательный неизменяемый slug и собственную доску. Создание приложения
  через общую операцию создаёт контейнер доски с восстановлением после прерывания.
  Миграция досок не добавлена; существующие приложения без slug не поддерживаются новым
  контрактом.

## Дисковый и внешний контракты

JSON-хранилище находится в `product` рядом с конфигурацией проекта. Дисковая схема v3
кодирует Markdown массивами строк; приложения и реализации вложены по ID. Состав
содержит ссылки и прежнюю историю, описание реализации хранится один раз. DTO v1
сохраняет строковые Markdown-поля. Совместимое чтение v1/v2 и возобновляемая миграция
не меняют ID, ревизии, тексты и историю. Точная структура, лимиты и ошибки принадлежат
[справочнику продукта](../../reference/PRODUCT.md), причины — [решению](../decisions/product-storage.md).

Разделение ID и ключей, самостоятельные реализации и восстановление составной записи:
[решение об идентичности](../decisions/product-identity.md).

## Ограничения

Сквозные пути сценарий → реализации → задачи → материалы доступны через
[граф сущностей](relations.md) только при явно сохранённых связях Core. Вычисление
domain-проекций удалено; продуктовые линки ждут подключения к движку отдельным этапом.
productTarget расширяет фичу/сценарий до её активных реализаций перед фильтрацией задач;
произвольные рёбра графа не участвуют в этом выборе.

Рабочее окно канбан-задачи использует существующий `product/context` для чтения
общих требований, контрактов и документов. `domains/product` предоставляет адаптер,
SWR-хук и адресные варианты выбора. Постоянные типизированные productLinks принадлежат
Core board-tasks; создание/обновление проверяет цели под общей блокировкой. Web, CLI
и MCP читают одни связи; требования агент запрашивает адресно через product_context.
Обратный список фильтруется productTarget и показывается на страницах фич/сценариев/контрактов.

- Постоянные планы и релизы реализованы отдельными владельцами, используют существующие
  задачи и продуктовые цели. Релиз сохраняет ссылки на планы и факт выпуска;
  требования и материалы читаются из актуальных записей без копирования.
  [Состояние и проверки](README.md#упрощение-планирования-25-сентября-2026).
  Обзор и общий раздел истории Web остаются заглушками; прежние записи жизненного цикла удалены.
- Готовность по контрактам не связывает отметку с фактическим тестом, коммитом или поставкой автоматически.
- Каталоги и редактор всего состава ещё получают полный снимок. Сценарии и реализации
  читаются адресно; задачи выбирают цели через компактный индекс с продолжением.
  Отдельная реализация проверяет свою ревизию, массовый состав — версию всего продукта.
- Общие операции удаления/архивирования записей и переноса сценариев не заявлены как реализованные.
