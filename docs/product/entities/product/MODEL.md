# Модель продукта

[Сущность «Продукт»](README.md) → Модель

## Область и идентичность

В проекте один продукт. Переименование паспорта не меняет регистрацию проекта.
Записи имеют постоянные ID; название, путь страницы и текст не определяют идентичность.
Переключение проекта переключает все данные. Межпроектные связи не создаются.

Продукт принадлежит выбранному проекту, фича — этому продукту. Бекенд сохраняет
соответствующие связи Core: фича → `part-of` → продукт → `part-of` → проект.
Паспорт может быть ещё не заполнен: продукт уже существует и связан с проектом.
Заполнение и переименование сохраняют постоянные адреса и ID этих связей.

```text
Продукт
├── Паспорт
├── Возможности (фичи)
│   └── Сценарии
├── Приложения
│   └── Контракты участия в фичах и выбранных сценариях
└── Документы с независимыми типизированными связями
```

## Сущности и содержание

| Сущность   | Назначение и содержание                                                                    |
| ---------- | ------------------------------------------------------------------------------------------ |
| Паспорт    | Название, краткое описание, полный Markdown о назначении, пользователях и границах         |
| Фича       | Постоянная возможность: название, краткое описание, общий Markdown-контракт                |
| Сценарий   | Один родитель-фича, название и Markdown конкретного действия и результата                  |
| Приложение | Название, назначение, Markdown и тип: frontend, backend или internal                       |
| Контракт   | Приложение, фича и при необходимости сценарий, собственные заголовок, Markdown и состояние |
| Документ   | Название, краткое описание, Markdown, тип и набор областей применения                      |

Типы документов: техническое задание, описание, правила, решение. Краткое описание
и связи документа могут быть пустыми. Имена — однострочные; краткие описания — обычный
многострочный текст; полное содержание — Markdown. Общий сценарий не имеет ручного статуса.

Фичи и сценарии не копируются в приложения. Иерархия двухуровневая; произвольных
подфич и подсценариев нет. Сценарий принадлежит ровно одной фиче. Задача реализации
является отдельной сущностью, даже если её название совпадает со сценарием.

## Приложения и контракты

Приложение — логическая программная часть продукта, а не проект реестра Relay.
Вся его выбранная реализация образует состав `scope`.

- Для одной пары приложение/фича существует один активный общий контракт.
- Для участия в сценарии нужен общий контракт его фичи.
- Выбор фичи не означает выбор всех сценариев.
- Допустимы фича без выбранных сценариев и приложение без состава.
- У каждого контракта собственные текст и состояние; изменение общих требований
  не переписывает описание приложения.
- Снятие участия сохраняет идентичность контракта и существующие ссылки.

## Документы и области

Документ может ссылаться на продукт целиком, фичу, сценарий, приложение или конкретный
контракт реализации. Выбор областей независим: сценарий не включает фичу, контракт
не включает приложение. Пустые связи не означают связь со всем продуктом.

Ссылки проверяются по существующим записям выбранного проекта. Один документ остаётся
одной записью при нескольких связях. Подписи берутся из актуальных целей.
Документ не создаёт участие приложения. Правила снятых контрактов:
[поведение](BEHAVIOR.md#связи-документов).

## Граница с жизненным циклом

Продукт служит постоянной основой работы. Новые канбан-задачи имеют явные связи
реализации с фичами, сценариями и контрактами приложений. Готовность каждой цели
поднимается от задач к имплементациям приложений и далее к их проектной фиче/сценарию;
прямые продуктовые задачи учитываются дополнительно. Правила полного состава — в [поведении](BEHAVIOR.md).
Это не заменяет проверки результата участниками. Постоянные
[планы](../../../reference/PLANNING.md) организуют существующие задачи по этапам и
сохраняют область воздействия. Самостоятельные [релизы](../../../reference/RELEASES.md)
выбирают планы целиком и сохраняют факт выпуска. Планы, задачи, требования и материалы
читаются из актуальных записей своих владельцев.
Прежний паспорт жизненного цикла удалён. Обязательное основание исполнения задач
начатым планом остаётся следующим этапом; направление описано в [DIRECTION.md](../../DIRECTION.md).
