# Задачи канбан-досок

Модель задач [досок](../boards/README.md). Точный контракт — в [справочнике канбана](../../../reference/KANBAN.md).
Прежняя числовая модель удалена; действующие задачи принадлежат отдельным доскам.

## Минимальная задача

Заголовок — однострочный текст, описание — Markdown. Оба поля могут быть пустыми.
При создании выбирается доска и, при необходимости, колонка; по умолчанию — «Входящие».
Система назначает ID из 8 символов, ключ с префиксом, порядок, ревизию, авторов и даты.
Нажатие «Создать» сразу сохраняет пустую задачу и открывает её редактирование с номером.
Закрытие окна не отменяет создание: пустая карточка остаётся как «Без названия».
CLI/API передают заполненные поля при создании одним запросом.
Префикс задаётся при создании приложения: `WEB`, `API`; системные — `PRODUCT`, `INFRA`.

Ключи последовательны внутри доски и не переиспользуются. При переносе на другую доску
задача получает новый ключ, сохраняя ID и связи. Старый ключ продолжает разрешаться
в ту же задачу. Переименование приложения не меняет slug и префикс.

## Критерии приёмки

Задача содержит до 100 собственных критериев приёмки. Каждый имеет постоянный ID,
обязательный однострочный заголовок, краткое многострочное описание обычным текстом
и полное описание Markdown. Краткое и полное описания могут быть пустыми. Новые критерии
не выполнены. Порядок добавления сохраняется; выполнение не перемещает строку.

Человек или оркестратор добавляет критерии при создании задачи либо адресно позднее.
Отметка выполнения сохраняет автора и время; её можно снять. Изменение любого текстового
поля снимает прежнюю отметку, одинаковый текст её сохраняет. Все операции защищены
ревизией задачи и идентификатором корреляции. Готовую задачу сначала возвращают из done.

Невыполненные критерии запрещают done, но не меняют blocked/ready и не мешают началу
работы или проверке. canComplete объединяет критерии, подзадачи и зависимости.
Все отметки не завершают задачу автоматически. Пустой набор не добавляет ограничений.
Список читается по 20 с продолжением и версией; полный Markdown — адресно по ID критерия.

В Web раздел называется «Критерии приёмки»: счётчик выполнения, чекбоксы и список
заголовков с кратким описанием. Нажатие на текст раскрывает полное описание внутри
окна задачи. Добавление и редактирование сохраняются явно, отметка — сразу.

## Работа и колонки

1. Входящие (`inbox`) — входящее поручение или идея.
2. К выполнению (`ready`) — сформулированная работа.
3. В работе (`in-progress`) — выполнение.
4. На проверке (`review`) — результат ожидает проверки.
5. Готово (`done`) — завершённый результат.

Отмена (`cancelled`) не является успешным результатом зависимости. Блокировка —
вычисляемый признак, отдельная колонка для неё не нужна. Начать подготовительную работу
можно с блокерами; завершить задачу с ними нельзя. Возврат зависимости из готовых
немедленно меняет вычисляемые блокеры зависимых задач, но не перемещает их автоматически.
Настройка произвольных колонок пока не предусмотрена.

## Связи для человека и оркестратора

У задачи нет отдельного типа «Эпик». Крупная работа организуется обычным родительством
и подзадачами. Создание с parentId сохраняет подзадачу одной атомарной операцией.
В карточке Web подзадача добавляется выбором существующей карточки: отдельной
формы создания подзадачи нет. Раздел «Подзадачи» показывает прямых детей единым списком
без групп и выбора типа связи. Каждая подзадача обязательна для завершения родителя.
Добавление компактное: селекторы доски и задачи в одной строке (на телефоне друг под другом).
По умолчанию выбрана текущая доска. Сохранение назначает текущую задачу родителем
выбранной; при замене прежнего родителя форма сообщает об этом до сохранения.
Открытие формы связи не раскрывает списки автоматически; dropdown задач открывается
по клику, вводу или клавиатурной команде в самом поле.
Селектор задач открывает список, ввод названия или ключа сужает его; сервер ищет
по заголовку, ключам и ID, не по Markdown. Задачи done и cancelled исключены до
пагинации. Продолжение списка доступно внутри dropdown. Уже связанные задачи
сохраняются в обзоре независимо от статуса; завершение не удаляет связь.
Смена доски сбрасывает выбранную задачу. Описание раскрывается по запросу;
уже добавленная подзадача отмечается и не добавляется повторно.
Список читает по 40 прямых детей с фильтром `parentId` до пагинации; продолжение
сохраняет родителя. Счётчик готовности относится ко всему списку только после полной
загрузки, до неё показывается число загруженных подзадач относительно общего количества.
Удаление из списка снимает родительство и соответствующую блокировку, сохраняя саму
задачу. Переход к общему графу и контексту из карточки отсутствует: этот интерфейс отложен.

### Реализует в продукте

Задача содержит до 100 явных типизированных целей. Доступность определяется типом её доски:

- продуктовая — только общие фичи и сценарии;
- приложение — только объявленные реализации фич и сценариев собственного приложения;
- инфраструктура — целей реализации нет, блок в карточке отсутствует.

Тип и приложение берутся из доски самой задачи, независимо от названия и фоновой страницы.
Несколько целей допустимы; выбор сценария
не создаёт отдельную связь с фичей. Контракт приложения не копирует общие требования.
Цели проверяются в выбранном проекте, дубли запрещены. Снятый контракт нельзя привязать
заново, но существующая ссылка сохраняется и отмечается в интерфейсе.
Завершение задачи не меняет готовность продуктовой цели. Требования читаются адресно
через адресные операции, а окружение цели — через полный сохранённый граф контекста.
На страницах целей доступны обратные списки задач реализации.
Предварительные выборы прежней версии из sessionStorage автоматически не импортируются.
Несовместимые связи запрещены при создании, замене набора и переносе на другую доску.
Для переноса сначала нужно явно снять такие связи; автоматически они не удаляются.
Прежние записи читаются без миграции. Редактирование содержания и смена колонки
не перепроверяют старые цели; явная замена набора проверяет все оставшиеся связи.

Все ссылки ведут на постоянные ID задач одного проекта, в том числе разных досок.

- Зависит от / блокирует — направленная связь порядка выполнения.
- Связана с — контекст без ограничения выполнения, видимый с обеих сторон.
- Родитель / подзадача — декомпозиция с обязательным результатом ребёнка для родителя.
  Блокировка вычисляется по `parentId`; отдельная копия в `dependencies` не нужна.

Запрещены ссылки на себя, отсутствующие задачи и циклы зависимостей либо родительства.
Новые связи также не могут образовывать смешанный цикл родительства и зависимостей.
Завершение подзадач автоматически не закрывает родителя. Блокеры — прямые зависимости
и прямые подзадачи без фактического выполнения, без повторов; транзитивную причину оркестратор читает
через прогресс этих задач. Отмена подзадачи не снимает блокировку. Добавить незавершённого
ребёнка готовому родителю можно после возврата родителя из `done`. Повторное открытие
ребёнка пересчитывает блокеры, но не перемещает родителя автоматически.
Фильтр `readiness=ready` возвращает задачи из `ready` без блокеров, `blocked` — с блокерами.
Список связей показывает направление, доску, актуальный ключ, колонку и блокировку соседа.

## Web

### Обсуждения и история

Операции и формат — в [справочнике обсуждений и истории](../../../reference/TASK-ACTIVITY.md).
Человек, оркестратор и воркер публикуют сообщения с обязательными заголовком и Markdown.
Web всегда подписывает публикацию «Оператор», агент явно передаёт имя и роль.
Сообщения доступны в любой колонке, не меняют ревизию содержания и готовность задачи.
Первая версия поддерживает публикацию и чтение без правки/удаления опубликованного.

Общий автоматический audit не ведётся: изменение статуса, связей, критериев или текста
не создаёт универсальное событие истории. Полные комментарии с авторством и временем
сохраняются в файле задачи; важные решения и результаты записываются содержательными
сообщениями, а не автоматически выдуманным отчётом. Старый общий аудит не переносится
внутрь задачи. Неизвестные факты не восстанавливаются задним числом.
Списки читаются по 20 с курсором и границей снимка; полный текст доступен адресно.
Табы и закрытие карточки сохраняют несохранённый ввод.

### Представление карточки

Компактная карточка показывает ключ, заголовок и блокеры. Полное содержание открывается
в широком модальном окне по центру; телефон использует полноэкранное окно.
Канонический адрес `/projects/:project/boards/:boardSlug/:taskId` открывает задачу
напрямую и переживает reload/Back/Forward. При переносе ID сохраняется, slug в адресе
обновляется. Старый `/projects/:project/tasks/:id` и адрес с неверной доской перенаправляются
на актуальный адрес. Числовые задачи прежней доски больше не открываются.
Промежуточного маршрута создания нет: один переход после получения номера;
ответ создания заполняет кеш редактора. Сохранение содержания не меняет адрес.
Фон доски не перемонтируется. Обычное открытие показывает читаемый Markdown;
редактирование, перенос и добавление связей включаются явными действиями.
Создание доступно из шапки, колонки и клавишей N.

Рабочее окно имеет обычный и развёрнутый размеры; на телефоне оно полноэкранное.
Карточка содержит табы «Задача» и «Обсуждения». Начальный таб «Задача»
показывает описание, продуктовые цели, критерии и подзадачи. Справа компактные строки статуса и доски: кликабельные
значения открывают меню, выбор сразу сохраняется. Отдельного блока «Детали», рамки,
подложки и формы перемещения нет. Ошибка оставляет подтверждённое значение.
Шапка остаётся на месте; прокручивается содержимое. Смена размера сохраняет редактор.
Шапка содержит ключ задачи и управление окном; хлебные крошки внутри карточки не показываются.
Заголовок и Markdown сохраняются явно; собственная правка связей/положения обновляет
ревизию черновика, не считаясь внешним конфликтом. Внешние изменения по-прежнему
требуют явной сверки. Выбор подзадачи позволяет прочитать полный Markdown кандидата;
существующие подзадачи показываются плоским списком со статусами.

В разделе реализации сохраняются постоянные связи. Выбор содержит только «Фичи»
и «Сценарии»: продуктовые цели или реализации собственного приложения определяет доска.
Поиск по ключу не переключает вид цели. Сохраняются множественный выбор и чтение описания до сохранения.
Полные требования и документы читаются внутри окна. Список целей выбора выводится
порциями по 20 с фильтрами приложения и вида реализации до пагинации,
существующие связи — по 5 с продолжением.

Markdown имеет ровно два состояния: отформатированный просмотр по умолчанию и явное
редактирование исходного текста с подсветкой CodeMirror. Вложенного предпросмотра нет.
Сохранение кнопкой либо Ctrl/Cmd+Enter возвращает просмотр; отмена отбрасывает ввод.
Закрытие окна сохраняет локальный черновик. Поле сохраняет историю отмены при вводе
и обычных обновлениях родителя; загрузка актуального текста явно сбрасывает поле.

Полноширинная доска занимает оставшуюся высоту окна. Заголовок и назначение отделены
от поиска и фильтров; боковые отступы 28px, на телефоне — 14px. Колонки имеют тональную
подложку и независимую вертикальную прокрутку, доска — горизонтальную. Ширина карточек
не меняется при появлении скроллбара. Ключ вторичен заголовку, заголовок превью занимает
до трёх строк; полное содержание остаётся в задаче. Блокеры обозначены текстом.

При переносе локальная проекция удерживает порядок загруженных карточек до завершения
записи и сверки. Поднятая копия имеет измеренные размеры исходной карточки; в целевой
колонке остаётся её место. Отпускание фиксирует положение до ответа сети. Ошибка
показывается явно, затем отображается подтверждённая проекция. Отпускание за пределами
доски отменяет жест. Мышь использует порог движения, сенсорный ввод —
удержание; клавиатура — пробел/стрелки/Escape. Настройка reduced motion сокращает анимации.
Колонку и доску также можно изменить штатной формой в модальном окне.

Черновик содержания и исходная ревизия хранятся в пределах вкладки. При внешнем изменении
ввод не заменяется; пользователь загружает актуальное содержание или явно применяет
свой ввод к новой ревизии. Ошибка записи сохраняет текст; неизвестный исход требует
чтения текущего состояния перед решением о новой записи.
События внешних CLI/MCP-записей перечитывают доску и связи.
После DnD полная карточка обновляется адресно, даже если её окно закрыто и SWR
не имеет подписчика. Повторное открытие показывает статус новой колонки. Обычное
открытие перечитывает кеш; только первоначальный ответ создания используется без второго GET.
Клик по фону, Escape и крестик закрывают окно; несохранённый текст остаётся в черновике.

## Границы и приёмка

Каждая колонка читает по 40 карточек, с полным счётчиком и кнопкой продолжения;
API допускает 1–100. Полный Markdown читается адресно. Каталог связей также постраничный.
Версия защищает продолжение от изменений. Web сохраняет предыдущую проекцию, загруженный
объём и прокрутку; при смене версии ограниченно перечитывает тот же объём целиком.
Подгрузка не заменяет существующие карточки скелетонами, SSE не сбрасывает число страниц.
Пустая колонка отличается от ошибки. Большие записи ограничены размером Markdown и файла.

Приёмка: создание через Web/CLI/MCP, конкуренция номеров, повторы, смена доски со стабильным
ID, циклы, блокеры и отмена, доступность готовой работы оркестратору, Markdown без потерь,
черновики, конфликты, пагинация, SSE, клавиатура, мобильный экран и обе темы.
