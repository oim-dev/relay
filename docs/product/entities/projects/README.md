# Проекты и рабочее пространство

Проект Relay — граница данных, конфигурации, продукта, задач и комментариев. Одинаковые
номера задач в разных проектах не обозначают одну задачу.

## Режимы

- Local открывает один проект через `.relay/config.json`.
- Workspace через `relay.workspace.json` регистрирует несколько независимых баз.
- Workspace с одной регистрацией остаётся workspace: проект указывается явно.
- Имя регистрации и название продукта имеют разное назначение.

## Сценарий выбора

Пользователь или агент получает список проектов, выбирает ключ или постоянный ID и
выполняет операции в этой области. Server закрепляет выбор за запросом, Web — за
маршрутом и состоянием страницы. Глобального изменяемого активного проекта на сервере нет.

При изменении реестра клиенты должны увидеть новый состав без смешения кешей и подписок.
Недоступность одной регистрации не превращает остальные проекты в недоступные.
CLI local может обращаться к ядру напрямую; workspace, Web и MCP используют Server.

## Критерии

Запись в A не изменяет B; выбор проекта сохраняется в продолжении списка; ошибка
неизвестной регистрации понятна; после переключения не появляются поздние ответы
предыдущего проекта. Подробности: [конфигурация](../../../reference/CONFIGURATION.md),
[реализация](../../../engineering/implementation/applications.md).
