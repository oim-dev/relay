# Relay MCP

MCP предоставляет агентским клиентам предметные инструменты Relay. Пакет
`@oim-dev/relay-mcp` запускает отдельный Streamable HTTP-сервис и обращается к
работающему Relay Server через общий REST SDK.

## Подключение

1. Запустить Relay Server с local- или workspace-конфигурацией.
2. Запустить MCP с адресом сервера или конфигурацией подключения.
3. Подключить `http://127.0.0.1:4710/mcp` в агентском клиенте.
4. Прочитать `projects_list`, затем выполнить операцию в нужном проекте.

В local проект можно опустить. В workspace параметр `project` обязателен для
проектных операций даже при одной регистрации. Запуск процесса MCP сам по себе
не добавляет инструменты в клиент. [Настройки](../../../reference/CONFIGURATION.md).

## Возможности агента

Инструменты `task_progress`, `implementation_progress`, `scenario_progress`, `feature_progress`,
`application_progress`, `product_progress` объясняют актуальное выполнение без обхода контекста.
Агент раскрывает источники причин следующими предметными запросами. [Контракт](../../../reference/PROGRESS.md).

| Цель                 | Группа интерфейсов                                                                |
| -------------------- | --------------------------------------------------------------------------------- |
| Выбрать область      | Реестр проектов и контекст проекта                                                |
| Прочитать продукт    | Обзор, список, адресный контекст и структурные замечания                          |
| Изменить продукт     | Предметные операции паспорта, фич, сценариев, приложений, документов и контрактов |
| Выполнить поручение  | Задачи, назначения, отчёты и контекст задачи                                      |
| Вести жизненный цикл | Проектные документы, проверки, приёмки и контрольные точки                        |

Точные инструменты, аргументы и примеры: [MCP](../../../reference/MCP.md),
[продуктовые операции](../../../reference/PRODUCT.md#mcp-и-контекст).

## Контракт инструментов

Имя, описание и аргументы объясняют действие по-русски. Значимые поля — название,
ID, содержание, область — доступны явно, а не только внутри непрозрачной операции.
Markdown передаётся строкой; краткое описание остаётся обычным текстом.
Бизнес-правила не копируются в MCP.

Запись продукта требует автора, requestId корреляции и применимых версий. Квитанция в
читаемом содержимом и структурированный ответ описывают один результат. После
неясного сетевого результата сначала читается текущее состояние и отношения;
безусловный повтор мутации недопустим, requestId не гарантирует дедупликацию.

## Объём, ошибки и обновления

Агент начинает с обзора, затем сужает запрос. Списки ограничены и сообщают продолжение;
превышение бюджета даёт ошибку с возможностью запросить меньший контекст.
Недоступность Server — ошибка инструмента, а не пустой проект. Реестр проектов
получается с сервера и обновляется без перезапуска MCP.

## Приёмка и реализация

Проверяются discovery-схемы, русские описания аргументов, успешное чтение и запись,
повтор, конфликт, ошибка сети, бюджет и изоляция проектов. Видимость действия в
строке вызова проверяется в целевом MCP-клиенте отдельно от серверной схемы.
