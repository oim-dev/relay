# Relay CLI

CLI — терминальный интерфейс Relay для человека и автоматизации. Пакет
`@oim-dev/relay-cli`, команда `relay-cli`. Он читает и изменяет память проекта,
выдаёт контекст и помогает диагностировать данные.

## Ответственность и режимы

CLI отвечает за команды, аргументы, справку и представление результатов. Предметные
правила принадлежат Core. В local он может вызывать Core напрямую или использовать HTTP;
в workspace рабочие операции идут через Server с выбранным проектом.
Web и сервер поставляются отдельным пакетом Server.

Конфигурация выбирается через `--config`, окружение и поиск вверх. Префикс проекта
или `--project` определяет область workspace. Автор записи задаётся через `--actor`
или `RELAY_ACTOR`. Точный приоритет: [конфигурация](../../../reference/CONFIGURATION.md).

## Пользовательские сценарии

`progress <вид> <ref>` показывает фактическое выполнение, полный итог и страницы причин;
`progress product` начинает раскрытие с фич продукта. Человеческое представление содержит
адреса и команды продолжения, JSON — отдельную схему вида. [Контракт](../../../reference/PROGRESS.md).

| Цель                | Действия и результат                                                          |
| ------------------- | ----------------------------------------------------------------------------- |
| Начать проект       | Инициализировать конфигурацию и проверить доступность выбранной базы          |
| Понять продукт      | Прочитать `product overview`, затем список, запись или адресный контекст      |
| Уточнить продукт    | Создать или изменить паспорт, фичу, сценарий, приложение, состав или документ |
| Организовать работу | Подготовить задачи досок, продуктовые цели и зависимости                      |
| Сохранить результат | Уточнить Markdown задачи или связанного документа по фактическим проверкам    |
| Проверить данные    | Получить результат валидации или структурные замечания к содержанию           |
| Автоматизировать    | Использовать JSON и читать все страницы по указателю продолжения              |

Точная карта команд: [CLI](../../../reference/CLI.md). Путь первого запуска:
[руководство](../../../GETTING_STARTED.md). Продуктовые операции:
[PRODUCT.md](../../../reference/PRODUCT.md#cli-markdown-напрямую).

## Человеческий интерфейс

По умолчанию команда показывает собственное понятное представление: результат,
метаданные, содержание и следующий шаг. Markdown рендерится, краткие описания
сохраняют переносы. Таблица адаптируется к ширине; цвет не является единственным
носителем смысла. Текст не исполняет управляющие последовательности терминала.

Пустой список объясняет отсутствие результата. Страница сообщает продолжение с
сохранёнными фильтрами. Ошибка объясняет причину и действие пользователя.
Справка описывает назначение, каждый аргумент, пример и ограничения на русском.

## Машинный контракт и сохранение

`--format json` выдаёт структурированный ответ без ANSI и посторонних пояснений.
Ограничения объёма и пагинация явные. [Вывод](../../../reference/OUTPUT.md),
[терминал](../../../reference/TERMINAL.md), [ошибки](../../../reference/ERRORS.md).

Перед обновлением продуктовой записи читается ревизия; для состава — версия продукта.
`requestId` служит корреляции, не гарантирует дедупликацию. После потери ответа
пользователь сначала читает текущее состояние, не повторяет мутацию безусловно.
Markdown можно передать многострочной строкой без промежуточного файла.
Прежняя модель жизненного цикла и числовая доска удалены из публичных команд.

## Приёмка и реализация

Отдельно проверяются текст и JSON: чтение, пустота, большой список, узкий терминал,
Markdown, успешная запись, конфликт, повтор и выбор проекта. Наличие JSON не
подтверждает качество человеческого интерфейса.
