# Relay Server

Server — общая точка доступа клиентов к данным Relay на одном хосте. Пакет
`@oim-dev/relay-server`, команда `relay-server`. Предоставляет REST, SSE, OpenAPI,
Swagger и собранный Web. Пользовательский запуск отделён от бизнес-операций Core.

## Режимы и выбор проекта

Local обслуживает одну конфигурацию `.relay/config.json`. Workspace читает реестр
`relay.workspace.json` и обслуживает независимые базы через один HTTP-listener.
Каждый запрос имеет свой контекст проекта; глобального переключателя активной базы нет.
Относительные пути разрешаются относительно файла конфигурации.

## Сценарий запуска

1. Пользователь выбирает конфигурацию и запускает Server.
2. Сервер сообщает адрес, режим и понятную ошибку при невозможности запуска.
3. Web, CLI или MCP получают список проектов и обращаются к выбранному проекту.
4. При завершении через `Ctrl+C` сервер освобождает свои подписки и ресурсы.

По умолчанию сервер доступен на `127.0.0.1:4700`. `--open` открывает Web;
`--format json` предназначен для машинного результата запуска. Приоритет порта и
других настроек задан в [конфигурации](../../../reference/CONFIGURATION.md).

## Публичные возможности

| Интерфейс                            | Назначение                                   |
| ------------------------------------ | -------------------------------------------- |
| `/`                                  | Готовый Web, включая выбор проекта           |
| `/api/v1/server`, `/api/v1/projects` | Режим и актуальный реестр                    |
| `/api/v1/projects/:project/...`      | Изолированные операции выбранного проекта    |
| `/api/v1/projects/:project/events`   | Уведомления об изменениях через SSE          |
| `/api/openapi.json`, `/api/docs`     | Машинный контракт и интерактивный справочник |

В local поддерживается также непосредственная адресация под `/api/v1`.
Workspace требует проект даже при одной регистрации. Точные операции, запросы,
ответы и ошибки: [API](../../../reference/API.md).

## Согласованность и ошибки

Все предметные изменения проходят общие проверки Core. Подписчик получает события
своей базы и перечитывает данные; событие не заменяет полный ответ REST. Heartbeat
поддерживает соединение без объявления изменения данных.

Изменения реестра подхватываются без перезапуска. Удалённая или перенаправленная
регистрация освобождает прежние ресурсы. Недоступность одного проекта не смешивает
данные и не должна скрывать остальные регистрации. Неверный проект, ревизия или
ссылка возвращают явную ошибку.

## Приёмка и реализация

Проверяются local/workspace, изоляция параллельных запросов, актуализация реестра,
SSE, остановка и запуск установленного пакета вне исходников со встроенным Web.
Отдельно проверяется результат запуска для человека и JSON.
