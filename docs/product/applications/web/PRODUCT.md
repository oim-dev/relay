# Работа с продуктом в Web

[Продукт](README.md) → Интерфейс

Раздел находится в выбранном проекте: `/projects/:project/product`.
Вход открывает паспорт; рядом доступны возможности и приложения. Документы вынесены
в общую библиотеку `/projects/:project/documents`, связанную с продуктовыми страницами.
Новый контракт библиотеки, состояний и универсальных связей описан в [библиотеке знаний](DOCUMENTS.md).
Ниже описан текущий интерфейс, без исторических переключателей мока.

## Адреса страниц

Префикс `P` ниже означает `/projects/:project/product`. Параметры фичи, сценария и приложения
принимают ключ или ID; канонический адрес использует ключ. ID остаётся идентичностью
записи, связей и черновика. Неизвестная запись показывает ошибку,
а не форму создания вместо потерянного объекта.

| Адрес                                                                   | Действие                                 |
| ----------------------------------------------------------------------- | ---------------------------------------- |
| `P`                                                                     | Перенаправление на паспорт               |
| `P/passport`                                                            | Чтение паспорта и общей карты            |
| `P/passport/edit`                                                       | Заполнение или изменение паспорта        |
| `P/features`                                                            | Каталог фич и сценариев                  |
| `P/features/new`                                                        | Создание фичи                            |
| `P/features/:featureId`                                                 | Фича, её сценарии, вклады и документы    |
| `P/features/:featureId/edit`                                            | Изменение фичи                           |
| `P/features/:featureId/scenarios/new`                                   | Создание сценария внутри фичи            |
| `P/features/:featureId/scenarios/:scenarioId`                           | Чтение сценария в контексте фичи         |
| `P/features/:featureId/scenarios/:scenarioId/edit`                      | Изменение сценария                       |
| `P/applications`                                                        | Каталог приложений                       |
| `P/applications/new`                                                    | Создание приложения                      |
| `P/applications/:applicationId`                                         | Приложение и его состав                  |
| `P/applications/:applicationId/edit`                                    | Изменение описания приложения            |
| `P/applications/:applicationId/scope`                                   | Атомарное редактирование состава         |
| `P/applications/:applicationId/implementations/:implementationRef`      | Чтение реализации в контексте приложения |
| `P/applications/:applicationId/implementations/:implementationRef/edit` | Независимая правка реализации            |

Маршрут `P/work/:workId` удалён: действующего сценария этой страницы нет.
Прежние `P/documents` и вложенные страницы перенаправляются в библиотеку проекта.
Старый якорь сценария и короткий `P/scenarios/:ref` перенаправляются на вложенный адрес.
Короткий `P/implementations/:ref` (также с `/edit`) перенаправляется в приложение.
Реализация проверяет принадлежность приложению; query, hash и контекст возврата сохраняются.
Полная [карта маршрутов](ROUTING.md) находится в библиотеке Web.

## Чтение и навигация

| Подраздел                            | Сценарий                                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Паспорт (`passport`)                 | Прочитать назначение, увидеть карту готовности, перейти к фичам, приложениям и общим документам              |
| Возможности (`features`)             | Найти фичу или сценарий, отфильтровать по готовности фичи и участию приложения                               |
| Фича (`features/:id`)                | Прочитать общий контракт, сценарии, вклады приложений и связанные документы                                  |
| Приложения (`applications`)          | Выбрать программную часть по назначению и увидеть размер её состава                                          |
| Приложение (`applications/:id`)      | Прочитать назначение, дерево собственных вкладов и связанные документы                                       |
| Документы (общая библиотека проекта) | Найти материал по тексту и связям, отфильтровать по типу и области, отсортировать по названию или обновлению |

Каталог возможностей — дерево, свёрнутое по умолчанию. Блок фичи раскрывает сценарии,
название открывает страницу. Поиск раскрывает совпадения с родительским контекстом.
Фильтр приложения отбирает фичи, не заменяя общий состав сценариев составом приложения.
Готовность всегда относится к полным данным, а не видимой выдаче.

Сценарий имеет страницу `P/features/FEATURE-2/scenarios/SCENARIO-3`; несовпадающая фича
отклоняется, не подменяется молчаливым переходом. В дереве приложения название открывает
самостоятельную реализацию, отдельная ссылка — исходное требование.
Фильтры сохраняются в URL. Раскрытие дерева хранится как личная настройка браузера по
постоянному ID проекта, не меняет адрес/историю и не запускает навигацию. Поисковое
раскрытие временное: после очистки поиска восстанавливается обычное дерево.

Ключи показаны компактным моноширинным текстом рядом с названием; название остаётся
главным. В заголовках есть отдельное действие копирования ключа. Списки и связи
различают общую фичу/сценарий и реализацию конкретного приложения. Выбор целей задачи
читает компактные страницы, ищет ключ/название и сохраняет ID. План включает существующие
задачи через свой предметный интерфейс; у вложенного этапа нет самостоятельных продуктовых целей.
Полный текст выбранной цели и расширенный контекст читаются по отдельному действию.

Карточка приложения показывает тип, назначение и число выбранных фич и сценариев.
Ниже расположены два показателя с полосами, процентом и числом фактически выполненных задач:
бизнес-прогресс (акцентный) и общий прогресс. Бизнес-прогресс считает задачи собственной
доски с явной связью с фичей, сценарием или их реализацией; общий — все задачи этой доски.
Каждая задача учитывается один раз независимо от количества связей, подзадачи — отдельно.
Выполненными считаются задачи в done с выполненными критериями и всеми обязательствами
по всей цепочке; отменённые остаются в общем количестве. Расчёт приходит из API прогресса.
Процент округляется вниз до целого: 100% появляется только при выполнении всех задач.
Без задач показаны «—» и объяснение пустоты вместо ложной готовности. Во время загрузки
видны скелетоны, при ошибке — сообщение и кнопка повтора. Изменение задач обновляет
показатели через SSE; неполная выборка не выдаётся за полный прогресс.
Приложение без состава допустимо. У каталога приложений пока нет поиска и фильтра типов.
В библиотеке документ может входить сразу в группы продукта и приложений, поэтому
сумма их счётчиков не обязана равняться общему числу документов.

## Редактирование

### Проектные фичи и сценарии

Проектные страницы используют тот же дизайн чтения, что реализации приложений:
полное Markdown-описание, якорная навигация, открытые задачи с общим прогрессом,
контекст и прямые зависимости. Фича показывает до 10 компактных сценариев
с продолжением, ключом, названием и отдельным статусом. Название открывает полную
страницу сценария. Документы фичи и её сценариев остаются доступны ниже.

Статус поднимается каскадно: задача → активная реализация приложения → проектная фича/сценарий.
Прямые продуктовые задачи учитываются дополнительно, их отсутствие не блокирует каскад.
Без задач во всём составе — «Не реализовано»; если начата хотя бы одна ветка — «В работе»;
все активные реализации и существующие прямые задачи готовы — «Реализовано».
Активная реализация без задач во всём своём составе остаётся неготовой. Тот же статус виден в общем дереве и обновляется через SSE.
Фича не готова, пока не завершены её сценарии: FI приложения учитывает выбранные SI
этого приложения, проектная фича — все свои описанные сценарии. Работа любого
дочернего сценария поднимает статус родителя. Отдельная задача на FI не обязательна,
если готов весь её выбранный сценарный состав.
Список задач и его прогресс включают задачи активных реализаций приложений, без дублей.
На странице FI список также содержит задачи выбранных SI, на странице проектной фичи —
задачи её проектных сценариев и их реализаций. Статусы, списки и прогресс используют один состав.
Процент показывает завершение известных задач; пустая активная реализация может ещё удерживать
общую готовность в работе — её состояние видно в блоке приложений.

Боковая колонка содержит переход на продуктовую доску, родительскую фичу либо каталог,
зависимости и до 5 активных реализаций именно выбранного требования с продолжением.
Каждая реализация ведёт на свою страницу приложения и показывает собственную готовность.
Пустые разделы объясняют следующий шаг; ошибки показывают повтор, не выдаются за пустоту.

### Реализации приложений

Страница реализации фичи или сценария показывает название исходного требования,
ключ реализации, приложение и статус полного состава. «Не реализовано»
означает отсутствие работы во всём составе, «В работе» — начатый, но не полностью готовый состав,
«Реализовано» — весь обязательный состав готов. Для FI в него входят выбранные активные SI
и собственные задачи, если они есть; сценарий без задач не готов. Дерево приложения
использует те же серверные статусы: FI не показывает done при незавершённых SI.

На странице сразу открыт список задач с ключами, названиями, колонками и переходами
на соответствующую доску. Общий прогресс считается по полному набору, строки читаются
по 40 с продолжением. Пустой список объясняет, как связать задачу на доске приложения.
Полный Markdown исходной фичи/сценария и собственный вклад показаны отдельными
областями. Прямые исходящие зависимости `depends-on` реализации и исходного требования
читаются раздельно по 5, с переходом к следующей странице и в общий контекст графа.
Отсутствие зависимостей отличается от ошибки их чтения.

Широкая страница выделяет боковую колонку контексту и зависимостям; узкая располагает
все области последовательно. Дерево оставляет раскрытие сценариев и переход в реализацию,
без повторного скрытого списка задач под каждой строкой. Редактор вклада меняет
только текст: ручной выбор готовности удалён. SSE обновляет статусы и прогресс,
ошибки сохраняют ранее прочитанное содержание и предлагают повтор.

Паспорт, фича и приложение имеют название, краткое описание и полный Markdown;
приложение дополнительно имеет тип. Сценарий имеет название и Markdown без ручной
готовности. Документ — название, необязательное краткое описание, тип, текст и связи.
Формы поддерживают предпросмотр. Успешная запись открывает сохранённый результат.
Редактор сценария возвращает на его страницу либо к блоку сценариев фичи, если открыт
оттуда. Редактор отдельной реализации имеет постоянный `/edit`; закрытие и сохранение
возвращают в просмотр, сохраняя дальнейший возврат к приложению или исходному контексту.
Фильтры каталога продолжают цепочку переходов сценария через query.

В режиме создания ID назначается общей операцией; при редактировании сохраняется
исходная идентичность и проверяется версия. Обязательный текст проверяется до
сохранения, ошибка указывает поле и не уничтожает остальные значения. Изменение
общих требований не перезаписывает собственное описание вклада приложения.

Паспорт объясняет назначение и показывает обзор, а не копирует полный каталог фич.
Страница фичи объединяет её общий контракт, адресуемые сценарии и приложения-участники.
Страница приложения описывает его собственные вклады рядом с исходными требованиями.
Документ читается целиком как Markdown; его области ведут к существующим целям.

Редактор состава (`applications/:id/scope`) показывает дерево выбора и поля текущего
вклада рядом с исходными требованиями. На узком экране выбор и ввод идут последовательно.
Переключение элемента, поиск и временное снятие выбора сохраняют введённые тексты.
«Выбрать все сценарии» включает и скрытые поиском сценарии фичи. Сохранение применяет
весь состав; незаполненный выбранный вклад блокирует запись и открывается для исправления.

Связи документа выбираются независимо из настоящих целей. Поиск не снимает скрытые
выбранные элементы. Закрытие окна выбора сохраняет их в форме, но не записывает документ;
весь текст и набор связей применяются общим сохранением.

## Сохранность ввода

- Подтверждённые данные общие для Web, CLI и MCP; SSE и повторное чтение обновляют экран.
- Черновики локальны вкладке, разделены по проекту и редактору, переживают reload.
  Они хранят исходную версию и не заменяют постоянную запись.
- Уход с изменениями позволяет оставить черновик; отмена удаляет ввод после подтверждения.
- Фоновое обновление не затирает изменённую форму. При конфликте можно загрузить
  актуальную версию или оставить свой ввод. Второе действие само ничего не записывает;
  последующее сохранение снова проверяет версию. Автоматического слияния текстов нет.
- Ошибка записи сохраняет ввод. Успех показывается после подтверждения операции.
  `Ctrl/⌘ + Enter` сохраняет форму, но не обходит открытое модальное окно.
- Загрузка, ошибка чтения, пустой раздел, пустая выдача и неизвестный ID различаются.
  Исчезнувшая запись не превращает редактирование в создание.

## Что проверять при изменении

Проверяем затронутый путь от чтения до подтверждённого результата: ссылки после
переименования, полный состав и готовность, независимость связей, сохранность черновика,
сетевой отказ и конфликт с внешней записью. Интерфейс должен оставаться доступным
с клавиатуры, в обеих темах и на узком экране. Это критерии проверки, не отчёт о её запуске;
фактические результаты передаются в отчёте исполнителя с версией и окружением.
