# Relay Web

Прогресс задач и продуктовых целей читается из отдельных серверных обработчиков.
В редакторе задачи фактическое выполнение показано отдельно от сохранённой колонки;
невыполненные критерии, подзадачи и зависимости имеют объяснения и переходы. У фичи,
сценария и реализации полный счётчик задач не заменяет готовность обязательного состава.
Причины читаются страницами с версией; после изменения можно перечитать с начала.
SSE и восстановление соединения обновляют данные, сохраняя черновик. [Контракт](../../../reference/PROGRESS.md).

Web — интерфейс человека для наблюдения за проектом, понимания оснований результата
и редактирования памяти. Канбан является одним из разделов. Web работает с общим
Relay Server и входит в его дистрибутив; отдельный Vite-сервер используется при разработке.

## Навигация и области

Пользователь выбирает проект. URL `/projects/:project` задаёт область всех страниц,
операций, подписок и черновиков. Переключение проекта не переносит ввод и данные в другой.

Повторные полные открытия и Back/Forward, включая восстановление страницы браузером,
не накапливают соединения ушедших страниц и не блокируют загрузку данных. После
возврата обновления проекта возобновляются; сохранённый ввод не заменяется фоновой сверкой.

Действующие адреса собраны в [карте страниц Web](ROUTING.md).
Основание переработки — [исходный аудит](../../../engineering/web-routing.md).

| Раздел         | Назначение и ожидаемый результат                                                    |
| -------------- | ----------------------------------------------------------------------------------- |
| Обзор          | В разработке                                                                        |
| Продукт        | Прочитать и уточнить паспорт, фичи, сценарии и приложения                           |
| Доски и задачи | Найти, создать, прочитать и изменить задачи отдельных досок                         |
| Планы          | [Постоянные планы работ](PLANS.md): цели, вложенные этапы и выбранные задачи        |
| Релизы         | [Самостоятельные релизы](RELEASES.md): актуальный состав из планов и статус выпуска |
| Документы      | Общая библиотека документов проекта: поиск, чтение и редактирование                 |
| Инфраструктура | В разработке                                                                        |
| Связи проекта  | Прочитать и изменить направленные отношения сущностей                               |
| История        | В разработке                                                                        |

После «Релизов» стоит тонкий разделитель без подписи. Нижняя группа:
«Документы» → «Инфраструктура» → «Связи проекта» → «История».
«Продукт» и «Доски и задачи» по умолчанию свёрнуты, в том числе при прямом входе
во вложенную страницу; раскрываются только нажатием. Активная группа подсвечивается
и в свёрнутом состоянии. Это правило общее для сайдбара и мобильного меню.

Библиотека открывается по `/projects/:project/documents`; просмотр, создание и редактор
продолжают этот путь. Документы больше не входят в подменю и хлебные крошки продукта.
Связанные документы остаются доступны из паспорта, фич и приложений. Прежние адреса
`product/documents` перенаправляются с сохранением query, hash и контекста перехода.
Текущая библиотека сохраняет существующие типы и продуктовые связи документов;
инфраструктурные сущности и новые типы связей этим этапом не вводятся.

Прежняя доска и скрытые страницы `passport`, `knowledge`, `activity` удалены.
Паспорт продукта находится внутри `product/passport`. Неизвестные и удалённые адреса
показывают «Страница не найдена». Заглушки не запрашивают данные прежних разделов.
Заголовок самостоятельной заглушки имеет уровень h1; вложенные состояния сохраняют h2.

### Хлебные крошки

Каждая страница показывает путь от проекта к текущему разделу и вложенной записи.
Родители открываются ссылками, текущая страница обозначена текстом и `aria-current`.
Названия записей берутся из сохранённых данных; создание, редактирование и состав
приложения являются отдельными конечными уровнями. Путь описывает иерархию, а не историю
посещений. Несуществующие каталоги сценариев и реализаций не становятся ссылками.

Полоса располагается над содержимым и согласована со светлой и тёмной темами. При
недостатке места промежуточные уровни доступны через меню «…»; текущая страница остаётся
видимой. Длинные названия сокращаются визуально, полная подпись доступна при наведении
и фокусе. Переходы и меню работают с клавиатуры. В модальном окне задачи хлебных крошек
нет: шапка показывает ключ задачи и управление окном. Выбор/недоступность проекта и ошибки
также имеют понятный текущий пункт.
Загрузка либо ошибка названия не убирает навигацию: остаётся подпись вида и адрес записи.

## Связи проекта

`/projects/:project/relations` открывает исследователь связей: слева компактный каталог,
справа окружение выбранной сущности. До выбора показано объяснение сценария, а не весь граф.
Поиск по названию/ключу и фильтр вида работают на сервере; каталог читается по 40.
На узком экране выбор и окружение показываются последовательно с возвратом в каталог.
Выбор сущности использует общий каталог девяти видов; поиск находит также прежние ключи,
а подпись выбранной записи показывает текущий ключ. Контекст можно открыть по ключу или ID.
`?root=kind:id` открывает окружение выбранной сущности; ссылки доступны также из
фич, сценариев, приложений, реализаций и документов. Переход из карточки задачи отложен.
Поиск выбора серверный, с продолжением.
По умолчанию показывается окружение в один шаг с группами по смыслу отношения и направлению.
Русские подписи читаются относительно корня; неизвестный тип сохраняет своё имя.
Нажатие на соседнюю сущность открывает её окружение, Back/Forward восстанавливают выбор.
Режим «Цепочка связей» расширяет глубину; режим и глубина сохраняются в URL.
Отношения читаются по 30 в одном снимке. Счётчик обозначает всё окружение, включая отношения
между соседями; последние выделены отдельно. Группы и фильтр направления относятся к текущей
странице, неполнота явно подписана. Страница не выдаётся за все отношения выбранной записи.

Строка показывает ключ, вид и название соседа; подробности раскрывают полное направление,
Markdown-пояснение и факт сохранения в Core. Диагностический отзыв доступен с подтверждением;
предметные связи защищены бекендом (`RELATION_MANAGED`) и меняются через запись-владельца.
Создание диагностического ребра открывается из выбранной сущности в модальном окне.
Его назначение явно объяснено: продуктовые линки оно не заменяет. Оператор выбирает начало/конец,
читаемый тип либо свой идентификатор, меняет направление и добавляет Markdown-пояснение.
Сворачивание окна сохраняет ввод до ухода со страницы; повторное открытие продолжает черновик.
Ошибки и конфликт версии сохраняют ввод; обновление версии выполняется явно.
Источник `graph` не означает ручное создание: и предметные, и диагностические связи сохранены.
[Общие правила](../../RELATIONS.md), [контракт](../../../reference/GRAPH.md).

### Визуальный контекст

В просмотре выбранной сущности кнопка «Смотреть визуализацию связей» открывает
`/projects/:project/relations/context?root=kind:id`. Начальная область — один шаг
в обоих направлениях. Глубина, направление, тип связи и «Дерево / Граф / Список»
сохраняются в URL; Back/Forward восстанавливают параметры и исходную сущность.

По умолчанию дерево показывает по одному кратчайшему пути от корня к каждой сущности.
Сущность не дублируется. Дополнительные связи, повторные пути и циклы обозначены
счётчиком на карточке и доступны при выборе узла. Это дерево достижимости,
а не продуктового родительства. Граф показывает все загруженные направленные рёбра,
включая петли и параллельные отношения. Исходная карточка выделена синей рамкой,
выбранная и объясняющий путь — бирюзовым контуром. Подписи и иконки дополняют цвет.
Начальная камера показывает корень в читаемом масштабе; доступны масштабирование,
возврат к корню, выбранной сущности и вписывание. Раскрытие добавляет соседей;
карточки и линии пересчитываются вместе с сохранением позиции выбранной карточки.

Панель показывает все загруженные отношения выбранной сущности порциями по восемь
с продолжением и полный текст, позволяет раскрыть её связи,
сделать исходной и открыть предметную страницу. Выбор линии показывает её концы,
тип, Markdown-пояснение, автора, время, ревизию и ID. На узком экране подробности
открываются поверх диаграммы. Режим списка читает те же узлы и рёбра порциями по 30.

Визуальный просмотр использует ограниченный `GET /graph`: страницы по 50,
не более восьми страниц за область просмотра. Непрочитанные страницы и граница
глубины показаны отдельно; доступны продолжение и раскрытие. Смена версии требует
обновить весь набор; ошибка сохраняет прежний согласованный снимок, выбор и фильтры.
Этот исследователь не выдаёт ограниченную область за полный `entity_context`.
В режиме графа перемещение карточки меняет только её локальное положение;
в дереве положение задаётся раскладкой. Создание, переподключение
и удаление отношений на диаграмме отключены.

В материалах цели задачи кнопка «Показать полный контекст» читает всю компоненту через
`GET /graph/context`. Список выводится по 30 карточек с общим количеством узлов и рёбер;
это порции отображения уже полного ответа. Выбранный полный Markdown загружается через
адресный `entity_get`. Новые документные `relations` и цепочки через задачи видны наравне
с остальными сохранёнными отношениями. Ошибка бюджета и ошибка загрузки обозначены явно.

## Настройки проекта

Шестерёнка в общей шапке открывает `/projects/<slug>/settings`. Кнопки создания задачи
в общей шапке нет: создание принадлежит доске. Настройки — самостоятельная страница
с заголовком, навигацией по секциям и оформленной областью «Основное».

Имя проекта и slug сохраняются явно общей операцией. Имя видно в шапке и выборе проекта;
оно независимо от паспорта продукта. Slug определяет адрес Web; при инициализации
создаётся `project-xxxx` с четырьмя случайными строчными буквами/цифрами. Имя — 1–120
символов обычного однострочного текста; slug — 2–64 строчные латинские буквы/цифры
с одиночными дефисами между частями. Занятый адрес отклоняется сервером.

Форма показывает предпросмотр адреса, состояние изменений, сохранение/отмену и постоянный ID.
Черновик изолирован по вкладке и ID проекта. Ошибка не очищает ввод, новая серверная
ревизия требует явного выбора между актуальными значениями и своим вариантом.
После смены slug обновляется URL без смены ID, данных, кеша и подписок. Ссылки по ID
перенаправляются на актуальный slug с сохранением хвоста пути, query, hash и состояния.
Прежний slug не резервируется навсегда. При коллизии адресов после ручного подключения
проект остаётся доступен по ID для исправления настроек.

Контракт сохранения: [REST API](../../../reference/API.md#настройки-проекта).

## Доска и задачи

### Карточка на доске

Карточка показывает ключ, название до трёх строк, первую цель реализации и `+N`
остальных целей. Фича и сценарий различаются иконкой, подписью и тональным акцентом;
название цели разрешается пакетно только для загруженных карточек. Полное название
задачи и первой цели доступно в подсказке при наведении и фокусе. Недоступная цель
обозначена явно; ошибка чтения допускает повтор на уровне колонки.

Критерии приёмки показываются отдельным счётчиком и тонкой полосой; выполненные
критерии не равнозначны завершению задачи. Блокеры обозначены «Ожидает N задач»,
прямые зависимости, связанные задачи и наличие родителя имеют отдельные показатели.
Отсутствующие секции скрыты, простая задача сохраняет компактную высоту.

Наведение меняет рамку и тень без сдвига. При переносе оригинал и превью используют
одну разметку; размеры измеряются по DOM до жеста и сохраняются вместе со снимком
содержания. Масштабирование не применяется, место вставки резервирует те же размеры
и скрывает повторяющийся текст. Ручка доступна с клавиатуры и постоянно видима
на touch; отмена возвращает порядок, клавиатурный перенос возвращает фокус.

### Окно задачи

Под названием карточки расположены табы **«Задача»**, **«Обсуждения»**, **«История»**.
По умолчанию открыта «Задача» со всем основным содержанием; название, ключ и управление
окном остаются общими. Переключение сохраняет ввод, выделение и историю отмены Markdown.

Обсуждения занимают ширину таба с теми же внутренними отступами, что история; ограничения
880px и центрирования нет. Аватары не используются. Сообщение — цельный блок с тонкой
границей: в компактной тональной шапке автор, роль при наличии и время; ниже отдельная
область с выделенным заголовком и полным Markdown. Высота зависит от содержания, без
пустой колонки автора и фиксированных зон. Новые сообщения сверху, даты сгруппированы по дням.
Действие «Написать сообщение» раскрывает компактную форму; «Свернуть» сохраняет
черновик. Публикация всегда подписана «Оператор», очищает ввод только после квитанции.
Ошибка сети сохраняет поля и ключ повтора; внешнее сообщение не конфликтует с описанием задачи.
История — компактный журнал с непрерывной линией между маркерами внутри дня. На широком экране
он занимает ширину таба без центрированного ограничения 880px, с обычными внутренними отступами.
Каждое событие занимает строку «действие / автор / время / раскрытие»; на телефоне автор и время
располагаются вторым рядом. В обзоре нет сырых ID полей и отдельной строки кнопки подробностей.
Вся строка раскрывает изменения мышью или клавиатурой. Длинный заголовок обзора занимает до
двух строк и полностью раскрывается вместе с записью. Для Markdown-правок новая история
показывает «Содержимое изменено. Редакции текста в истории не сохраняются»; это отличается
от очистки поля. Полные опубликованные комментарии не обрезаются.
Старые записи без подробностей обозначены явно. [Предметные правила](../../entities/tasks/KANBAN.md#обсуждения-и-история).

Обе ленты читаются по 20. Подгрузка добавляет ранние записи снизу; SSE предлагает показать
новые, не смещая текущую страницу. Счётчик в конце ленты означает число загруженных записей,
не полный итог. Раскрытие события не разрывает линию и не меняет положение соседних маркеров
относительно их собственных строк.

Раздел «Критерии приёмки» в окне задачи содержит заголовки и краткие описания,
чекбоксы выполнения и полный Markdown по раскрытию строки. Добавление/редактирование
сохраняется явно с черновиком в текущей вкладке; изменение текста снимает отметку.
Список показывает прогресс по всей задаче и продолжение после первых 20 записей.
Готовая задача требует явного возврата из done перед изменением критериев.
Правила завершения принадлежат [модели задачи](../../entities/tasks/KANBAN.md#критерии-приёмки).

Стандартные поля ввода и селекторы используют общий размер Mantine sm: однострочное
поле высотой 36px при базовом масштабе. Markdown-редактор согласован со шрифтом sm,
имеет компактные отступы и начальные четыре строки; большие описания могут явно
задавать больше строк. Настройки применяются через общую тему и ui/markdown-field.

В сайдбаре и мобильной навигации порядок досок: «Продукт», доски приложений,
«Инфраструктура». Между этими группами показаны тонкие разделители без текста.
Доски приложений подписаны ключом (`prefix`), например `WEB` или `API`;
полное название доступно в подсказке ссылки. Системные доски сохраняют названия.
Группа определяется сохранённым типом доски, а не её названием. Если приложений нет,
между двумя системными досками остаётся одна линия. Разделители появляются только
между загруженными группами; кнопка «Показать ещё доски» продолжает каталог.

Новый раздел **«Доски и задачи»** открывает [отдельные доски](../../entities/boards/README.md)
по slug: продуктовую, доски приложений и инфраструктурную. Рабочая область использует
полную ширину и оставшуюся высоту окна. Шапка отделена от поиска и фильтров, колонки
имеют тональную подложку и собственную вертикальную прокрутку. Перенос сразу показывает
локальный результат, затем согласует его с сервером. [Канбан новых задач](../../entities/tasks/KANBAN.md)
определяет колонки, перенос, пустое создание и связи. Задача открывается широким
центральным модальным окном по `/projects/:project/boards/:boardSlug/:taskId`.
Окно разворачивается вручную и сохраняет редактор при смене размера. Таб «Задача»
объединяет описание, продуктовые цели и подзадачи; справа компактные меню статуса и доски
с немедленным сохранением. Markdown показывается по умолчанию, при редактировании
открывается исходный текст с подсветкой, без дополнительного предпросмотра.
Старый адрес новой задачи `/tasks/:id`
перенаправляется на актуальный; при переносе меняется slug, а не ID.
Закрытие по фону, Escape и крестику сохраняет черновик. Создание сразу выдаёт ID/номер
и открывает редактирование; CLI/API могут передать содержание сразу одним запросом.
Колонки загружают задачи порциями по 40 с продолжением; родительство и зависимости
различаются. Фильтры и переходы сохраняют проектный контекст в URL.

Метки фич и сценариев на карточках канбана имеют спокойные, различимые подложки
в обеих темах. В тёмной теме подложки светлее поверхности карточки, с сопоставимой
заметностью; светлый текст и иконки сохраняют читаемость без насыщенной заливки.

Раздел «Подзадачи» содержит единый список прямых детей с ключом, названием и статусом.
Добавление выбирает доску и существующую задачу без переключателя типов связи.
Незавершённая подзадача блокирует завершение родителя по общему правилу Core.
Список загружается по 40 записей, с общим числом и продолжением; готовые и отменённые
подзадачи остаются видимыми. Ссылка «Все связи и контекст задачи» из карточки удалена:
переход к общему контексту отложен.

Блок «Реализует в продукте» на продуктовой доске предлагает только общие фичи и сценарии.
На доске приложения он называется «Реализует в приложении» и предлагает только объявленные
активные реализации этого приложения. В обоих случаях выбор разделён на «Фичи» и «Сценарии»;
отдельного режима реализаций и выбора приложения нет. На инфраструктурной доске блок отсутствует.
Доска читается по самой задаче; при переносе доступные цели обновляются. Несовместимые
сохранённые цели требуют явного снятия до переноса. Компоновка выбора и предпросмотра сохранена.
В уже связанных целях фича обозначена иконкой пазла и фиолетовым акцентом, сценарий —
иконкой маршрута и бирюзовым акцентом. Это же правило действует для имплементаций;
вид определяется данными, не ключом. Текстовая подпись дополняет цвет и иконку.
Цветовой акцент — иконка и лёгкая заливка; рамка равномерная, без толстой боковой полосы.

## Обновления и сохранность ввода

### Удаление

Сценарии каскада определены в [общем контракте удаления](../../ENTITY-DELETION.md).
Действие на странице сущности и в окне задачи открывает предпросмотр. Пользователь
видит удаляемые записи, сохраняемые записи со снимаемыми ссылками и число связей графа.
Отмена оставляет сущность и черновик. Подтверждение доступно после загрузки состава;
на время отправки повторный запуск блокируется. При конфликте требуется обновить
предпросмотр; при сетевом отказе доступен повтор с тем же ключом операции.
После успешного удаления открывается каталог или родительская страница, для задачи — доска.

SSE сообщает об изменениях, после чего данные перечитываются через REST. Фоновое
обновление не затирает введённый текст. Ошибка записи сохраняет форму; конфликт
требует решения пользователя. Редактор задачи поддерживает выбор пересекающихся
полей; продуктовый редактор сохраняет или перечитывает ввод без автоматического слияния текста.

Черновики разделены по проекту, вкладке и редактору. Ошибка загрузки отличается
от пустого списка; неизвестный ID — от создания. Потеря связи отображается и
снимается после восстановления. Переход по внутренней Markdown-ссылке не должен
перезапускать всё приложение и терять контекст.

## Доступность и приёмка

Навигация и действия доступны с клавиатуры, цвета дополняются текстом. На узком
экране меню и формы остаются работоспособны. Проверяются обе темы и размеры
1440/1024/768/390, черновики, Back/Forward, пустота, сеть и конкуренция.
Успешная сборка не подтверждает эти сценарии: результаты браузерных проверок
передаются в отчёте исполнителя с версией и окружением.
