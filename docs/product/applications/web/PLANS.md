# Планы работ в Web

Статус: подключено к постоянным данным; модель вложенных этапов уточнена 25 сентября 2026. Предметная основа —
[ТЗ планов](../../entities/plans/README.md), точный [контракт](../../../reference/PLANNING.md).
Web использует общие операции Core через REST.

## Каталог

«Планы» показывает только планы работ. После заголовка расположены
фильтры состояния, поиск по названию/ключу и карточки. Активные планы
обозначены статусом «В работе»; отдельного блока плана в фокусе нет.
Карточка раскрывает краткое описание, собственный прогресс,
следующий этап и размер состава. Цвет дополняется текстом и иконкой.

Каталог и план размещаются в общей рабочей области проекта, с боковыми отступами
хлебных крошек и верхним отступом страницы. Отдельного центрированного контейнера,
добавляющего смещение на широком экране, нет. Боковая сводка внутри плана относится
к его содержанию и не подменяет общую навигацию проекта.

Поиск, фильтры и число показанных карточек сохраняются в URL. Порция — 12 планов,
с общим количеством и продолжением. Нулевая выборка отличается от нового пространства.

## План

Адрес `/projects/:project/plans/:planId` открывает полную страницу. Основное содержание:
название, ключ, состояние, цель Markdown, вкладки «Этапы и задачи» и «Материалы».
Справа — прогресс и раздельные счётчики задач. Область, основания, границы, участники,
дублирующий ожидаемый результат и служебный следующий шаг не показываются.

Отдельной кнопки «Начать план» нет. Созданный план обозначается «Запланирован»;
готовый план можно сразу завершить с итогом. Core проверяет весь состав независимо
от предварительного начала. Прежние планы «В работе» остаются совместимыми.

Этапы представлены вертикальным маршрутом: номер, ожидаемый результат, счётчик и
раскрываемый состав. Выполняемый этап открыт; готовые и будущие можно раскрыть.
Этапы — вложенные записи плана без собственных ключей. В файле плана сохранены
их порядок, содержание и ID только явно выбранных задач. Изменения защищает ревизия плана.
Дерево подзадач относится к следующему UI-этапу; дети выбранного родителя
не добавляются в сохранённый состав автоматически.
Задача показывает исходную доску, ключ и колонку; её описание читается в боковой панели.
Порядок этапов не обозначает запрет параллельного выполнения.

В форме только название, краткое описание и цель с ожидаемым результатом.
Скрытые поля прежних планов сохраняются без изменения. Подбор существующих задач сохраняет выбранные строки при поиске
и смене доски. Колонки задач не меняются при включении. Закрытие формы сохраняет ввод.

## Граница с релизами

[Релиз](RELEASES.md) — отдельная сущность и отдельный экран. У плана нет релизного
типа, версии, собственного состава из других планов и действий выпуска.
Планы выбираются при создании релиза. Каталог, форма и страница плана не предлагают
выбор релизов. Панель чтения задачи из этапа сохранена по уточнению пользователя.

## Серверное состояние и восстановление

Каталог, этапы и задачи имеют независимое продолжение. Полные показатели приходят
из Core и учитывают критерии, детей и зависимости. Порядок этапа меняется относительно
полного серверного списка, даже если следующая строка ещё не загружена.

Черновики и неподтверждённые запросы изолированы по проекту и вкладке. Они сохраняют
исходную ревизию; после потери ответа повторяется тот же requestId. Конфликт оставляет
ввод, предлагая явное отбрасывание и перечитывание. SSE обновляет серверные проекции,
не подставляя новую ревизию к старому тексту. Страница этапов возвращает ревизию своего
плана, чтобы редактор не смешивал ответы разных запросов.

Ошибка чтения сообщает о недоступной загрузке и предлагает повторить её.
Сообщение о неподтверждённом действии и сохранённом вводе относится к записи из формы,
а не к открытию каталога, этапов или задач.

Материалы прикрепляются существующими действиями документов. Общей ленты истории нет;
сохранение предметных событий планирования не означает наличия отдельного раздела Web.
Из реальной карточки задачи доступен текущий план.
Закрытый план сохраняет результат; повторное открытие задачи показывает расхождение.
Обязательный запрет исполнения без начатого плана выделен пользователем в отдельный этап.

Черновики формы плана, этапа, выбора задач и итога используют пространство `server-v2`,
ключи неподтверждённых операций — `v2`. Прежние черновики, запросы и демонстрационные
примеры не подмешиваются к новой модели; подтверждённые данные читаются только с сервера.

Техническое устройство: [реализация планирования в приложениях](../../../engineering/implementation/applications.md#две-сущности-планирования-25-сентября-2026).
