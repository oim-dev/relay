# Просмотр контекста сущности в UI Relay

**Статус: предложение интерфейса и поверхностного технического решения.**
Документ сохраняет исходное предложение. Действующий контракт реализованного среза — по ссылкам ниже.

Первый срез реализован 23 сентября 2026 с входом только из выбранной сущности
в разделе «Связи проекта». Действующее поведение и ограничения ведутся в
[контракте Web](README.md#визуальный-контекст), устройство — в
[реализации связей](../../../engineering/implementation/relations.md).
Остальные точки входа ниже остаются предложением.

По результатам пользовательской приёмки 23 сентября основным представлением стало
дерево кратчайших путей от корня. Дополнительные отношения и циклы доступны в сведениях,
все линии — в отдельном режиме графа. Послойный граф ниже сохраняет статус исходного
предложения; действующие три режима, геометрия и ограничения описаны в контракте Web.

## Назначение

Из любой сущности Relay пользователь может открыть «Просмотреть контекст» и увидеть,
как она связана с другими сущностями: задачами, фичами, сценариями, приложениями,
реализациями, документами и досками. Пользователь исследует направления, раскрывает
цепочки и переходит к нужным записям.

Контекст отображает только сохранённые связи движка Core. Фронтенд не создаёт отношения
из продуктовых полей, названий или расположения элементов. Основной контракт:
[линки, связи и контекст](../../../development/LINKS-AND-CONTEXT.md).

## Рекомендуемое решение

**React Flow + ELK.js, направленный граф с послойной раскладкой слева направо.**

- React Flow отвечает за карточки, линии, выбор, масштабирование и перемещение камеры.
- ELK.js рассчитывает координаты узлов и, при необходимости, маршруты линий.
- Исходная сущность выделяется рамкой; при открытии камера центрируется на ней.
- Первоначально показываются непосредственные соседи: глубина 1, оба направления.
- Дальнейшее окружение раскрывается по запросу пользователя.

Это граф, а не строгое дерево: возможны циклы, общие документы, несколько родителей
и несколько путей к одной сущности. Сущность показывается одним узлом; повторные
пути сходятся к нему. Послойная раскладка делает цепочки читаемыми, не удаляя рёбра.

ELK выбран за настройку сложных направленных графов, портов и маршрутизации линий.
Dagre проще для небольшой диаграммы, но оставляет меньше возможностей для сложного
окружения. Радиальная раскладка удобна для ближайших соседей, хуже — для длинных
названий и цепочек. Силовое «облако» не предлагается как основной режим чтения.

## Точка входа и общий экран

На страницах сущностей — кнопка **«Просмотреть контекст»**. Все кнопки открывают
один общий просмотр с собственным URL, чтобы сохранять ссылку и пользоваться Back.
Точный маршрут определяется при интеграции с существующей картой роутинга.

Основное представление — большая область диаграммы с боковой панелью подробностей.
На небольшом экране панель может открываться поверх диаграммы. Предусмотрено
переключение **«Диаграмма / Список»** для последовательного и клавиатурного чтения.

Верхняя панель:

- ключ и название исходной сущности;
- глубина обхода;
- направление: все, исходящие, входящие;
- фильтр типа связи;
- «К исходной сущности», «Вписать в экран», «Обновить»;
- индикатор неполной загрузки, если есть продолжение или граница глубины.

Пример окружения задачи, условное расположение:

```text
WEB-3 ──зависит от──→ API-1 ──реализует──→ API-SI-1 ──реализует──→ SCENARIO-1
                       │
                       ├──зависит от──→ API-2
                       │
                       └──материал───→ DOC-4
```

Стрелки сохраняют направление from → to из ответа Core. Положение слева или справа
само по себе не означает родительство, приоритет или порядок выполнения.

## Карточка сущности

Компактный узел содержит:

- иконку и название вида;
- читаемый ключ;
- название сущности;
- статус, если он применим.

Исходная и выбранная сущности различаются визуально. Цвет может помогать различать
виды, но сопровождается иконкой и текстом. Полные описания не помещаются внутрь узлов:
они доступны в панели или на обычной странице сущности.

## Отображение связей

Рекомендуются направленные линии с прямоугольными изгибами и скруглёнными углами.
На линии показывается понятное название: «реализует», «зависит от», «описывает»,
«материал», «часть». Неизвестный тип остаётся видимым с техническим именем.

При плотном графе подписи можно показывать прежде всего у выбранной сущности и пути.
Несколько связей между одной парой узлов разводятся визуально и сохраняют отдельные ID.
Циклы и петли отображаются, а не скрываются. Постоянная анимация всех линий не нужна.

Выбор линии открывает её данные: начало, конец, тип, пояснение, автора, время и ID.

## Исследование окружения

| Действие           | Результат                                                   |
| ------------------ | ----------------------------------------------------------- |
| Выбрать карточку   | Показать сведения и выделить её непосредственные связи      |
| «Раскрыть связи»   | Запросить соседей выбранного узла и добавить их в диаграмму |
| «Сделать исходной» | Перейти к контексту выбранной сущности как нового корня     |
| «Показать путь»    | Подсветить доступный объясняющий путь от исходной сущности  |
| «Открыть сущность» | Перейти на её обычную продуктовую страницу                  |
| Увеличить глубину  | Запросить более глубокое окружение текущего корня           |

Для первой версии достаточно одного объясняющего пути из ответа Core. Поиск всех
путей между произвольными узлами — самостоятельная будущая возможность.

Раскрытие отдельного узла отличается от увеличения общей глубины: оно добавляет
окружение выбранного узла. Смена корня меняет основной контекст и отражается в URL.

## Поверхностная схема реализации

```text
Кнопка на странице сущности
  → общий экран контекста
  → запрос графа через существующий REST SDK
  → сборка согласованного набора nodes и edges
  → расчёт раскладки ELK
  → отображение React Flow
```

### Получение данных

Используется существующий проектный запрос графа:

```text
GET /api/v1/projects/:project/graph
  root=<ключ или kind:ID>
  direction=both
  profile=all
  depth=1
```

Контракт: [граф сущностей](../../../reference/GRAPH.md).

- `nodes` и `endpoints` объединяются в каталог карточек отображаемых сущностей.
- `edges` определяет реальные линии диаграммы.
- `paths` используется для объяснения включения, а не вместо полного набора рёбер.
- `nextOffset` обозначает непрочитанные страницы; `boundary` и `depthLimited` — границу глубины.
- Страницы одного запроса дочитываются с теми же фильтрами и `version`.
- При добавлении окружения другого узла используется та же версия графа. Если она
  изменилась, нужно обновить согласованный набор, а не смешивать старые и новые данные.

ID узла React Flow строится из `{kind,id}`. ID ребра равен ID сохранённой связи.
Новые ответы объединяются по этим идентификаторам, без дублирования сущностей.
Короткие ключи и названия используются для отображения, а не как постоянные ID.

### Состояние интерфейса

Отдельно хранятся:

- серверный снимок узлов и связей;
- параметры запросов и раскрытые области;
- выбранный узел или ребро;
- координаты, положение камеры и состояние боковой панели.

Параметры основного просмотра сохраняются в URL. Перемещение карточки меняет только
её визуальные координаты и не вызывает запись связи в Core.

### Раскладка

ELK получает узлы с размерами и существующие рёбра; возвращает координаты.
При использовании его маршрутизации собственный компонент ребра отображает рассчитанные
сегменты: React Flow не применяет маршруты ELK автоматически.

Раскладка пересчитывается при изменении состава, не при каждом выделении карточки.
Для раскрытия нужна политика сохранения положения уже показанных узлов: стабильность
не обеспечивается автоматически одним подключением ELK. Пользователь не должен терять
выбранную область из-за резкого перемещения всей диаграммы.

Диаграмма и ELK загружаются по необходимости. Для больших наборов расчёт раскладки
целесообразно выполнять в Web Worker. Начальный просмотр не загружает весь граф проекта.
Пределы визуальной выборки определяются при реализации и явно показываются пользователю.

## Просмотр не редактирует отношения

На основном экране отключены создание связей перетягиванием, переподключение концов
и удаление рёбер клавишей Delete. Разрешены исследование, фильтрация и переходы.

Изменить прикрепление документа, цель или зависимость пользователь может через
соответствующий продуктовый интерфейс. Прямое исправление графа остаётся отдельным
диагностическим сценарием того же движка.

## Пустые состояния и ошибки

- Нет сохранённых связей: показать исходный узел и сообщение «Связей пока нет».
- Есть продуктовый линк, но сценарий ещё не интегрирован с Core: не рисовать выдуманное ребро.
- Есть непрочитанные страницы: показать неполноту и действие продолжения.
- Достигнута глубина: предложить раскрытие граничных узлов.
- Сменился снимок: предложить обновление, сохранив выбранную сущность и фильтры.
- Запрос завершился ошибкой: отличать ошибку от пустого результата, дать повторить.

Связи с другими областями видны, если они сохранены и входят в границы запроса.
Достижимость документа не означает обязательности его требований или изменения
продуктовой принадлежности исходной сущности.

## Объём первой версии

1. Общий просмотр контекста и вход из страниц сущностей.
2. React Flow с ELK Layered слева направо, исходной сущностью и направленными связями.
3. Глубина, направление, тип отношения, продолжение и раскрытие соседей.
4. Выбор узла/ребра, боковая панель, переход к сущности и подсветка объясняющего пути.
5. Режим списка, пустые состояния, ошибки и явная неполнота.

Отдельный редактор графа, глобальная карта всего проекта, сохранение пользовательских
раскладок и поиск всех путей не входят в предлагаемый первый срез.
