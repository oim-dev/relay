# Библиотека знаний проекта

[Web](README.md) · [Операции сущностей](../../../reference/ENTITIES.md).

## Назначение

Библиотека по `/projects/:project/documents` хранит дополнительные знания для человека
и агента. Один документ может быть связан с задачами, фичами, сценариями, приложениями,
реализациями и другими сущностями проекта. Ссылка сама по себе не меняет готовность
и не превращает обсуждаемое предложение в принятое требование.

Раздел определяет место поиска, тип — характер материала, связи — предметный контекст.
Начальные разделы: продукт, архитектура, разработка, инфраструктура, процессы. Пользователь
создаёт, переименовывает, упорядочивает и удаляет разделы. Удаление раздела сохраняет
документы в представлении «Без раздела»; постоянные ID документов и ссылок не меняются.

## Каталог и создание

Каталог — компактные строки, локальная навигация и серверный поиск по названию, summary
и Markdown. Фильтры и страницы сохраняются в URL. По 40 карточек, total и nextOffset,
продолжение связано с версией снимка. Ошибка продолжения предлагает начать выборку заново.
Счётчики разделов отражают полный набор неархивных документов вне текущего поиска.

Представления: все документы, закреплённые, черновики, без раздела и архив.
Типы: описание, техническое задание, правила, инструкция, проект решения, решение,
исследование. Состояния: черновик, действующий, архив. Закрепление общее для проекта.

Создание требует названия и Markdown. Краткое многострочное описание объясняет,
когда читать материал. Сохранённый черновик доступен остальным участникам и агентам;
локальная копия несохранённых правок относится только к вкладке и обозначается отдельно.

## Чтение и проектирование

Верх страницы сразу показывает назначение, тип, состояние и ключ. Рядом с полным текстом
видны раздел и связи с актуальными названиями, видом сущности, ключом, контекстом приложения
или доски и Markdown-пояснением. Оглавление строится по реальным заголовкам текста.
На узком экране прикрепления и оглавление раскрываются кнопкой, чтобы полный текст
не вытеснялся длинным списком. Раздел остаётся виден в компактном блоке свойств.

«Проект решения · Черновик» — проектирование будущей реализации. Бейдж виден в каталоге,
поиске, выборе и обратных списках; страница объясняет, что решение ещё не принято.
Принятие явно переводит проект решения в действующее решение с тем же ID и связями.
Архив сохраняет прямую ссылку и показывает предупреждение о неактуальности материала.

## Прикрепления документов

Окно выбора ищет по всему проекту, допускает несколько целей и сохраняет скрытый выбор
при смене поиска, вида и страницы. Реализации различаются по приложению, задачи — по доске.
Выбор родителя не выбирает детей. До 100 адресных отношений на документ.

- «Для чтения»: сущность ссылается на документ (`references`).
- «Описывает»: документ описывает сущность (`documents`).
- Необязательное пояснение Markdown объясняет, когда и зачем читать материал.

Отмена окна не применяет изменения. В редакторе применение меняет только локальный ввод;
страница чтения сохраняет продуктовые линки по ревизии документа. Текст, свойства и линки
принимает одна предметная операция. После продуктовой записи её бекенд явно вызывает
функции Core для установки/изменения/разрыва отдельно сохраняемых связей контекста.
Web не делает второй запрос к графу. Снятие линка и соответствующей связи не удаляет документ.

Это требование [обязательного стандарта](../../../development/LINKS-AND-CONTEXT.md).
Вычисление связей из полей документа удалено из движка. Бекенд сохранения документа
согласует продуктовую запись с явными вызовами Core; прерванный сценарий восстанавливается
под общей блокировкой. Прежние линки переносятся при явном сохранении. Переход описан в
[состоянии реализации](../../../engineering/implementation/relations.md).

На страницах сущностей доступны «Прикрепить» и «Создать». Создание заранее выбирает
исходную сущность; прикрепление использует существующие документы. Несколько документов
сохраняются по одному: при частичном отказе UI сообщает результат и оставшийся выбор.
В библиотеке показываются прямые прикрепления. Отдельный просмотр графа, контекста
и путей не входит в задачу библиотеки документов.

## Приёмка

Человек создаёт инфраструктурную инструкцию и связывает с приложением и задачей; агент
находит тот же материал из контекста и читает полное тело. Черновой проект решения виден
как черновик до явного принятия. Проверяются обе темы, четыре ширины, клавиатура,
сохранность ввода, отказ сети, конфликт версии, пагинация, SSE и старые ссылки.
Фактическое покрытие и ограничения передаются в отчёте исполнителя,
а не выводятся из этой спецификации.
