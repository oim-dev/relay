# Карта маршрутов Relay Web

[Web](../../../../apps/web/README.md) ·
[Роутер](../../../../apps/web/src/app/router/app-router.tsx) ·
[Продуктовый контракт](README.md)

Каноническая карта страниц фронтенда. Обновляется вместе с деревом URL и ссылками.

## Принципы

- `P` ниже — `/projects/:project`; каноническое значение проекта — slug.
- `R` — `P/product`. Ссылки на фичи, сценарии, приложения и реализации принимают
  ключ или ID; после разрешения используют канонический ключ (ID при неоднозначности).
- Дочерняя страница продолжает адрес родителя: сценарий — фичи, реализация — приложения,
  задача — доски. Исходное требование реализации открывается отдельной ссылкой.
- Полностраничные продуктовые редакторы имеют `/edit`; состав приложения — `/scope`.
- Совместимые адреса перенаправляют через replace с сохранением query, hash и контекста.
- Возврат в продукте хранит `state.returnTo`; редактор дополнительно принимает
  `state.editorReturnTo`. Без state доступен предсказуемый родитель/просмотр.
- Внутренние Markdown-ссылки на Web используют React Router, внешние — обычную ссылку.

## Вход и общие разделы

| URL                           | Страница или действие                                         |
| ----------------------------- | ------------------------------------------------------------- |
| `/`                           | Выбор проекта в workspace; вход в единственный проект в local |
| `P`, `P/`                     | Обзор — «В разработке»                                        |
| `P/settings`                  | Настройки проекта, секция `#general`                          |
| `P/relations`                 | Связи проекта, `?root=kind:id` выбирает контекст              |
| `P/relations/context`         | Визуализация связей выбранной сущности, обязательный `root`   |
| `P/plans`                     | Каталог постоянных планов работ                               |
| `P/plans/:planId`             | Цель, этапы, задачи, описание и итог плана                    |
| `P/releases`                  | Каталог самостоятельных релизов                               |
| `P/releases/:releaseId`       | Версия, статус и актуальные выбранные планы выпуска           |
| `P/infrastructure`            | Инфраструктура — «В разработке»                               |
| `P/boards`                    | Переход на `P/boards/product`                                 |
| `P/boards/:boardSlug`         | Канбан продуктовой, инфраструктурной или прикладной доски     |
| `P/boards/:boardSlug/:taskId` | Модальное окно задачи над доской                              |

## Библиотека знаний

| URL                            | Назначение                    |
| ------------------------------ | ----------------------------- |
| `P/documents`                  | Библиотека знаний проекта     |
| `P/documents/new`              | Создание документа            |
| `P/documents/:documentId`      | Чтение документа и его связей |
| `P/documents/:documentId/edit` | Редактирование документа      |

Крошки идут от проекта непосредственно к документам. Поиск, фильтрация и сортировка
выполняются на сервере; библиотека читает по 40 документов, а не полный снимок проекта.
Параметры URL:

- `q` — поисковый запрос;
- `view` — системное представление: `all`, `draft`, `pinned`, `none`, `archived`;
- `section` — ID раздела библиотеки;
- `kind` — тип документа;
- `sort` — `updated` (по умолчанию) или `title`;
- `target` — связанная сущность;
- `offset` и `version` — позиция и версия серверной выдачи.

Смена фильтра или раздела сбрасывает позицию и версию; переход между страницами сохраняет
версию выдачи. Создание принимает `?section=:id`, чтобы подставить выбранный раздел.
Возврат из просмотра или редактора учитывает `state.returnTo` с фильтрами каталога.

## Совместимость и неизвестные адреса

| Входной адрес                       | Результат                                                              |
| ----------------------------------- | ---------------------------------------------------------------------- |
| `P` с ID/ключом проекта             | Текущий slug с сохранением хвоста, query, hash и state                 |
| `R/documents` и вложенные адреса    | `P/documents` с прежним хвостом, query, hash и state                   |
| `R/scenarios/:ref`                  | `R/features/:feature/scenarios/:scenario`                              |
| `R/implementations/:ref` и `…/edit` | Вложенный адрес реализации в приложении и соответствующий режим        |
| `R/features/:feature#scenario-:id`  | Вложенная страница сценария                                            |
| `P/tasks/:ref`                      | Текущая доска и постоянный ID задачи                                   |
| `P/boards/:board?task=:id`          | Маршрут задачи; служебные `task/column` удаляются, фильтры сохраняются |
| Задача по прежней доске             | Адрес актуальной доски без смены ID                                    |
| Неизвестный проект                  | «Проект недоступен»                                                    |
| Неизвестный путь внутри проекта     | «Страница не найдена»                                                  |

`P/board`, `P/passport`, `P/knowledge`, `P/activity` не зарегистрированы. В workspace неизвестный
глобальный путь показывает выбор проекта; в local пути без `P` получают проектный префикс.

## Контекст и устройство

- Каждый конечный маршрут объявляет уровни хлебных крошек в `handle.breadcrumbs`.
  Общие уровни наследуются от совпавших родителей; технические pathless-границы
  не добавляют пунктов. Шаблоны адресов задаются рядом с деревом URL.
- `page-breadcrumbs` отображает путь в каркасе проекта; внутри модалки задачи крошек нет.
  Компонент читает названия сущностей/досок адресно через доменные API. На узком экране предки
  доступны в меню. Последний пункт обозначает текущую страницу и не является ссылкой.
- Возврат к доске через крошки сохраняет `q/blocked/cancelled`. При совпадении адреса
  родителя с `returnTo/editorReturnTo` используется сохранённый контекст этой страницы.
- Состояния подключения, выбора/недоступности проекта и ошибки имеют собственные
  цепочки без зависимости от доступности проектных данных.

- Каталог «Возможности»: `q/status/app`; состав приложения: `feature/scenario`.
- Каталоги планов и релизов: `q/status/limit`; у каждого свои статусы.
  Подробности плана: `tab=stages/overview`. Релиз — отдельный
  экран без плановых вкладок. Неизвестные ID показывают «План не найден» / «Релиз не найден».
  Черновики изолированы по ID проекта и вкладке. Каталоги, этапы и состав читаются
  с сервера страницами; прогресс относится ко всему составу, не только видимой странице.
  Релиз ссылается на актуальные планы, не имеет собственных этапов или снимка выпуска.
  Подробнее: [планы](PLANS.md) и [релизы](RELEASES.md).
- Доска и URL задачи: `q`, `blocked=1`, `cancelled=1`. History state дополнительно хранит
  доску-фон и возможность вернуться Back, но не заменяет query скопированной ссылки.
- Исследователь связей: `root`, режим `view=chain` и `depth` в URL;
  номер страницы отношений хранится в состоянии текущего просмотра.
- Визуализация: `root`, `depth` (1–100), `direction` (both/incoming/outgoing), `type`,
  `mode` (tree/graph/list, по умолчанию tree; прежний diagram совместим с graph).
  Раскрытые области, прочитанные страницы, выбор и координаты
  живут в текущем просмотре. Вход — кнопка выбранной сущности в «Связях проекта».
  Смена корня и фильтров добавляет шаг истории; обновление снимка сохраняет выбор.
- Раскрытие фич хранится как личная настройка проекта; дерево приложения использует `open`.
- Кнопки «Продукт» и «Доски и задачи» раскрывают группы меню; настройки открываются из шапки.
  Группы по умолчанию свёрнуты и не раскрываются автоматически по URL.
  Подразделы продукта: «Паспорт», «Возможности», «Приложения».
  После релизов разделитель отделяет «Библиотеку знаний», «Инфраструктуру»,
  «Связи проекта» и «Историю».

## Загрузка маршрутов и данных

Код большинства экранов и маршрутных границ подключается через React Router `lazy`;
ленивый фасет экспортирует `Component`. Начальную загрузку кода показывает `hydrateFallbackElement`,
ошибки маршрута обрабатывает `errorElement`. Предметные GET-запросы выполняют доменные
SWR-хуки, не `loader`; изменения данных вызываются через доменные операции, не `action`.

Общий `ProductLayout` содержит `Outlet` и `ScrollRestoration` продуктовых страниц.
Ветка `product-snapshot` подключает полный снимок каталогам, агрегированным страницам
и редакторам. Самостоятельное чтение сценария и просмотр/редактор реализации используют
адресные запросы в той же продуктовой маршрутной области.
Библиотека знаний — самостоятельная ветка `documents` вне `ProductLayout` и
`product-snapshot`; страницы читают данные через домены `entities` и `documents`.
Канонизация продуктовых ключей применяется только к продуктовой ветке.

Перед изменением проверить прямой URL, совместимую ссылку, неверного родителя,
Back/Forward, reload редактора, возврат к источнику и фильтры после закрытия задачи.
