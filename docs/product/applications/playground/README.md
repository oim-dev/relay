# Relay Playground

Playground — локальная среда использования текущего Relay на двух независимых
демонстрационных проектах. Она позволяет открыть отдельную агентскую сессию,
прочитать ТЗ, наполнить память по поручению и наблюдать результат через Web.
Это не отдельный сервер и не реализованные приложения кофейни или аренды.

## Проекты и источники

- `coffee-shop` — кофейня «Тёплый круг», предзаказ и самовывоз.
- `p2p-rental` — P2P-сервис аренды техники.

ТЗ находятся в каталогах проектов. ТЗ аренды — внешний материал с сохранёнными
ссылками и контекстом источника: его утверждения не доказывают наличие реализации
в Playground. Исходная поставка содержит ТЗ и инициализацию; фактическое текущее
наполнение локальной базы проверяется через Relay, а не предполагается пустым навсегда.

## Сценарий работы

1. Установить зависимости репозитория и собрать продуктовый скилл.
2. Выполнить `pnpm run init` из `apps/playground`: инициализировать отсутствующие проекты
   и проверить существующие без сброса данных.
3. Из корня Relay запустить Server и Web с workspace-конфигурацией:
   `RELAY_CONFIG=apps/playground/relay.workspace.json pnpm dev`.
4. Проверить `pnpm --silent run cli projects list` из Playground и выбрать проект.
5. Выполнять чтение или порученное наполнение через CLI/MCP, проверяя сохранённые записи.

Обычный корневой `pnpm dev` без указанной конфигурации использует однопроектную
настройку кофейни. Для одновременной работы с двумя проектами требуется workspace.

## Интерфейсы и ограничения

CLI запускается из текущих исходников с явным workspace-конфигом. Записи требуют
автора. MCP запускается через `pnpm run mcp` и доступен на порту 4710; клиент
подключается отдельно. Web, CLI и MCP должны обращаться к одному Server и проекту.
Локальная валидация возможна через `--local` с явной проектной конфигурацией.

Инициализация не создаёт примерные паспорта, планы и задачи. Наполнение выполняется
по поручению пользователя, а не ради демонстрации мнимого прогресса. Результат ТЗ
не объявляется выполненным без проверки. История пользовательского продукта ведётся
через публичные операции Relay; результат изменения инфраструктуры передаётся в отчёте исполнителя.

Все каталоги `.relay` внутри Playground исключены правилом Git-ignore. Правило не
удаляет уже отслеживаемые файлы из индекса; это проверяется отдельно при изменении
состава репозитория. Инициализатор создаёт недостающую конфигурацию. Локальный пакет
скилла в `.agents` тоже исключён из Git и обновляется сборкой.

## Приёмка и реализация

Повторная инициализация сохраняет существующие данные. Действия в одном проекте
не меняют другой. Отсутствие Server даёт понятную ошибку. Перезапуск сервисов
не очищает память. Проверки записи проводятся только в согласованной области.
