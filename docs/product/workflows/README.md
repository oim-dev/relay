# Сквозные процессы Relay

[Концепция](../README.md) → Процессы

Эта страница описывает использование Relay для сопровождения продукта, не отчётность
разработчиков этого репозитория. Их процесс — [поручение и ответ оркестратору](../../development/PROTOCOL.md).

## От намерения к результату

1. Человек задаёт цель и границы самостоятельной работы.
2. Оркестратор восстанавливает продуктовый контекст, уточняет требования и неизвестное.
3. Человек или оркестратор подготавливает продуктовые задачи и задачи приложений с критериями.
4. Формирует план разработки: выбирает объём и распределяет задачи по этапам.
   В проекте может быть несколько планов; вложенные этапы хранят явно выбранные ID задач
   по [контракту планирования](../../reference/PLANNING.md).
   План обосновывает работу; отдельная операция начала не обязательна для его завершения.
5. По поручению организует исполнение во внешней агентской среде.
6. Сохраняет проверки, принимает результат или возвращает конкретные замечания.
7. Фиксирует интеграцию и поставку, если они входят в цель.
   Самостоятельный релиз заранее выбирает планы и имеет собственный статус;
   работа по выпуску при необходимости оформляется обычным планом. Связь определяется в
   [модели планов и релизов](../DIRECTION.md#состав-релиза-и-работа-по-выпуску).
8. Обновляет память продукта и точку продолжения.

Изменение требований пересматривает применимость прежних подтверждений. Ни завершение
попытки, ни существование записи релиза не подменяют проверку результата.

## Подключение существующего проекта

Источники — код, документация, история и пояснения пользователя. Сначала сохраняются
происхождение и фактическое исходное состояние. Противоречия и предположения отмечаются.
Затем описываются продукт, необходимые изменения и ближайшая работа. Импорт материалов
не является новой реализацией; старые проверки сохраняют свои дату и область.
Автоматический импорт всего проекта не заявляется как готовая функция.

## Исправление и развитие

Для бага фиксируются ожидаемое и фактическое поведение, воспроизведение и область
влияния. Для развития — изменение существующего контракта или новая возможность.
Новый цикл не пересоздаёт продуктовую сущность и не стирает прежнюю историю.
Самостоятельная цель должна проходить через план даже при одной задаче; это согласованный
принцип следующего этапа, а не действующее ограничение всех операций.

## Продолжение после паузы

Оркестратор читает цель, план, назначения, ожидающие проверки результаты и блокеры.
Исполнитель — поручение, предыдущие попытки, проверки и следующий шаг. Оба сверяют
код, процессы и окружение с сохранённым состоянием перед продолжением.

## Граница текущей реализации

Действуют продуктовые сущности, задачи отдельных досок, граф контекста, постоянные
[планы](../../reference/PLANNING.md) и [релизы](../../reference/RELEASES.md)
через Core/REST/CLI/MCP/Web. Обязательный запрет исполнения без начатого плана остаётся
следующим этапом. Проверку результата и внешнюю поставку выполняют участники;
структурированные записи прежнего жизненного цикла удалены. Результаты проверок можно
сохранять в Markdown задач и документов. Выпущенный релиз сохраняет статус, автора и дату;
состав и готовность читаются актуальными. Relay не запускает CI/CD.
Обзор и общая история проекта — в разработке.
Подробности: [покрытие](../../engineering/implementation/README.md), [направление](../DIRECTION.md).
