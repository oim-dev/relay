# Связи сущностей и восстановление контекста

Агент и оператор задают предметные линки штатными действиями: выбирают цели задач,
прикрепляют документы, назначают зависимости. Бекенд сохраняет продуктовые данные,
затем явно вызывает функции Core для установки, изменения или разрыва отдельно хранимых
связей. Публичный контекст читает эти связи и восстанавливает цепочки между сущностями.
Определения и обязательные правила — [стандарт линков, связей и контекста](../development/LINKS-AND-CONTEXT.md).
Фича/сценарий не являются обязательными
посредниками: баг приложения и работа над инфраструктурой могут иметь собственную область.

## Правила

- Продуктовые линки обслуживают UI и бизнес-правила. Связи обслуживают механизм движка
  и контекст: они не заменяют продуктовые поля и не вычисляются вместо записи при чтении.
- Для каждого продуктового сценария разработчик определяет необходимые вызовы движка
  после продуктовых действий. Бекенд отвечает за согласованность двух записей и восстановление.
- Фича принадлежит единственному продукту выбранного проекта, продукт — самому проекту.
  Бекенд сохраняет фича → `part-of` → продукт → `part-of` → проект. Незаполненный паспорт
  остаётся сущностью продукта: корневая связь возникает уже при инициализации базы.
  Это обязательные предметные принадлежности, не произвольные связи всех записей с проектом.
- У сущностей постоянные адреса; название, публичный ключ и расположение файла не являются связью.
- Универсальное ядро допускает любые пары существующих сущностей, расширяемые типы,
  несколько родителей и циклы. Ограничения конкретных предметных операций задаёт приложение.
- Вложенность выражается отношениями. Основной контекст охватывает всю достижимую компоненту
  одним вызовом; технический предел обозначается ошибкой, а не скрытой границей глубины.
- Сценарная реализация принадлежит реализации своей фичи в том же приложении: отдельное
  `part-of` сохраняется вместе с `implements` к сценарию и принадлежностью приложению.
  Снятие участия сохраняет адреса и прежние отношения; удаление выполняет предметный каскад.
- Контекстная ссылка на документ не превращает его в требование и не наследует его область.
  Документ может быть полезным примером из другого приложения. Сохранённые связи этого
  документа входят в полный обход; достижимость не меняет продуктовые правила.
- Связь «реализует» обозначает намерение, не факт приёмки или поставки. Произвольная
  связь сама по себе не изменяет статусы и блокировки канбана.

## Сценарий агента

Обход принадлежит Core. CLI делает один запрос к общей операции (напрямую или через API)
и форматирует результат; Web получает те же данные. Агент не должен сам открывать каждую
сущность по цепочке ради обнаружения соседей. Дополнительные обращения нужны для полных
текстов. Дерево — представление плоских nodes/edges выбранного корня,
а не копия всей цепочки внутри фичи; повторные узлы и циклы остаются ссылками на сущности.

1. Выбрать проект и найти адрес нужной сущности.
2. Запросить контекст: получить все карточки и отношения достижимой компоненты.
3. Убедиться в complete=true и исследовать цепочки по направленным рёбрам. При ошибке
   бюджета увеличить допустимый размер ответа; неполный граф не выдаётся за успешный.
4. Полные требования прочитать адресными предметными операциями. Краткая карточка их не заменяет.
5. При необходимости установить предметный линк через операцию его владельца,
   перечитать результат и контекст. Не синхронизировать отдельное ребро из клиента.

Пустая выборка, неизвестная сущность, повреждённая ссылка, устаревший снимок и неполный
обход различаются. После потери ответа сначала читаются текущая запись и отношения;
requestId служит корреляции, не гарантирует дедупликацию.
Параллельная запись не должна незаметно затереть изменения другого участника.

## Сценарий оператора и переход

В штатном интерфейсе выполнить предметное действие, например прикрепить документ к задаче.
Бекенд сохраняет прикрепление у документа, затем вызывает Core для записи связи с задачей.
При откреплении удаляет продуктовый линк и вызывает разрыв соответствующей связи.
В исследователе окружения
выбрать сущность и глубину, прочитать направления и пути.

Существующий Web-раздел «Связи проекта» также позволяет создавать произвольные рёбра.
По принятому стандарту это явно обозначенный диагностический сценарий, не замена предметным
операциям. Предметные связи защищены от прямого отзыва в едином формате. Ошибка сохраняет ввод; конфликт
версии требует перечитывания. Отзыв существующей явной связи не создаёт общий audit;
идентичность отношения и проверка версии защищаются правилами Core.

В материалах выбранной цели задачи Web читает полный сохранённый контекст. Карточки
показываются порциями по 30 с явным общим количеством; это ограничение отображения,
а не полноты графа. Полный текст выбранного узла загружается адресно. SSE обновляет
граф и содержание; ошибка отличается от пустого окружения.

## Приёмка и границы

Контекст любой сущности раскрывает сохранённые связи с обоих концов, включая продолжение
через документы, приложения и другие виды. Сценарий должен находить задачи своих реализаций
после явной установки необходимых связей продуктовым бекендом. Обход не меняет область
требований; циклическая цепочка завершается; большой граф возвращается целиком либо с явной ошибкой предела.

Движок теперь читает только явно сохранённые рёбра: автоматические domain-проекции
удалены. Продуктовые линки сохранены, но без вызова движка не дают отношений в контексте.
В едином формате предметные операции явно согласуют свои группы связей в общей транзакции;
прежние базы переходят явной миграцией. Визуальный canvas карты и исторические снимки
требований не входят в покрытие.
Точные ограничения: [состояние реализации](../engineering/implementation/relations.md),
операции: [справочник графа](../reference/GRAPH.md).
